**状态：** Agent 设计与评审的统一规范入口；现行约束、待实施要求和可选扩展分别标注。本文不声明所有要求均已实现。<br>
**更新日期：** 2026-09-23<br>
**适用范围：** 员工 Agent、管理助手、发布试运行及自动任务中的 Agent 执行，不绑定具体业务场景。<br>
**实现核对：** [Agent 规范与当前实现差异清单](agent-design-gap-analysis.md)。

## 1. 定义与使用方式

dsh-work Agent 是一种可发布、可复用的受控智能执行定义：声明职责与指令、模型能力要求、能力依赖、上下文规则、输入输出契约和执行边界，由平台通过统一 Runtime 实例化，在任务与环境反馈下选择和执行获准动作。

Agent 定义与执行进程分离；声明不授予权限；使用业务状态不意味着自行实现存储、调度或身份系统。确定性计算、事务和数据服务可由受控程序执行，业务规则放在扩展或领域服务中。

**产品定位与待实施目标：** Agent 是有稳定身份、职责和人格的独立 AI 员工，不代表某一位员工。人格、记忆、能力、工作数据和主动触发按第 3 节统一设计，但分别治理；Skill、Tool、记忆和主动任务不因创建 Agent 而全部成为必填。现有以人类用户为中心的执行身份与配置入口尚不等于该目标身份模型。

本文中的要求分为：

| 标记 | 效力 |
| --- | --- |
| 现行约束 | 现有及新增功能必须遵守；实现缺口应登记并修复，不能因文档写有约束就视为已经满足 |
| 待实施要求 | 已明确设计方向，启用对应能力前须落实契约、代码和验证；本次文档整理不自动授权全部代码改造 |
| 可选扩展 | 有需求并通过设计评审后建设，不是所有 Agent 的发布前置条件 |

[架构总览](overview.md)维护系统边界；本文维护 Agent 的通用规则；[内部端口与契约](internal-ports.md)、源码类型、Schema 和迁移维护接口事实；阶段交付与验收按[差异清单](agent-design-gap-analysis.md)及各专项实施文档推进。目标字段不能直接当作当前 API 使用。

新建或重大调整 Agent 时，使用[通用 Agent 全生命周期模板](agent-lifecycle-template.md)形成工作定义、扩展决策、发布与验收记录，并通过[生命周期实现映射](agent-lifecycle-implementation-map.md)核对每个阶段的现行承载对象和门禁。[通用文本整理助手参考记录](reference-agent-lifecycle-record.md)只示范如何填写模板及验证严格包契约，不代表生产发布或 P2。模板不改变本规范的约束，也不把未实现的扩展变成已支持能力。

## 2. 对象语义与统一契约决策

| 对象 | 职责与生命周期 |
| --- | --- |
| Agent | 稳定目录身份、名称、负责人、默认发布版本和可用性；不保存本次执行进度 |
| Agent 定义版本 | 指令、能力引用、上下文与输入输出规则、限制申请、评测和内容摘要；封存内容不覆盖 |
| Binding／环境绑定修订 | 平台批准的连接、凭据引用、执行身份或身份解析策略、数据范围及环境；语义变化产生新修订 |
| Agent Version／平台发布版本 | 继续使用现有 `agentVersionId` 作为精确运行入口；目标上组合定义版本、精确依赖、批准绑定修订与发布证据 |
| Run | 一次任务的来源、发起人、输入与状态；可有多个按序 Attempt |
| Attempt | 一次执行尝试；固定运行清单、路由及来源快照，状态按状态机推进，历史清单不可覆盖 |

定义与绑定在逻辑上分离，不要求本轮增加独立 Binding 表或第二种 Release ID。本规范采用以下语义：相同定义可在不同环境绑定；绑定语义变化产生新平台发布版本，无需无意义地修改作者包版本；旧 Session、自动任务和 Attempt 不静默切换。

凭据轮换只有在身份、授权范围和数据过滤语义不变时才可保持原绑定语义，并须验证新凭据可用。历史快照记录当时依据，不能授予已经撤销的权限。

**2026-09-20 决策：不考虑历史兼容。** 后续 Agent 定义、包格式、绑定、运行与结果采用一套明确的新契约；不要求旧格式双读、字段别名兼容、历史配置转换、旧发布记录回填或旧结果展示分支。格式版本仍需明确，不支持的格式/字段直接拒绝。新格式切换时同步修改生产者与消费者，并验证新契约下完整链路。

此决策不取消新系统内部的不可变版本、依赖锁定、实时授权、运行追溯、回滚和审计；Runtime 能力匹配、路径安全和内容摘要检查仍必需。内联与外置 Skill 若分别有实际用途，可作为同一契约下的两种显式形式保留，不按历史格式维护两套逻辑。数据库结构变更仍需实施，但不要求历史数据回填；本轮只更新文档，不授权清空数据库或删除已有包、版本、执行和成果。

以下实施边界保持明确：

- 当前管理端负责 Agent/Tool 上传、配置和发布；员工使用批准能力及管理本人自动任务。员工自助贡献属于未来产品范围，本文不启用它。
- 包格式已按 B-01 统一为分层 `agent.yaml`（`apiVersion`/`kind`/`metadata`/`spec`）并经严格 JSON Schema 校验，配置与 ZIP 归一化为同一 `AgentSpec`（持久化于 `agent_versions.agent_spec`）。旧扁平清单、字段别名、未知字段与重复键一律拒绝；不做历史数据回填，已持久化的旧定义按其当时语义保留但不接受新的旧格式导入。
- 模型路由由平台管理，当前沿用默认路由；Agent 可声明 `model.requirements`，准备阶段须同时通过模型目录和实际 Runtime 的能力校验，不允许包携带 Provider 凭据或自建模型调用路径。当前 DSH 固定 Profile 尚不能保证 `long-context` 或 `structured-output`，声明这些要求的任务明确拒绝执行；空要求的文本 Agent 继续使用现有链路。
- 当前 Run 和 Manifest 依赖 Session；自动任务每次创建独立 Session。无 Session 的事件/API 执行是可选演进，必须先改契约及消费者，不能删除当前必填字段或伪造员工身份。

## 3. AI 员工统一目标架构

**状态：目标架构，AE-01 与 AE-02 已达到代码级，真实验收另记。** 本节是已确认的目标设计；除下文明确标注的已实现范围外，不表示现有 API、Schema、数据库、管理端或 Runtime 已支持。目标字段和示例路径不得直接当作当前契约使用。每项能力落地时按第 4 节相应 AS 条款、[生命周期模板](agent-lifecycle-template.md)和[差异清单](agent-design-gap-analysis.md)同步更新生产者、消费者与验收。

AI 员工是稳定的 Agent 身份，拥有经发布的职责与人格、获准能力、独立授权、可治理的长期经验、可管理的工作数据和主动任务规则。它可以被员工请求协作，也可以在批准范围内由时间或事件唤醒。一次唤醒创建 Task/Run/Attempt，不是启动常驻模型进程；模型执行仍唯一经过 Run/Attempt → Runtime Adapter → DSH。

```text
AI 员工 = 稳定身份 + 已发布 Soul + 可检索的受控 Memory
        + 已批准 Skill/Tool 与当前 MCP 能力 + 工作数据集 + 主动任务规则
一次工作 = 触发来源 + 发起人/执行主体 + 固定 Agent Version
        + 当前授权 + Task/Run/Attempt + 可核验结果
```

这些对象的权威存储与生命周期必须分开。独立身份不等于无人负责：管理负责人、发布审核人和停用责任人负责治理，不成为 Agent 的执行身份；发布、记忆审核、数据 Schema 发布和主动任务启用分别留痕。

| 对象 | 目标语义 | 当前差异 |
| --- | --- | --- |
| Agent 身份 | `agents` 保留稳定目录身份；增加独立的 `agent` Principal、状态和授权，负责人另记为治理关系 | AE-02 已将 human/agent/system Principal、独立角色/数据授权及 Task/Manifest/动作与审计归因接入统一执行链（代码级）；真实 DSH/OIDC 验收仍需单独留证 |
| Soul | Agent 定义版本根目录的唯一可信指令文件 `SOUL.md`；结构化标识、目标、边界和评测仍由 AgentSpec/发布记录管理 | AE-01 已把包 Schema、解析器及配置入口切换至根目录 `SOUL.md`（代码级）；独立身份与后续治理仍待实施 |
| Memory | Agent 稳定身份下的受控记忆条目和不可变版本，按来源、同意、作用域、保留期及当前 ACL 检索；`memory.md` 只是只读视图 | PF-05 当前仅接受员工从本人成功 Attempt 主动提交，按精确 Agent Version 使用；无 Agent 自主候选或跨版本连续继承 |
| Skill 与内置 Tool | Agent Version 固定所需的精确依赖，按当前状态和权限复核；没有需求时允许空集合 | AE-01 已使配置创建和 ZIP 均允许空集合（代码级）；业务能力仍须按需显式声明 |
| MCP Tool | 保留 Connector 整体发现、租户内全部 Agent 默认可见及每 Attempt 能力摘要复核；调用归因到 Agent Principal、Task 和 Attempt | 当前共享 Connector 凭据不能证明上游区分各 Agent 身份 |
| 工作数据 | 数据集定义、记录当前指针及不可变记录版本；写入绑定 Agent Principal、Workspace、Task/Run/Attempt、来源和 Schema 版本 | 当前 `task-result/v1` 只有文本、Artifact 与工具回执，无通用结构化业务记录或记录引用 |
| 主动任务 | Agent 拥有的版本化 routine，受触发条件、Workspace、身份、授权上限和预算约束 | 当前 `agent_automations` 由员工本人拥有，不能当作 AI 员工心跳 |

### 3.1 独立身份与授权

目标 Principal 类型统一为 `human`、`agent`、`system`。人类仍经 OIDC 登录；Agent Principal 由平台创建并绑定稳定 Agent ID，不借用真人会话、员工 OIDC Token、默认员工角色或管理负责人 Cookie。外部系统接受工作负载身份时可签发或交换短期凭据；只接受共享服务凭据时，平台仍记录真实 Agent 调用者，并明确上游无法区分各 Agent 的限制。

Task 分别记录 `initiated_by`、`executed_as`、`approved_by`（可空）和治理负责人引用。员工请求由 `human` 发起、`agent` 执行；定时/事件任务可由 `system` 发起、Agent 执行。高风险动作仍由有权的人类批准。当前人类外键、Run Manifest、审计及结果读取须作为一个契约变更同步处理，不能将 `agent_id` 偷写入 `user_id` 或静默混用两类身份。

Agent Principal 的角色与数据授权独立、可撤销，并满足 Workspace 当前准入。员工交互请求的输入与新结果披露还受发起人当前授权上限约束，防止借 Agent 越权读取；这不改变 Agent 的执行身份。主动任务只使用 Agent 当前授权与启用时批准上限的交集。停用、收权或授权服务不可用时拒绝新动作；历史快照不能恢复已撤销权限，活动读写与结果提交均须复核。已完成结果按当前人类账号和 Workspace 读取授权保留为不可变证据，Agent 事后停用不撤销历史结果读取。现行 MCP“对全部 Agent 默认开放”只表示可装载 Connector，不替代目标系统数据授权；需要上游独立身份时另设计可核验的工作负载凭据，不默认增加逐 Agent MCP Grant。

### 3.2 Soul、Memory 与目录

每个 Agent 定义版本的唯一人格与指令文件采用包根目录 `SOUL.md`，只写稳定职责、工作原则、沟通风格、禁止事项和转人工条件。名称、所属部门、发布版本、依赖、权限、预算、调度和凭据仍属于结构化契约或平台绑定。改变 Soul 要创建新定义版本并重新评测，不能运行时自动改写。AE-01 已使 `agent.yaml` 的 `spec.instructions` 唯一指向根目录 `SOUL.md`，配置创建与 ZIP 导入归一化为同一个 AgentSpec；原 `prompts/*.md` 路径在新包中拒绝。该代码级变更不代表独立 Agent Principal、Agent-owned Memory 或主动任务已实现。

目标记忆包含 Agent 自身经验、Workspace 共享经验和经个人明确同意的偏好。每条记录保留来源、提出者、批准人、范围、保留期、版本和撤回状态。Agent 只能在正常 DSH Run 后提出经验候选，不能自行修改文件发布长期指令；发布仍受相应审核策略约束。新 Attempt 按稳定 Agent 身份与当前授权选择记忆版本，将实际引用固定进 Manifest；跨 Agent Version 的继承须复核范围，不改写已完成 Attempt。私人记忆不得进入团队输出，Memory 不可覆盖 Soul、权限、工具策略或权威业务事实。对具体 Agent，记忆仍是按需使用的能力。

每个 Agent 可拥有按稳定 `agent_id` 命名的逻辑目录，方便导入、导出、审阅和定位版本；目录不是身份、授权、记忆和业务数据的唯一存储：

```text
agents/<agent-id>/
  versions/<agent-version-id>/
    agent.yaml
    SOUL.md
    evals/cases.yaml
    checksums.json
  exports/memory.md                 # 可选，只读的已批准记忆导出

attempts/<attempt-id>/
  memory.md                         # 本次身份、Workspace 和权限过滤后的临时视图
```

已发布 `agent_versions.agent_spec` 是运行权威，包文件用于导入、审阅和内容核对；摘要不一致则拒绝使用，不能分别更新。记忆权威是数据库条目、版本、来源和 ACL；`memory.md` 仅为管理员可读导出或本次 Attempt 的有界只读投影，不汇总所有私人、团队及组织记忆，也不存业务台账、文件原文或检查点。工作记录属于第 3.3 节数据集。生产存储经受控包/成果端口访问，不依赖单机绝对路径；Agent 公共目录不得存 Token、Cookie、模型凭据或员工私人记忆。

### 3.3 通用结构化工作数据

目标 Agent Data 能力采用先发布 Schema、再受控读写的模型，仅承载工作记录、分析结果、提案和跟进状态。外部 ERP 等仍保有权威主数据；通用 JSONB 记录不能接管外部系统事务。

| 对象 | 最小字段与约束 |
| --- | --- |
| `agent_data_collections` | `tenant_id`、稳定 key、负责 Agent、Workspace/可用范围、JSON Schema ID 与不可变版本、读写策略、保留期、可查询字段、状态 |
| `agent_data_records` | `tenant_id`、collection、Workspace、稳定 `record_key`、当前版本指针、状态、创建主体和时间；`(tenant, collection, workspace, record_key)` 唯一 |
| `agent_data_record_versions` | 不可变版本号、Schema 版本、校验后的 JSONB 内容及摘要、写入 Agent Principal、来源 Task/Run/Attempt、输入来源引用、审核/工具回执、创建时间 |

管理员发布数据集 Schema 与授权；Agent Version 只声明需要的数据集与动作，不通过 Prompt 动态建表。Agent 经平台受控工具 `data.query`、`data.propose`、`data.update`、`data.transition` 操作；写入检查 Schema、大小、当前身份、Workspace、业务键及期望版本，并以 Task 操作键去重。查询仅开放获准的过滤、排序、分页字段，不给模型任意 SQL；常用字段建索引，大文件放 Artifact 并仅保留受权引用。

模型生成的 JSON 首先是提案；Schema 合法不等于业务事实正确。确认为工作记录或触发外部写动作须满足数据集审核与回执策略。成功写入返回可核验 `recordVersionId`，供未来结果契约增加结构化交付引用；Run `succeeded` 不单独证明外部效果完成。复杂查询、强事务或已有权威系统对象由领域服务承接，仍使用相同 Agent Tool 与结果引用契约。

### 3.4 Agent 主动任务与心跳

Agent-owned routine 是经批准的工作规则，不是无限模型循环。规则固定 Agent Version 或明确升级策略、时间/事件触发、时区、Workspace、输入模板、身份与授权上限、预算、重叠策略及结果接收范围。调度器先做确定性资格和去重检查，需要工作时创建 Task，随后走现有 Run/Attempt → DSH。每次触发留下关联键、执行记录、跳过原因、结果和告警；Agent 停用立即阻止新触发。

“巡检心跳”只是可选 routine 预设；由管理员批准启用，不随 Agent 创建自动运行。现有个人自动任务继续保持个人语义；目标复用其调度、预算与 Run 基础设施，但增加 Agent Principal 拥有的规则，不把 `owner_user_id` 偷换为 Agent ID。通知员工或团队须有明确接收人和信息披露策略。

### 3.5 管理端与目标验收

管理端按“身份与 Soul → 能力 → 数据集 → 记忆策略 → 主动任务 → 评测与发布 → 运行和审计”呈现 AI 员工。基础 Agent 仅要求身份、目标、Soul、负责人及最小授权；Skill、工具、记忆和主动任务按需启用。数据写入和主动任务各自经过治理，不因 Soul 发布自动授权。

实施依赖顺序为：独立 Principal 与 Task/审计身份契约 → Agent Data Schema 与受控工具 → Agent-owned Memory 和 routine → 管理端、评测及 P1/P2 验收。每项须同步现有消费者和数据库约束；文档、Prototype 或合成 Runtime 测试均不能宣称目标能力上线。

至少验证：Agent 身份与负责人不混淆；员工不能借 Agent 越权读取；停用或收权阻止主动任务；Soul 升级不改写已固定 Attempt；记忆撤回阻止新使用；无 Skill/Tool Agent 可发布；结构化记录经 Schema、并发和幂等校验并追溯真实 Attempt；未知外部回执不标记完成；共享 MCP 凭据不被误称为上游独立 Agent 身份。

## 4. 十二条设计规范

### AS-01 身份、版本、绑定与执行分离

**现行约束：** 按第 2 节区分生命周期；编辑草稿不改变已发布能力，运行始终引用精确版本；业务事实不能塞进 Agent 目录记录。发布状态变化不覆盖历史内容。

**待实施要求：** 将实际绑定修订及其内容摘要纳入可追溯发布引用；展示名称或固定字符串不能证明绑定已封存。

**验收：** 修改草稿后旧会话仍使用原版本；定义不变而绑定变化时，能查到新旧绑定及分别使用它们的执行。

### AS-02 精简 AgentSpec，以引用组合扩展

**现行约束：** 定义围绕职责与指令、能力引用、上下文、输入输出、执行限制和质量要求组织；平台可提供明确默认值。包可附带 Skill、脚本、模板和工具候选，导入不执行安装钩子、不自动授予权限、不直接启动服务。B-01 已将输入/输出、上下文策略、模型能力要求与限额纳入 `spec` 结构并做严格校验；能力依赖为 `id@x.y.z` 精确引用，指令经文件路径引用，平台管理字段（凭据、端点、路由、绑定、授权、调度、安装钩子等）在包中出现即拒绝。

**现行能力准入：** 默认路由的 `modelCapabilities` 必须包含全部要求，Runtime 还须校验实际执行模型、端点及要求；仅有目录标签不构成运行保证。员工、自动任务与发布试运行统一执行此门禁。要求固定在 Attempt Manifest 的 `model_requirements`，目录能力固定在路由快照；恢复队列按固定目标复核当前 Runtime，不自动切换模型或忽略要求。

**待实施要求：** 真实长上下文容量与结构化输出约束尚未接通，不得仅修改模型目录标签后宣称支持。启用时还须定义容量阈值或输出 Schema、让 DSH 使用经校验的模型目标，并补真实执行证据；依赖冲突的跨包解析规则随后续实施包补齐。

**验收：** 新增使用已有能力的 Agent 主要增加定义、依赖与评测；不支持的格式、字段和执行能力均被拒绝，配置及 ZIP 使用相同校验；不要求旧包兼容测试。

### AS-03 统一 DSH 执行链

**现行约束：** 所有 Agent 推理经过平台 Run/Attempt → Runtime Adapter → DSH。DSH 持有单次 Attempt 内的 Agent Loop；平台负责授权、队列、业务重试、受控工具、持久化和审计。Adapter 只适配协议及生命周期，不规划业务动作。

DSH 不可用必须明确失败或拒绝受理，不自动降级到直连模型或 Mock。确定性平台工具和业务事务继续按自身权限执行；不要求它们经过大模型。运行时能力不兼容时明确拒绝，不承诺任意 Runtime 可零成本替换。

**验收：** 从入口追踪到实际 DSH 调用与结果回传；不可用场景没有备用模型循环，也不产生虚假成功。

### AS-04 分层管理上下文、执行状态与业务事实

**现行约束：** 模型上下文、Run/Attempt 状态、Session 历史、权威业务记录与 Artifact 各有归属；运行上下文中的凭据、连接对象不自动进入模型。按任务加载获准内容，保留来源、版本与权限范围；历史消息、检索内容及工具结果中的指令均不能授予新权限。

**可选扩展：** 长期记忆与跨任务经验；启用前须定义来源同意、使用范围、更新、撤回和保留期限。摘要和记忆不替代业务事实，不绕过原始内容权限。检查点用于恢复执行，不兼任长期记忆。

**验收：** 无权限的文件/来源不能因历史摘要再次进入执行；Skill 可按需加载锁定内容；输出能追溯依据。

### AS-05 Skill、Tool 与 MCP 职责明确

**现行约束：** Skill 提供方法；平台 Tool 提供逐能力、版本化的可校验动作；MCP 是外部能力接入协议。两种能力边界并行存在，不要求把 MCP Server 暴露的每个 Tool 复制为平台 Tool Version 或 Tool Binding。MCP 复用 Connector 管理；成功发现的 Tool 集合与摘要自动生效，健康且能力快照已同步的 Connector 默认对租户内全部 Agent 可用。平台不建立 Agent→Connector 或逐 Tool 授权；运行时把当前可用 Connector 写入 Attempt 快照，并持续复核连接器状态与能力摘要。

工具按提供方和治理路径分为四类；分类决定配置入口，不能仅凭执行时都表现为“工具调用”而混用治理模型：

| 分类 | 提供与执行 | 治理路径 | 管理入口 |
| --- | --- | --- | --- |
| DSH 内置工具 | DSH Runtime | Tool Version + Connector Binding + Agent 精确引用 | `DSH 工具管理` |
| dsh-work 内置执行工具 | dsh-work Platform Tool Bridge，DSH 在 Attempt 内调用 | Agent/Skill Manifest 精确声明；不进入普通 Tool Binding | Agent/Skill 定义与运行证据 |
| dsh-work 内置平台工具 | dsh-work Platform Tool Bridge，DSH 在管理 Attempt 内调用 | 由平台按 Run purpose 注入并强制校验；不提供 Agent 自由选配 | 对应平台流程与审计 |
| MCP 外部工具 | 外部 MCP Server，DSH MCP Client 调用 | Connector 整体发现、自动生效快照、全部 Agent 默认可用及状态/摘要持续复核；不复制为平台 Tool Version/Binding | `MCP 连接器` |

`activate_skill`、`python_execute` 属于 dsh-work 内置执行工具；`inspect_admin_state`、`propose_admin_task`、`prepare_admin_action`、`prepare_skill_installation` 属于 dsh-work 内置平台工具。普通工具列表只返回 `connector-dsh-workspace` 下的 DSH 内置工具；不得把平台桥工具、MCP 发现项或旧的自定义候选原型混入该列表。

`connector-dsh-workspace` 是平台创建的 DSH Runtime 基础设施，不是管理员登记的外部连接。其健康、工具目录摘要和 Binding 状态只进入 `安全与运维 → Runtimes`；`MCP 连接器` 页面与列表接口只返回外部 MCP Connector。页面入口分离不改变底层 Connector、Tool Version、Binding 和审计模型。

**现行 MCP 范围：** 首期只支持管理员登记的 Streamable HTTP MCP Server 和 Tools。管理员填写名称、端点、认证方式、整体权限范围及可选 Bearer Token；Connector 标识和 `serverName` 由平台生成，“所属系统”不属于 MCP 登记契约。新增前必须先通过 DSH 执行不落库的连通测试并发现至少一个 Tool；名称、端点、认证方式或 Token 变化使页面测试结果失效，登记接口仍须独立重新测试，不能信任客户端的“已测试”状态。DSH/ACP 若将上游 HTTP 401/403 折叠为 `Internal error`，平台只发起无副作用的 `ping` 恢复认证失败分类；无认证时提示改用 Bearer Token，Bearer 认证时提示 Token 无效、过期或无权，不读取远端错误正文、不回显 Token。测试或登记复核失败时不得写入 Connector 或凭据。Bearer Token 以 AES-256-GCM 密文存入 PostgreSQL，主密钥由服务环境中的 `DSH_CREDENTIAL_MASTER_KEY` 提供，开发与生产使用同一实现但使用不同密钥；明文不进入查询响应、Manifest、前端持久状态、Patch 或日志。旧版环境变量引用升级后保留 Connector 和能力快照，但 Connector 降级并阻止执行，管理员须通过同一轮换入口重新录入 Token 才能恢复；旧版共享引用在重新录入时为目标 Connector 拆分独立加密凭据，不能静默改变其他 Connector。每次发现固定凭据 ID、存储后端和密文版本；写回时先取得 Connector 行锁，再以独立语句读取锁后的最新凭据版本。检查完成前发生轮换时丢弃旧结果，不能用旧 Token 的成功结果恢复健康状态。管理员成功发现完整 Tool 清单后，平台立即把名称、描述、输入 Schema 及摘要保存为当前生效快照；清单变化在成功检查后自动替换生效快照，无需人工整体审核。健康且能力快照已同步的 Connector 默认对租户内全部 Agent 开放；停用、离线、凭据异常、能力摘要变化或删除都会阻止后续解析和在途复核。删除 Connector 时停用关联平台 Tool/Binding，并销毁仅由该 Connector 使用的加密凭据；Connector、能力快照、健康检查和调用审计保留为不可执行的治理证据，活动列表与 Runtime 解析不再返回该 Connector。DSH 通过每 Attempt 受控 Patch 装载当前可用 Connector，策略按 `mcp__<serverName>__*` 命名空间放行。平台按实际 MCP Tool 调用记录名称、参数摘要、Run/Attempt 和结果审计。MCP Resources、Prompts、stdio 和包内任意服务进程当前不支持，不能因 Tools 已接通推定可用。

租户最多同时启用 20 个 MCP Connector，与单个 Attempt 的 Runtime Manifest 上限一致。登记、重新启用和检查恢复健康必须在同一租户级事务锁下检查容量；第 21 个请求返回冲突并保持原 Connector 状态，不能把超限错误延迟到 Agent 新 Attempt。

**验收：** 新登记或新发现的能力在成功检查后自动生效并对全部 Agent 可用；已准备 Attempt 继续固定原摘要并在摘要变化、停用或删除后拒绝执行，新 Attempt 使用最新生效摘要；调用仍经过统一 DSH 链路并产生实际 Tool 级审计；不能把 ACP、本地平台工具桥接或数据库记录的存在当作真实 MCP 已接通。

### AS-06 工具具有效果与失败语义

**现行约束：** 纳入 DSH 工具管理的每个不可变 Tool Version 须声明输入/输出 Schema、输出是否由 Runtime 或平台实际校验、只读/写入性质、执行身份与资源范围、审批、超时、重试、并发及完成语义。dsh-work 内置执行/平台工具使用同等严格的代码契约目录，但不因此创建普通 Tool Version 或 Binding；MCP 外部工具遵循 Connector 生效能力快照与状态门禁。实现负责参数及业务约束，不能只靠 Skill 或 Prompt。平台桥接工具在调用前后复核当前授权，严格校验输入和输出并限制输出字节；`serialized` 工具拒绝同名重叠调用。DSH 原生工具尚无穿过平台验证边界的结构化输出，因此目录必须显式标为 `outputValidation=unavailable`，不能用空 Schema 宣称已校验。

**现行失败语义：** 参数无效、输出无效、无权限、调用上限、冲突、暂时不可用、取消、超时、结果未知和普通执行失败使用稳定错误码。错误携带 `retryable` 与 `effect_state`；写入工具超时返回结果未知且不可自动重试，只读工具仅在契约声明安全时标记可重试。该标记是调用方判断依据，不会触发平台自动重试。

**待实施要求：** 新增外部写动作前必须提供业务幂等键或明确不可重试策略；异步动作声明 `accepted` 并提供可查询的操作标识、状态与回执。写入超时先核对效果，不能盲目重发。DSH 原生工具只有在真实输出穿过可执行校验边界后，才可把输出验证从 `unavailable` 提升为 `runtime` 或 `platform`。

**验收：** 重复请求不重复产生业务效果；冲突和未知结果可被识别；Run 幂等、工具调用 ID 或检查点本身不能作为外部动作恰好一次的证明。

### AS-07 执行边界强制实施当前授权

**现行约束：** 动作必须同时满足能力声明、平台批准、执行身份、目标资源及当前安全策略。准入、领取/恢复、实际能力调用与结果访问均检查各自授权；不可变 Manifest 不能覆盖当前收权。隐藏工具只是减少误用，不能代替调用端检查。发起人、执行身份、批准人分别记录，不允许后台冒充员工批准。

**现行持久化审批：** PF-04 将批准绑定工具、规范化参数摘要、资源、执行身份、有效期和数据版本；兼容 DSH 仅携带调用 ID 的请求时，参数必须来自平台策略生成的可信日志并通过摘要校验。参数变化重新申请，恢复前重新鉴权。审批只有在来源 Attempt、Run 与审批记录原子进入等待后才对管理员可见；`approval.required` 只有携带持久化 `approval_id` 与 `checkpoint_id` 且 Run 已进入 `waiting`，才表示可跨进程等待；普通瞬时事件不具备该语义。并发决定只允许相同决定和相同幂等键重放；相反决定或不同幂等键返回冲突，不能把其他请求的结果伪装成本次操作成功。

**验收：** 个人及团队空间撤权、输入来源撤回、身份停用和过期批准均阻止后续越权动作；授权基础设施故障拒绝继续，区别于已确认收权。

### AS-08 等待与恢复有持久化语义

**现行约束：** 重试创建新 Attempt，旧 Attempt 不能覆盖当前状态；取消阻止后续执行，不承诺撤销已发生的外部效果。重启按持久化事实收敛，不能无依据重放副作用。

保留 [AG-03 轻量语义](../design/automation-implementation-plan.md)：单进程、不补跑、不自动重试、不续办中断准备；queued Attempt 复用现有恢复，丢失 Worker 的活动 Attempt 失败。用户再次运行自动任务创建新触发和新 Session/Run。

**现行可选能力：** 同 Run 持久化等待/恢复使用受控检查点和新 Attempt；等待释放 Worker。检查点只在确实需要持久化人工等待时捕获，无需审批的调用直接按策略处理，不受检查点容量限制。检查点固定精确待执行参数及摘要，并有界保存此前工具结果、输出工作文件和未提交部分回答；安全工作文件路径支持 Unicode 名称，拒绝目录遍历和非可移植分隔符。恢复时校验检查点、批准有效期与当前权限，恢复工作文件后只允许消费一次完全相符的动作，旧 Attempt 为不可回退终态；来源 Attempt 在进入等待前终止时立即取消其准备中审批和活动检查点，过期处理也必须核对 Run 的当前 Attempt，不能终止后续重试。员工端按同一 Run 的事件顺序串行处理恢复事件，只为首个未知 Attempt 合并一次权威刷新。该能力已由平台提供，但具体 Agent 仍须满足生命周期模板触发条件。独立后续事件也可创建关联的新 Run；Outbox 仍是按事件来源选择的实现方法，接收端必须去重。

**验收：** 按中断发生点区分未受理、准备中、排队、活动和终态；能说明已发生的动作与恢复后的动作，不把 SSE 重放等同于执行恢复。

**现行受控记忆：** PF-05 将记忆限定为员工从本人成功 Attempt 主动填写的稳定偏好或可复用经验，并要求明确范围与保留期；平台不自动把回答、Session 历史、业务记录、知识文档或检查点转成记忆。候选经管理员审核后发布为独立不可变版本，同一逻辑记忆的修订创建新版本并更新当前指针。提交幂等固定来源 Attempt、类型、规范化内容、范围和保留期，任一参数变化均返回冲突；相同用户与幂等键的并发提交在事务内串行化。新 Attempt 只检索同时满足当前来源同意、来源用户仍可访问原工作空间、保留期、用户/空间/角色 ACL 和精确 Agent Version 的当前版本；角色 ACL 使用当前角色与 Attempt 快照角色的交集，“仅本人”范围只可进入本人的个人空间，不能进入团队共享回答。实际版本、摘要与摘录固定进 Manifest 和 Attempt 来源记录，领取、执行及持久化恢复再次复核；撤回、来源撤权或其他权限变化立即阻止未来使用，审核幂等重放及管理查询也不得重新暴露失效正文，已完成运行仍保留当时实际引用的审计。DSH Prompt 明确把记忆标为非权威参考，不能覆盖系统指令、权限、工具结果或权威业务事实。

**验收：** 未经明确同意或审核的内容不可检索；跨用户、空间、角色和 Agent Version 查询返回空；撤回阻止新运行和等待恢复；版本升级不改写已固定 Attempt；回答引用可追溯到实际记忆版本。

### AS-09 自主执行受可执行预算约束

**现行约束：** 程序约束单 Attempt 的执行时长、工具调用与输出上限，并以 Task 预算账户对时长、工具次数和输出字节进行原子预占、终态结算与重试累计；并发 Attempt 共用同一预算范围时串行检查，取消与恢复只结算一次。超过可预占额度时拒绝创建 Attempt。产品只声明能强制执行的限制；输出字节截断不等于模型 Token 或成本硬预算。Token 只接受 Runtime 明确上报，否则标为 unavailable；当前不提供 Token 或成本硬限制。

**待实施要求：** 如承诺 Token、成本、磁盘或无进展硬限制，须先接通可靠计量、执行中拦截及验证；不能仅靠估算、配置字段或用量记录。

**现行可选能力：** PF-06 提供工具式 Agent 委派，不提供控制权移交或通用编排框架。Agent Version 只声明精确的已发布目标版本及深度、并行、超时；平台按父 Attempt 和请求摘要幂等创建无 Session 子 Task/Run，子 Task 使用根 Task 预算范围。子任务使用当前用户和工作空间，权限取目标当前授权与父 Attempt 角色/数据范围上限的交集，团队空间还复核 Agent 成员关系；父任务终止传播取消，重启时对账遗留关系，委派来源 Task 禁止脱离父关系使用通用重试。同步委派受理与 Runtime 领取共用容量锁和子任务席位预留，满载时直接拒绝委派。子 Agent 仍走统一 Run/Attempt → Runtime Adapter → DSH 链路。子结果遵循 `task-result/v1`；只有全部必要回执均为 `completed` 且至少存在一项可核验交付时才能标为 `achieved`，存在 `accepted/unknown` 时保持 `unverified`，存在失败回执时为 `not_achieved`。

**验收：** 限额不能因重试或委派绕过；目标版本、深度、并行、Runtime 容量、父任务活性、当前权限、取消与恢复均须 fail-closed；自动任务满载时交互任务仍可获准执行。具体 Agent 未满足生命周期模板触发条件时不得配置委派目标。

### AS-10 输出表达真实结果

**现行约束：** 区分执行结束、目标达成、批准完成和外部动作完成。成果必须经过登记及访问授权，不能只返回未发布路径。错误与未解决事项应可见，读取失败不触发重新执行。

**待实施要求：** 建立统一结果外层语义，包含执行状态、目标完成情况、主要结果、证据来源、动作回执、待输入/批准事项、失败、成果引用及后续建议。字段名、状态枚举与 API/消费者同步切换另行设计；本文不新增虚拟 API。

**可选扩展：** 结构化表格、表单与卡片由平台安全渲染，动作仍走服务端授权；任意生成 JavaScript 不能成为可信平台代码。Agent 能力与固定页面解耦。

**验收：** 模型自报完成但缺少必要回执/成果时，不能显示目标已达成；平台执行状态与业务结果可分别查询。

### AS-11 发布不可变且可追溯的能力

**现行约束：** 固定指令、精确 Skill/Tool 依赖和内容证据，每次 Attempt 保存实际运行清单及模型路由。静态检查、隔离试运行、业务确认和发布是不同事实；修改候选后旧证据不能自动放行。权限实时可撤销，版本回滚不自动撤销外部效果。

**待实施要求：** 补齐完整绑定、上下文/模型策略和 Runtime 兼容要求的发布关联及变更影响检查。可追溯保证解释“当时使用什么”，不保证模型或外部数据完全可重复。运行中生成的改进只进入候选，不能覆盖生产版本或扩大权限。

**验收：** 发布能追溯实际定义、依赖与证据；换绑定、依赖或关键策略后有对应验证；回滚保留既有执行与成果历史。

### AS-12 评测与可观测性随 Agent 交付

**现行约束：** 发布包含明确任务案例与预期，检查真实输出，关联版本、Run/Attempt、工具、授权和成果证据。Agent 包中的 `evals/cases.yaml` 使用 [AgentEvaluationSuite v1 模板](agent-evaluation-template.yaml)：至少覆盖目标质量、无效输入、越权、提示注入和能力特有失败；Run/Attempt 记录、执行终态及非空输出由平台按案例声明自动断言，开放质量由审核人依据 rubric 判定。确定性约束优先由代码验证，人工结论不能覆盖失败的机器断言。记录脱敏动作、结果、错误、时延和消耗，不保存或展示隐藏思维链。

**待实施要求：** 将任务质量、安全与注入边界、可靠性、成本效率覆盖落实为分层评测；不要求每个包复制整个平台故障套件，但新增能力必须有对应测试。通用默认案例不能代替业务专属验收，也不能把固定工具路径当作唯一正确答案。

**验收：** 测试报告标明代码版本、数据/身份/Runtime、验证层级及结果；P0 原型、P1 隔离集成、P2 真实验收不互相替代；生产不得用测试替身作成功回退。

## 5. 评审与分阶段应用

| 门槛 | 必须检查 | 不随本规范自动增加的范围 |
| --- | --- | --- |
| 基础 Agent 发布 | 定义和精确依赖、DSH 接线、当前授权、输入输出、实际限制、发布证据与审计 | 新契约统一切换，不建设旧格式兼容层，也不因此拆服务或启用员工配置 |
| 新外部能力或写动作 | 契约、批准绑定、凭据范围、效果回执、幂等、冲突与未知结果处理 | 不因包声明就安装 MCP、执行器或连接器 |
| 持续执行扩展 | 等待与恢复协议、去重、旧执行隔离、取消、权限再检查及容量 | 不改变 AG-03 已确认的轻量语义 |
| 记忆、委派与交互扩展 | 需求价值、权限传播、版本及成本、独立验收 | 不要求所有 Agent 实现复杂应用组件 |

通用推进顺序固定为：工作定义 → 能力分解 → 扩展判定 → AgentSpec → 能力准入与环境绑定 → 五类评测 → 候选检查与 DSH 试运行 → 审核发布 → 结果核验 → 变更或退役。完整交付物、门槛和变更失效规则见[生命周期模板](agent-lifecycle-template.md)。具体业务场景只能填写模板，不改变平台主流程。

既有基础链路按五个实施包完成：统一定义与严格包格式、统一运行契约与预算、真实绑定与发布追溯、工具及任务结果契约、分层评测与验收。继续开发具体 Agent 前，平台按差异清单的 PF-01～PF-07 建设任务/外部操作、累计预算、MCP、持久化等待与审批、受控记忆、委派及统一真实验收。平台支持这些能力后，具体 Agent 仍按本规范的触发条件和最小权限原则逐项启用。

新增或修改 Agent 能力时，以 AS 编号说明适用条款、证据和缺口。当前差异、具体实施工作项及建议顺序统一在[差异清单](agent-design-gap-analysis.md)维护；自动任务与 Runtime 执行细节分别引用已有实施文档，不要求另建 Agent 总方案。
