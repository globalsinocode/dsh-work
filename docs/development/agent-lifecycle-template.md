# 通用 Agent 全生命周期模板

**状态：** 新建或重大调整 Agent 时使用的通用工作模板。  
**适用范围：** 所有业务 Agent、管理助手、发布试运行与自动任务；不绑定具体业务场景。  
**规范依据：** [Agent 设计规范](agent-design-standard.md)。实现能力与缺口以[差异清单](agent-design-gap-analysis.md)为准。

## 1. 使用原则

每个 Agent 都沿同一条主流程设计、发布和运行。场景差异通过版本化定义、Skill、Tool、绑定、评测案例和业务服务表达，不在平台中复制 Agent Loop。

MCP、持久化等待、受控记忆、Agent 委派和无 Session 入口是 Agent 的扩展轨道。平台按差异清单统一建设这些通用能力；具体 Agent 只有满足本模板的触发条件并完成独立设计与验收后才启用。未选择时明确记录“不启用”及理由，不能因为平台已经支持就自动授予能力、权限或预算。

本模板中的“完成”必须有可核验结果。模型回复“已完成”、试运行状态为 succeeded 或人工批准本身，都不能替代必要的工具回执、业务结果或 Artifact 证据。

## 2. Agent 设计记录

创建 Agent 前复制下表，作为需求、评审和发布记录的首页。

| 字段 | 必填内容 |
| --- | --- |
| Agent 标识与名称 | 稳定 id、展示名称 |
| 负责人 | 业务负责人、技术负责人、发布审核人 |
| 业务目标 | Agent 承担的工作及可观察结果 |
| 范围外事项 | 明确不承担、不允许执行或必须转人工的事项 |
| 用户与入口 | 使用角色；员工对话、管理入口、自动任务或其他已批准入口 |
| 输入 | 输入类型、来源、必填信息、敏感级别和无效输入处理 |
| 输出与完成判据 | 文本、结构化数据、工具效果、Artifact；各自的核验依据 |
| 权威业务事实 | 数据归属系统、读写边界、业务台账或领域服务 |
| 能力依赖 | 精确 Skill/Tool 引用、模型能力要求及 Runtime 要求 |
| 上下文 | recent/history、文件、知识来源、加载范围与来源追溯 |
| 执行限制 | 时长、工具次数、输出字节及停止/转人工条件 |
| 环境与绑定 | 目标环境、执行身份、凭据引用、数据范围、绑定修订 |
| 评测 | `AgentEvaluationSuite v1` 文件、业务 rubric 和平台通用回归引用 |
| 扩展决策 | MCP、持久化等待、记忆、委派、无 Session 入口逐项选择与理由 |
| 发布与验收 | 候选版本、P0/P1/P2 层级、证据位置、已知限制 |

目标、输入、输出或完成判据仍无法写清时，不进入能力设计。缺少外部系统接口、执行身份或数据授权时，可以完成定义草稿，但不能伪造绑定或发布证据。

## 3. 通用主流程

| 阶段 | 必须完成的工作 | 交付物 | 进入下一阶段的门槛 |
| --- | --- | --- | --- |
| 1. 工作定义 | 明确目标、用户、输入、结果、范围外事项和人工边界 | Agent 设计记录 | 完成判据可由程序证据或明确人工 rubric 判断 |
| 2. 能力分解 | 区分模型判断、确定性规则、Skill 方法、Tool 动作、业务服务和权威数据 | 能力与数据清单 | 每项动作有执行者、输入输出和权限边界 |
| 3. 扩展判定 | 按第 4 节逐项判断 MCP、等待、记忆、委派和无 Session 入口 | 扩展决策记录 | 所选扩展具备触发事实；未选扩展有替代方案 |
| 4. AgentSpec 定义 | 编写职责、指令、精确依赖、输入输出、上下文、限制、模型要求和评测引用 | 唯一格式 Agent 包或配置生成的规范化 `AgentSpec` | 严格 Schema、字段、路径、摘要和依赖检查通过 |
| 5. 能力准入与绑定 | 审核 Tool/Skill；在目标环境绑定执行身份、凭据引用、数据范围和实际修订 | 已批准能力版本及 Binding 修订 | 不依赖包内凭据或端点；当前授权与 Runtime 能力可验证 |
| 6. 评测设计 | 定义正常目标、无效输入、越权、提示注入和能力特有失败；补业务 rubric | `AgentEvaluationSuite v1` | 五类齐全；机器断言与人工判断边界清楚 |
| 7. 候选检查与试运行 | 固定候选修订和绑定，通过 Run/Attempt → Runtime Adapter → DSH 执行案例 | 试运行记录及 Run/Attempt 证据 | 全部机器断言通过，人工 rubric 逐项确认，修订未漂移 |
| 8. 审核与发布 | 复核定义、依赖、绑定、权限、限制、评测和变更影响 | 不可变 Agent Version 与发布证据 | 审核职责分离；旧证据不能放行新修订或新绑定 |
| 9. 运行与结果 | 从批准入口创建 Run/Attempt；执行时持续复核权限并投影真实结果 | `task-result/v1`、回执、来源和 Artifact | 业务结果与执行终态分开；缺证据时为 unverified 或未达成 |
| 10. 监控与演进 | 观察错误、取消、限额、质量、消耗和收权；变更创建新候选并重做受影响证据 | 审计、评测趋势、变更记录 | 定义/依赖/绑定/Runtime 变化按影响使证据失效 |
| 11. 停用与退役 | 阻止新执行，保留有权读取的历史证据，处理自动任务和连接撤销 | 停用记录及后续处理清单 | 不删除审计与不可变历史，不恢复已撤销权限 |

主流程固定，业务处理步骤不要求全部由模型规划。确定性计算和事务应由程序完成；模型用于理解、判断、解释和选择获准动作。

## 4. 扩展轨道判定

### 4.1 MCP 外部能力

仅在至少存在一项事实时选择：

- 目标外部系统已经提供必须使用的 MCP Server；
- 需要以 MCP 标准发现、固定和调用多个远端 Tool；
- 需要受控使用 MCP Tool，普通平台 Tool/固定 API 适配器无法表达；
- 同一能力必须在多个环境绑定不同 MCP 服务，同时复用 Agent 定义。

“需要查询外部系统”本身不是 MCP 触发条件。已有受控 Tool 或固定 API 适配器能够满足时继续使用现有路径。

选择 MCP 后必须补：服务身份、Streamable HTTP 传输与网络范围、凭据引用、完整 Tool 清单及自动生效摘要、默认对全部 Agent 开放的风险确认、命名空间冲突处理、超时取消、实际 Tool 调用审计、漂移同步以及错误服务/凭据、停用和删除测试。首期不提供 Agent 或逐 Tool 权限，也不生成平台 Tool Version/Binding；Agent 发布不携带或改变 Connector 配置。MCP Resources、Prompts、stdio 和包内任意服务进程当前不支持。

### 4.2 持久化等待与长流程

仅在同时满足以下条件时选择：

1. 同一个业务实例必须等待人工决定、外部回调或未来事件后继续；
2. 等待可能跨进程、跨部署或超出单次 Attempt 的可执行时长；
3. 不能合理建模为“保存业务事实后，由新事件或自动任务创建一个关联的新 Run”。

每天重新分析、周期性扫描、独立自动任务和业务台账中的跨天状态，不自动构成长流程需求。

选择后必须补：持久化状态机、等待事件关联键、检查点边界、跨 Attempt 的业务动作标识、恢复前重新鉴权、旧执行隔离、取消、超时、重复事件去重、已发生副作用核对及容量策略。不得通过重放聊天或模型输出恢复副作用。

### 4.3 受控记忆与经验

仅在需要跨 Session、跨 Run 复用经过治理的偏好或经验，且这些内容不属于权威业务数据时选择。典型对象包括经审核的方法改进、用户明确授权的稳定偏好和带来源的组织经验候选。

业务主数据、订单、库存、工单、状态台账、文档原文、Session 历史和运行检查点都不是 Agent 记忆，应继续留在各自权威存储中。

选择后必须补：来源和同意、候选生成、人工审核、独立版本、作用域与 ACL、检索引用、冲突处理、保留期限、撤回/删除传播、质量评测和审计。记忆不能覆盖 Agent 指令、授予权限或成为业务事实的唯一来源。

平台现行基线要求候选绑定本人成功 Attempt，员工主动填写内容并明确选择范围和保留期；如后续由 Agent 辅助提炼候选，提炼本身也必须通过既有 Run/Attempt → DSH 链路，且不能代替用户最终提交和同意。管理员审核发布独立不可变版本；每次 Attempt 只使用当前 ACL 和精确 Agent Version 允许的当前版本，并固定实际引用。具体 Agent 选择该扩展时仍需说明要记住什么、为什么不能从权威数据实时读取、默认不启用时的替代流程及专属质量评测。

### 4.4 其他扩展

| 扩展 | 触发条件 | 必须补充 |
| --- | --- | --- |
| Agent 委派 | 一个 Agent 必须把边界明确的子任务交给另一个独立发布 Agent，普通 Tool 调用不能表达 | 父子版本、最小上下文、权限不扩大、总预算、取消传播、结果合并 |
| 无 Session 入口 | 任务来源没有对话语义且现有自动任务创建 Session 的方式不能满足接口或生命周期 | 新触发来源、身份、关联键、结果读取授权及全部消费者契约 |
| 结构化交互 | 用户必须通过表格、表单或卡片核对数据、批准动作或补充字段 | 安全渲染 Schema、服务端动作授权、版本与可访问性；禁止任意生成脚本 |

## 5. 通用评测与验收记录

每个 Agent 的平台通用回归与目标质量评测分开记录。平台通用套件证明权限、故障、取消、预算和运行契约；Agent 套件证明该 Agent 的目标质量和能力特有失败。不得为每个 Agent 复制整套平台测试，也不得用平台绿灯替代业务质量。

### 5.1 案例记录

| 字段 | 内容 |
| --- | --- |
| 案例 id / 类型 | success、invalid_input、permission_denied、prompt_injection 或 capability_failure |
| 输入摘要 | 脱敏后的实际输入及数据前置条件 |
| 预期与 rubric | 可观察结果、禁止行为和人工判断标准 |
| Agent/绑定版本 | Agent Version、定义摘要、Binding 修订 |
| Runtime | DSH Lock、Adapter、模型与能力标签 |
| 身份与环境 | 环境、用户角色、团队/资源范围、批准工具 |
| 执行证据 | Run ID、Attempt ID、工具回执、结果状态、Artifact |
| 判定 | 机器断言、审核人、时间、人工结论及说明 |

### 5.2 P2 真实验收包

P2 至少记录：代码或部署版本、目标环境、验收时间、真实身份、DSH/Adapter/模型、批准工具与绑定、五类案例结果、结果/成果证据、撤权或故障场景、已知限制、验收人和最终结论。敏感输入、Token 和凭据不得进入文档。

手工执行可以构成 P2，但必须留下上述可审计记录。仅有“已手工完成”的结论时，状态写为“已执行，证据待归档”，不能写成仓库内已核验通过。

## 6. 变更影响规则

| 变化 | 默认处理 |
| --- | --- |
| 仅展示文案且不影响指令/契约 | 运行相关证据通常不失效，保留评审记录 |
| 指令、输入输出、上下文或模型要求变化 | 创建新候选，重跑受影响的目标与安全案例 |
| Skill/Tool 版本变化 | 创建新候选，重做依赖检查、能力特有失败和相关业务案例 |
| Binding 身份、范围、端点或契约语义变化 | 产生新修订，原试运行证据不能放行新绑定 |
| 等价凭据轮换 | 保持绑定语义前提下验证连接可用，不复制密钥到版本证据 |
| Runtime/模型变化 | 重做能力匹配与目标环境 P2；不能只修改目录标签 |
| 权限撤销或 Agent 停用 | 立即约束新动作；历史快照只用于解释，不能恢复权限 |

## 7. 完成定义

一个 Agent 可以标记为“已发布并验收”，必须同时满足：

- 工作目标、范围外事项和完成判据明确；
- AgentSpec、精确依赖、Binding 和实际执行版本可追溯；
- 统一 DSH 执行链、当前授权和可执行限制有证据；
- 五类 v1 案例完成机器断言和人工 rubric；
- 输出通过 `task-result/v1` 表达真实结果，必要回执和 Artifact 已登记；
- 所选扩展完成各自设计、代码和验证，未选扩展没有被文案暗示为已支持；
- 验收报告区分 P0、P1、P2，并列出环境、版本、时间和未覆盖项。
