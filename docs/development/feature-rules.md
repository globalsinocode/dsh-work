# 功能规则

本文汇总已交付功能中仍约束后续开发的产品规则、权限边界和安全约束。系统边界见[架构总览](overview.md)，接口与端口见[内部端口与契约](internal-ports.md)；准确字段以 OpenAPI、SQL 迁移和源码为准。修改下列功能时同步更新本文；规则被新决策替代时直接改写，不保留并行的旧版本。

各节末尾的“未完成”只列仍开放、会影响后续开发判断的事项。

## 1. 跨功能约束

- **统一执行链路：** 员工对话、管理助手、试运行、自动任务和主动任务都经 Run/Attempt → Runtime Adapter → DSH。DSH 不可用时明确报告不可用，不降级为直接调用模型，测试替身不能成为生产备用引擎（见[项目工作规范](../../AGENTS.md)）。
- **不可变事实：** 不修改已发布版本，不回写旧 Attempt 或其 Manifest，不覆盖已应用的 SQL 迁移。
- **执行前复核（A2）：** 个人与团队任务在实际执行前复核当前身份、固定能力和输入授权；团队另加成员与角色检查。旧 Manifest 不会因时间推移扩大权限，重试也不换成新版本。授权服务故障记为 `AUTHORIZATION_CHECK_UNAVAILABLE`，不伪装成撤权；撤权记为 `AUTHORIZATION_REVOKED`。
- **当前时间：** 每个 Agent 执行的 Manifest 带 `timezone`（IANA）；DSH 适配器把 `created_at` 按该时区渲染为系统提示中的“当前时间”（日期、星期、时刻与 UTC 偏移），模型的“今天”“本周”以此换算。主动任务与自动任务用各自日程的时区，主动任务的验证案例同样用该主动任务的时区；员工交互与其他验证案例用平台默认时区 `DSH_WORK_TIMEZONE`（缺省 `Asia/Shanghai`，无效值启动失败）。重试按重试时刻重新固定。
- **跨空间输入（A1）：** 同一 Workspace 内本人可跨会话复用已上传附件；跨 Workspace 的隐式引用一律拒绝。本人上传不替代来源空间的当前权限。下载可按归档只读规则放行，新任务输入必须来自活动空间且仍有权访问。
- **试运行证据隔离（8a）：** Skill 试运行的进度、激活、Python 执行、最终回答和发布证据按精确 Attempt 隔离；验证依据是启动时固定的内容。未绑定的历史测试不能充当新策略的证据。
- **读取复核当前权限：** 快照不可变不等于永久可读。列表、详情、搜索、计数、下载、SSE 续传、Run 启动、重试和工具读取都按当前授权检查，不能只隐藏按钮。已经交付的内容无法回收。
- **不伪造结果：** 平台根据持久化证据判断结果（`task-result/v1`），模型自述完成不能替代成果登记或工具回执。

## 2. 个人工作区与内容

### 2.1 入口与空间解析

- 员工端主导航固定为新对话、Skill 广场、AI 同事、项目空间、自动任务。历史对话和我的文件保留路由、数据能力和上下文入口，但不进主导航；修改导航时同步 `e2e/TEST-CATALOG.md` 与 `e2e/personal-workbench.spec.ts`。
- 后台默认个人 Workspace 保留，员工端不显示它的卡片、选择器和成员管理。
- 全局请求不带 `workspaceId`，由服务端按当前用户解析；显式传入错误 ID 必须拒绝，不能回退到第一个团队。团队入口固定团队归属；旧 Session/Run 不迁移空间。
- `POST /sessions` 接受省略空间、本人个人空间 ID 和 legacy standalone；不接受他人个人空间或无权团队。
- `/workspaces/:id` 先经服务端有权列表确认；无权 ID 显示拒绝，不静默跳回默认页。`/artifacts` 是 `/files?source=artifact` 的别名；`/tasks/:runId`、`/conversations/:runId` 继续可用。
- 无数据库的原型环境中，持久化功能返回 503，不用空列表或模拟回答冒充成功。

### 2.2 历史与文件

- 本人历史按作者和当前空间权限在 SQL 中过滤后再按 Session 分页；最近 Run 列表只是快捷入口。本人全局历史不等于团队共享会话目录。
- 游标保留数据库微秒精度，不用毫秒截断的 Date 定位下一页。
- “我的文件”统一展示个人资料、会话附件和生成成果，来源由服务端关联确定，不为每类建表；下载复用文件授权。

### 2.3 内容生命周期（`logical-retention-v1`）

权威策略来自 `GET /api/workbench/v1/content-policy`。保留期限为 `null` 表示尚未批准清理时限，不表示已删除或可以任意清除。

| 操作 | 前台结果 | 数据与权限 |
| --- | --- | --- |
| 移除对话 | 历史和最近入口不再显示；不提供恢复；旧深链明确不可用 | Session 标记 archived；消息、Run/Attempt、文件、成果独立保留 |
| 对话文件与成果 | “我的文件”显示实际来源；原对话移除后不提供失效链接 | 仍需当前身份、对象和来源空间授权 |
| 移除文件 | 不再显示；停止下载和新任务引用 | 写入 `removed_at/removed_by`，保留不可变对象、解析结果、成果版本和历史 Run 引用；不改写历史 Manifest |
| 账号停用或离职同步 | 登录 Session 撤销；历史、文件、新任务拒绝；在途执行按 A2 停止交付 | 保留原作者与 Workspace；不自动转交；重新启用仍走当前授权 |
| 团队归档 | 现任成员按权限只读；被移出者拒绝 | 与个人“移除对话”不同，不开放写入 |

- 没有物理删除、清理定时器、自动到期销毁或隐式内容移交。上线前企业须明确保留期限、备份、审计例外和合法保留要求；以后引入清理须先做 dry-run 清单、检查历史引用和保留锁、经审批后再实施。
- 删除和移除请求的幂等不豁免当前权限。平台管理员身份不自动开放业务正文，运维与审计须使用明确授权。
- 锁顺序为 Workspace → Session → Run，与创建 Run 一致。仍有排队或运行中的任务时，先停止任务再移除对话。

## 3. 团队工作空间

界面名称为“项目空间”（代码、表与接口仍用 workspace / team）。定位与后续切片见[项目空间方案](../design/project-space-plan.md)。

### 3.1 范围

- 项目空间是人与 Agent 协同完成一个项目的地方：负责人组建由员工成员和 Agent 成员组成的团队，用项目简报对齐目标，把工作拆成项目任务交给员工或 Agent，成员在共享讨论中 @Agent 临时问答；项目档案员在任务完成后把成果整理进项目档案，供之后的 Agent 任务参考。工作空间同时承担内容归属、协作发现和访问边界，空间角色不能扩大员工的企业数据权限。
- **已放弃，不再实现：** 内容分享与快照、同团队派生、来源撤回传播、成果审核；成果评论与 @成员、个人收藏与空间置顶、空间模板。团队会话产生的成果对空间成员可见（TW-10），项目任务完成即产出团队成果，不设审核。不为这些能力预留入口或 `scope` 参数。
- **首版不包含：** 在线共同编辑文件、跨企业邀请、跨空间访问、匿名公开链接、外部系统写入。
- 本节规则只作用于团队空间。个人空间不添加员工或 Agent 成员，不接入团队共享、来源依赖、归档和通知，也不要求团队 Agent 关联 ID 或 `workspace_capability_grants`。个人空间的入口与生命周期按第 2 节演进。

### 3.2 员工成员与角色

- 从当前企业有效业务员工目录选择成员，AI Hub 员工与独立账号员工同等可选，只返回姓名、部门等最小字段；不向员工端开放管理端全量身份数据。离职、停用或无应用访问资格的账户不能添加。重复添加幂等。
- 角色为负责人（owner）、管理员、成员、只读成员。负责人以 `member_role = owner` 的成员关系为唯一事实来源，团队空间任何时刻恰有一个有效负责人（团队限定的可延迟约束；不改个人空间的唯一索引和保护触发器）。创建者与当前负责人分离，转交不改写内容的原始创建者。
- 转交锁定空间行，在同一事务更新新旧负责人角色。唯一负责人不能被移除或直接退出，须先转交。
- 移除与主动退出规则相同：立即撤销后续访问，在途运行按 3.8 收敛；保留其已上传的共享文件、作者归属和业务记录，不自动转移所有权或清理贡献。
- 负责人停用等异常由有明确治理权限的平台管理员处理，不因此开放空间私有内容。

### 3.3 Agent 成员

- Agent 成员只引用平台已发布且允许加入该空间的 Agent，固定加入时的启用版本；不在空间中复制或修改 Agent 的模型、凭据、Skill、Tool 配置。同一空间同一 Agent 不重复加入。Agent 不是员工账户，没有空间管理角色。
- 添加时复用精确版本授权，校验 Agent、Skill 和 Tool 依赖，关联与授权在一个事务中成功后才可用；缺依赖不部分保存。Skill 不能间接扩大 Agent 的 Tool Allowlist。只有负责人能添加、停用、启用、升级和移出 Agent。
- 授权来源与有效授权是多对多关系：区分 Agent 关联版本、人工授权和待对账旧授权。两个 Agent 共用一个工具时，移出其一保留另一来源；来源不明的存量授权不能猜测归属，对账前阻止涉及歧义来源的破坏性调整。迁移 `0079` 只为仍有效的 `agent_member` 来源补齐缺失授权。
- 状态分为可用、已停用、不可用（附具体原因：平台未授权、版本失效或 Runtime 不可用）和已移出。停用或移出后阻止新的启动、续写和重试，排队与活动任务经取消链路收敛；保留历史消息、成果和版本来源，不撤销其他 Agent 仍需要的共享工具授权。
- 版本升级由负责人显式执行，只影响新会话；既有 Session、Run、Attempt 保持原快照。旧版本仍获授权时可继续使用，失效或撤权时明确阻止。
- Agent 以自己的 Principal 执行（`executed_as` 为 Agent Principal），发起员工记为 `initiated_by`。团队空间的交付边界是全体现任成员而不是发起人：岗位角色只取 Agent 授权；数据范围取 Agent 授权与全体现任成员（含只读成员，不含停用账号）数据范围的交集（`resolveTeamCommonDataScopes`），并受空间能力授权约束。发起人只用于归因和准入（可见角色、非只读成员）。个人空间与员工个人请求保持角色和数据范围都与员工求交。发布版本执行时直接使用冻结时固定的工具绑定，其中自动解析的平台默认工具只固定可见角色可及的部分；Agent 自己声明且可见角色可及的工具不受影响。草稿在冻结前仍按全部岗位角色解析默认工具，冻结后统一以固定绑定为准。负责人与管理员在 Agent 名册中看到每个 Agent 的“本空间可交付数据范围”；添加员工前经 `GET /workspaces/:id/agent-members/disclosure-impact` 预览，会缩小范围时先确认。加入空间不会让 Agent 自动读取全部共享文件或成员内容，只能访问用户显式引用或受控工具获准返回的内容；例外是项目任务线程的执行默认带上当前项目简报（3.9）。成果保留发起员工归属并标注生成它的 Agent。
- 一个 Session 固定一个 Agent 版本；换 Agent 时新建对话，不在原 Session 内静默切换。

### 3.4 共享讨论与 @Agent 触发

- 团队会话是全部空间成员可见的共享讨论（一条会话对应一个话题）。普通消息是成员间讨论，不产生 Run（`messages.run_id` 为空）；纯讨论会话的 `agent_version_id` 可为空（迁移 `0041`）。标题取首条输入去除首尾空白后的前 40 个字符（超出加省略号），后续发送不改名，不用模型生成标题。
- 只有消息 @ 当前可发起的 Agent 成员时才创建 Run，绑定该成员的固定版本（`workspaceAgentMemberId` 与 `resolveTeamSessionAgentVersion` 的服务端校验）。不 @ 不触发；Agent 不监听讨论、不自动发言、不发生 Agent 之间的循环调用。唯一例外是项目任务线程：回复无需 @ 即交给承接 Agent（3.9）。只有一个可发起成员时可自动预选，用户显式选择不被覆盖。
- Agent 回复进入共享消息流，对全部成员可见；数据范围按全体现任成员的交集裁剪（3.3），可见范围与交付范围一致。回复标注发起人与执行的 Agent 成员及版本。
- 发讨论消息和 @ 触发要求现任且非只读成员；只读成员可读讨论流，前端按 `currentUserRole` 隐藏输入框及停止/重试入口。成员被移除或空间归档后停止投递新消息和运行事件。
- 团队 Run 的 `conversation_history` 包含全部讨论消息，用户消息统一加“发送者：”前缀；个人会话不加前缀。
- 成员级实时推送经 `GET /workspaces/:workspaceId/session-events`，每批写出前按与 `/runs/:id/events` 相同的口径复核，失权即断流。
- 会话删除由创建者独占（按 `created_by`）。创建者可删除含其他成员消息的讨论串，删除后全员不可见；成员级删除或管理员介入须另行立项。

### 3.5 共享文件与版本

- 支持 PDF、DOCX、XLSX、CSV、TXT、Markdown，单文件上限 20 MB；遵守当前运行的文件数量和解析文本预算，不因共享扩大限额。
- 状态区分上传中、检查中、解析中、可引用、失败和已移除。只有通过安全检查且解析成功的不可变文件对象可进入 Run；引用固定文件对象 ID、解析结果 ID 和内容快照，不只把文件名拼进提示词。
- 正常成员可上传、下载、引用并移除自己上传的文件；负责人和管理员可移除任何共享文件；只读成员只能查看和下载。
- 空间共享文件与私有对话附件分开，附件不自动成为团队文件，文件名、大小和数量也按读取权限过滤。
- 移除是逻辑移除：不再出现在有效列表，不允许新引用，历史运行仍可追溯。文件移除不等于来源权限撤销；成员收权时历史读取仍按当前授权拒绝。物理清理由独立保留策略控制。
- 版本：在同一逻辑文件下上传新版本并记录上传人、时间和说明，不覆盖既有对象。新版本解析成功前旧有效版本继续可用；新引用默认用最新有效版本，已加入对话的文件固定所选版本；并发上传以明确的版本分配或冲突反馈处理。个人文件不使用逻辑版本。

### 3.6 生命周期与归档

- 负责人可修改设置、转交、归档和恢复。归档复用 `workspaces.status` 和 `archived_at`，历史动作由审计记录保留，不提供永久删除。
- 归档语义为只读保留：现任成员按权限查看会话、文件、成果和历史运行并下载；新对话、续写、重试、上传、成员与 Agent 变更、设置修改一律拒绝。必要的访问撤销和负责人治理在归档后仍然允许。
- 授权分读取轨和执行轨：执行轨要求空间处于活动状态；读取轨只要求调用者是现任成员。读路径不得复用只认活动状态的空间解析，写路径不得因读取轨放宽。
- 有排队或活动 Run 时不允许归档，提示先等待完成或取消。恢复不自动恢复已移除的成员，不扩大能力授权。
- 团队列表提供“全部 / 活动 / 已归档”筛选，归档筛选只查当前用户仍有权访问的团队。

### 3.7 动态、通知与用量

- 团队动态只记录成员变动、文件上传与移除、项目简报更新、项目任务创建与员工任务完成等协作事件；普通消息不进入动态。审计日志与团队动态是不同的可见投影。
- 通知仅站内，支持未读标记和按空间静音；接收与点击时都检查可见权限，失权后不能经旧通知读取正文或敏感名称。业务成功后由持久化事件生成通知并幂等去重，通知失败不把已成功的业务变更报成失败。
- 空间用量只展示 token 与调用次数（来自 `model_usage_events`），不展示金额，不从消息长度猜测消耗；仅负责人与管理员可见，归档空间可读。个人空间返回 422，前端不发请求。

| 添加、停用、升级、移出 Agent 成员 | 允许 | 不允许 | 不允许 | 不允许 |
| 修改空间设置、转交、归档、恢复 | 允许 | 不允许 | 不允许 | 不允许 |
| 查看空间用量 | 允许 | 允许 | 不允许 | 不允许 |
| 退出 | 先转交 | 允许 | 允许 | 允许 |

原则：

1. **管理权与内容读取权分离。** 管理角色不因身份自动读取他人的个人空间内容或私有附件。
2. **企业权限与空间权限取交集。** 空间授权不能越过平台授权上限。
3. **不自动公开既有内容。** 加入团队不会让历史私有对话、成果和附件互相可见。
4. **收权覆盖整条链路。** 成员移除、退出、降级和 Agent 停用/移出在提交时更新团队授权修订标识并写入持久化撤权事件；成员加入只更新修订标识，由修订变更触发的全量复核取消快照数据范围超出新共同范围的在途任务；Run 启动、重试、队列领取后和调用 Runtime 前复核当前员工、成员角色、Agent 关联和平台授权；SSE 建连、续传和每批写出前复核；撤权处理经平台内部系统取消入口幂等收敛排队、运行中和终态任务，撤权事件可重放，进程重启后继续处理。无 Session 的系统运行（对话摘要、项目档案整理）因撤权或启动前容量不足收敛为失败时，立即交给对应入口收尾，不再等待事件回放或过期清理；项目档案同样计入整理重试次数。

接口与状态码：

- 非成员与不存在的空间返回一致的拒绝，不能借状态码差异枚举空间是否存在。团队会话分页在个人空间上返回 403；其他团队专用接口（共享文件、成员名册、Agent 名册、负责人转交等）在个人空间上返回 422。
- 授权拒绝使用类型化错误（如“当前用户角色不可使用所选 Agent”为 403），不靠错误文案分类。
- 列表、页签数量和搜索使用同一可见条件，在服务端聚合后分页计数，不先限制 Run 数量再在前端去重。缓存或投影必须能按当前身份过滤，并在收权后失效。

### 3.9 项目简报与项目任务（S1）

- **项目简报：** 空间的一个属性（正文 ≤8000 字、可选截止日期），每次保存新增版本（`workspace_brief_versions`），不覆盖历史。全部现任成员可读（读取轨，归档可读）；负责人与管理员在活动空间可编辑。保存写入“简报更新”动态。
- **项目任务：** `project_tasks` 是业务层工作项，不复用执行层 `tasks`。字段为标题、说明、创建人、承接者（一位非只读员工成员或一个可用 Agent 成员）、可选截止日期；Agent 任务可引用本空间已解析成功的共享文件版本（最多 5 个，与单次 Run 上限一致）。非只读成员可创建；创建人、负责人与管理员可编辑、改派与移除（逻辑移除，线程与成果保留）；只读成员只读；归档后只读。
- **员工任务：** 待办 → 进行中 → 已完成，由承接人、创建人、负责人或管理员推进；完成时可附说明与共享文件，交付显示在任务卡片上。完成写入“任务完成”动态。
- **Agent 任务即任务线程：** 首次启动经既有 `createSession` / `startRun` 创建绑定承接 Agent 成员固定版本的团队会话，首条消息为任务标题与说明，不新增执行入口或无 Session 入口。状态由线程最近一次 Run 推算（无 Run 待办、执行中进行中、成功已完成、失败或取消执行失败），不单独存储。改派只在线程无执行中 Run 时允许，改派后从新线程开始。
- **线程续接：** 任务线程内非只读成员的回复无需 @，服务端固定交给承接 Agent（携带其他 Agent 成员关联时 422），回复人记为发起人。同一线程同一时间只允许一个执行，执行中再回复或重试返回 409，需等待完成或先停止；并发回复由创建 Run 时在会话行锁内复核，只受理一个。启动 Agent 任务未能创建 Run 时（如 Runtime 不可用）解绑并归档这条空线程，任务可直接重新启动。
- **项目上下文：** 任务线程中员工交互执行的 Manifest 携带 `project_context`，固定当时的简报版本与内容摘要；DSH 适配器把它作为参考资料渲染进系统提示，声明不是操作授权。重试按当前简报重新固定。
- **停止标注：** 停止沿用现有取消（发起人与非只读成员可停止）；Run 记录第一个请求停止的员工（`runs.cancel_requested_by`），线程执行记录显示“某人 发起 · 某人 停止”，Run 详情显示“本轮执行已由某人停止”；系统撤权取消不标注员工。
- **团队成果来源：** 项目空间“成果”页签的成果卡片标注来源：所属项目任务（任务线程产生的成果，任务移除后不再标注）、承接 Agent 及版本、发起人；普通讨论中 @Agent 产生的成果只标注 Agent 与发起人。个人空间不标注。
- **设为任务：** 讨论中经 @Agent 执行过的线程可由非只读成员设为任务，承接者为该线程最近一次执行的 Agent 成员；未执行过或已是任务的线程返回 409。

### 3.10 项目档案与项目档案员（S2）

- **项目档案：** 有序条目列表（最多 50 条，每条 1～500 字，不可重复），每次变更新增版本（`workspace_archive_versions`），按版本记录来源：档案员（运行与依据的项目任务）、手动编辑或回退（回退到第几版）。全部现任成员可读档案与最近 100 个版本（读取轨，归档可读）；非只读成员在活动空间可添加、编辑、删除条目和回退。写入携带基于的版本号，版本已变化返回 409；前端收到 409 时把本次单条修改（编辑、添加、删除）重新应用到最新版本再保存一次，要编辑的条目已被他人改掉或删掉时显示最新档案并把输入转为新条目草稿，不丢失人工输入；回退以历史版本内容生成新版本，回退到当前或不存在的版本返回 422。接口为 `/workspaces/:id/project-archive`（含 `/versions`、`/rollback`），与空间归档接口 `POST /workspaces/:id/archive` 区分。
- **只在档案页签展示：** 档案变更不写入最近动态；任务线程、简报卡片等其他页面不展示档案提示。不提供停用档案或停用档案员的功能。
- **项目档案员：** 平台内置的 `project-archive` 系统运行，与会话摘要同类：不是 Agent 成员记录，不占名额；经 Run/Attempt → Runtime Adapter → DSH 执行，不建 Session、不带工具/文件/数据范围，以平台系统身份执行，后台车道全局并发 1，容量不足时直接失败。员工任务标记完成、Agent 任务线程的一次执行成功时登记待整理成果（`workspace_archive_inputs`）并触发；同一空间同时只有一次整理（`workspace_archivist_state`），期间完成的成果进入下一次，单次最多 20 项。输入为当前简报、当前档案条目和成果（Agent 任务取该次最终回复的模型原文，不含平台追加的知识与记忆引用页脚；员工任务取标题、完成说明和交付文件名）；档案员只记录现有档案中还没有的、与项目目标相关的结论、决策、术语和进展，不记录执行过程说明、出处引用、对档案本身的复述、对已有结论的再次确认和简报已写明的目标与约束。输出只含新增与改写（`{"add": [{"text", "why_new"}], "update": [{"from", "to"}]}`），档案员不能删除条目；平台在基于的版本上应用：改写须逐字匹配现有条目，否则整份输出无效；与现有条目重复（忽略空白与标点）的新增略去；结果经条目校验后写入新版本，与当前内容相同时不生成新版本。
- **人工优先与失败：** 整理完成时若档案已被成员修改，丢弃本次输出并基于最新版本重新整理；输出无效、失败或取消时成果回到待整理，随下一次触发重试，同一成果失败 3 次后放弃。失败不提示用户，记录在运行历史与审计。执行前复核空间仍为活动项目空间且整理批次未被取代。
- **Agent 读取档案：** 任务线程中员工交互执行的 Manifest `project_context.archive` 固定当时的档案版本（版本号、条目与摘要；没有条目时不携带），与简报同样作为参考资料渲染进系统提示，声明不是操作授权；版本号只用于追溯，不在界面展示。

### 3.11 界面基线

- 复用现有 `EmployeeShell`、空间卡片列表与创建弹窗、空间详情的“任务 / 对话 / 共享文件 / 成果 / 档案”页签（项目空间默认“任务”；个人空间没有任务和档案页签，只有“对话 / 文件 / 成果”）、右侧项目简报卡片与 `WorkspaceInfoPanel`（小屏为信息抽屉），以及现有组件、[Design Token](../../packages/design-tokens/src/tokens.css) 和按钮样式；不新增独立主题，也不采用此前被否决的独立交互稿。
- 右侧项目简报卡片、成员区与 Agent 区可分别收起，收起状态只是本浏览器的偏好。成员区同时展示员工和 Agent，人数分别统计（如“4 位员工 · 2 个 Agent”），Agent 区固定显示“项目档案员（系统）”且不计入 Agent 数；“管理成员”弹窗同屏上下分段管理员工与 Agent；Agent 的能力、版本和状态放在成员详情里，不另设“可用能力”入口。
- 动态在右栏显示“最近动态”摘要和“查看全部”抽屉，不占第四个页签。
- 状态区分加载、空数据（空间无内容 / 本人无内容 / 筛选无结果）、错误（保留输入）、无权限（写操作不渲染；无读权限时不返回名称、摘要、数量）、不可用（区分未加入 Agent、Agent 停用、能力未授权、Runtime 不可用、文件解析失败）和归档只读。
- 删除、移除、转交、归档需二次确认；所有字段有 label，图标按钮有可访问名称；清空可选说明时 API 显式传 `null`。

## 4. 管理助手

- 管理端 `/assistant` 默认为普通对话，由 `admin-assistant` 的 DSH Agent Loop 识别意图，不在浏览器维护关键词路由。查询、解释和诊断直接回复，不出现执行确认。
- 识别到管理任务时先展示任务摘要、将调用的专用助手、预计读写及影响范围（任务提案）。管理员确认后才创建专用 Run：`admin-skill-install`、`admin-agent-manage` 或 `admin-platform-operations`。
- 专用助手只做受控检查并生成结构化计划，平台工具不在 DSH 调用时直接写入。含平台写入的计划需第二次确认，确认时校验计划摘要、Run 成功状态、管理员当前写权限和目标当前状态；Skill 安装的“确认安装计划”即第二层确认。
- **一次确认的例外（C6）：** 只有现存 Agent 草稿的四个展示字段 `name`、`description`、`welcomeMessage`、`examplePrompts` 可由通用助手直接生成计划并一次最终确认，白名单唯一定义在 `server/src/modules/agent/agent-draft-copy-policy.ts`。systemPrompt、负责人与部门、角色、数据范围、工具、Skill、可见性、发布与停用、Runtime 参数和未知字段一律走两次确认；合法字段混入任何不支持的键也拒绝，不接受客户端或模型给出的风险标签。专用 Run 执行高风险计划时必须存在同一管理员、Session、专用 Run 和目的的已确认委派记录。旧计划没有 confirmation 元数据时按两次确认处理。
- 操作计划保存 Agent 配置指纹或 Runtime 配置 revision，领域服务在目标行写锁内再次比较，状态已变则拒绝，不自动重试。
- 计划进入 `executing` 后服务退出，重启时只核对事实：目标与计划后状态一致收敛为 `executed`，否则收敛为 `failed` 并写入对话消息；不自动重放管理写入。
- 确认、取消、执行结果和失败都作为持久化对话消息返回。取消的卡片不能再执行；对话历史在管理员身份变化时重置，浏览器不持久化来源和命令文本。
- 路由和侧栏沿用 `adminRead`，只读账号可普通对话和查看提案，但不显示也不能调用确认。管理会话使用 `sessions.audience=admin`，与员工会话隔离，API 只返回当前管理员自己的记录。
- 每轮向 DSH 传入同一管理员会话最近 12 条消息、合计最多 24000 字符；历史不构成新的操作授权。
- 首次进入提供普通问答、Skill 管理、Agent 管理和平台运维四个示例，点击只填入输入框，不自动发送。各业务页的“交给管理助手”通过 `context=skills|agents|operations` 带入领域，不自动执行。

未完成：普通查询、三类提案、两层确认、取消、撤权、状态漂移和重启恢复尚未在真实 DSH 与测试 PostgreSQL 环境端到端验收。

## 5. Skill 安装与发布

### 5.1 入口与来源

- 三个入口共用包解析、校验、安装记录、版本保存和发布服务：「新增 Skill」页的 ZIP 上传、直接链接导入（`channel=link`，无 Run/Session），以及管理助手对话（`channel=assistant`）。手工填写名称和指令的创建方式已删除，不保留隐藏入口。
- 只安装已有 Skill，不通过对话新建、编写或改写 Skill；没有来源时引导提供链接或 ZIP，不生成替代包，也不补写缺失文件。
- 支持的来源：
  - 公共 HTTPS 的 ZIP 或单个 `SKILL.md`，默认允许 GitHub 相关域名，其他域名由 `DSH_WORK_SKILL_SOURCE_HOSTS` 精确加入白名单；
  - GitHub 仓库或目录链接，解析为固定提交，多 Skill 时须指定目录或名称；
  - `npx skills add owner/repo --skill name`（含 `skills@latest`、`skills@x.y.z`、`--skill=name`）；
  - `curl -L https://.../skill.zip`，支持 `-L/-f/-s/-S` 及其组合；
  - 明确的自然语言，只接受唯一的 GitHub `owner/repo` 和可选 Skill 名称。
- 命令只作为来源语法解析，不执行 npm 包或 Shell。不支持私有凭据、带鉴权或任意查询参数的来源、管道、重定向写盘、命令组合和变量展开。每次重定向都校验域名，DNS 结果固定到实际连接，拒绝私网和保留地址；IPv6 下载暂时关闭。

### 5.2 包规则

- `SKILL.md` 带 YAML frontmatter，必须有 name、description 和正文；version 可选，缺失时不伪造。拒绝重复 YAML 键和别名展开。
- 允许 md、txt、json、yaml/yml、csv、toml、py 和 LICENSE。Shell、二进制、运行时动态安装依赖和未适配工具不会被静默忽略，而是拒绝解析或标为不兼容。
- `allowed-tools` 已适配 read/glob/grep 的固定平台版本，纯指令包可以零工具；Python 包声明 `python_execute@1.0.0`，只有固定沙箱镜像可用时才兼容。
- 正文明确要求调用的另一个 Skill 须在同一制品中，递归形成依赖图；缺失或循环依赖阻止确认。单次计划最多 32 个 Skill。依赖 Skill 随根 Skill 按锁定版本加载，员工端只显示曾作为安装根节点的已发布 Skill。
- 限额：下载 20 MB；ZIP 解压 32 MB / 2000 项；所选 Skill 64 文件 / 1 MB（运行时同样按单个 Skill 限制）。校验 UTF-8、路径穿越、绝对路径、重复与冲突、CRC、大小和压缩格式；所选 Skill 目录不允许符号链接或特殊文件。无关 Skill 的不兼容声明不阻断安装。

### 5.3 存储、确认与发布

- 内容保存为 `${DSH_WORK_DATA_ROOT}/skills/packages/<name>/<sha256>/` 下的不可变文件夹：先写临时目录并校验，再原子重命名转正。PostgreSQL 只保存相对引用、文件路径、大小、摘要、来源、计划和业务状态，不保存正文或脚本源码。生产备份须把整个 `DSH_WORK_DATA_ROOT` 与 PostgreSQL 作为同一恢复点。
- 确认接口校验管理员当前权限、运行状态和完整计划 SHA-256，在一个事务内保存根 Skill、全部依赖版本、依赖边、安装结果和审计；重复确认返回同一结果，不兼容、已取消或摘要过期的计划不能确认。不按名称覆盖已有 Skill，不自动发布，也不更新 Agent 引用。
- 安装与发布分离：入库只表示已保存待验证版本。发布要求当前包及配置通过校验、对应配置的严格试运行成功，并由管理员确认。配置或依赖变化使旧证据失效；仅链接入口允许依赖待验证时先保存草稿，但不能称为兼容，发布时在领域事务内复核能力与精确试运行证据。
- 严格试运行要求根 Skill 和全部递归依赖都留下 `activate_skill` 激活证据，含 Python 的 Skill 还要留下沙箱退出码为 0 的执行证据；“DSH 成功并给出一条回复”不算通过。发布根 Skill 时同一安装图的依赖草稿在一个事务中同步发布。
- 发布更新活动版本，Agent 和既有对话的精确版本引用不自动升级。回滚切换活动版本，不改写历史制品；启用/停用与待发布版本独立管理。已安装包不能经文本编辑 API 原地改写。
- 员工执行与试运行先获得 Skill 名称、说明和版本目录，调用 `activate_skill` 后由 Runtime Adapter 校验摘要，并把目录只读暂存到 Attempt 工作区。

### 5.4 场景试运行（8b）

- `POST /api/admin/v1/skills/test-runs`（异步）和 `/skills/test`（同步）接受可选 `scenario`：`requiredSkills`、`requiredPythonEntries`（入口必须在本次锁定目录中）和断言。只允许 `admin-skill-test` 使用。
- 断言只支持 `reply_contains`（字面包含）和 `reply_json_equals`（严格 JSON 标量，数字与字符串不等同，代码块或附加解释不算严格 JSON）；最多 32 条，路径最多 8 段，能力和入口各最多 64 个。不允许自定义代码、正则或锁定目录外的脚本。场景只约束验证，不扩大工具或权限。
- 场景在启动时规范化并固定到 Manifest 的 `test_scenario`，重试完整复制；根 Skill 始终必需。
- 场景证据使用 `scenario-v1`，与完整严格证据 `attempt-v2` 分开。没有完整严格证据时，发布聚合同一根版本、同一配置和依赖内容摘要下的场景证据，必须覆盖所有锁定 Skill 及每个含 Python 的 Skill 至少一个入口。同名场景以最新结果为准，最新失败不借用较早的通过。无断言的通过只标记为“执行验证”。

## 6. Skill Python 执行

- 安装与执行分离：安装只下载、检查、保存，不执行 Python、setup.py、构建脚本或安装钩子。依赖未满足的包可存为草稿，但不能试运行或发布。
- 执行只通过平台工具 `python_execute@1.0.0`，入口只能是已激活 Skill 固定版本中登记的 `.py` 文件。模型不能提交源码、解释器路径、镜像、挂载路径或 Shell 命令；禁止 `-c` 和任意 `-m`。
- 每次调用使用一个摘要锁定镜像（`DSH_WORK_PYTHON_IMAGE`）的临时容器：无网络、只读根文件系统、cap-drop、no-new-privileges，并限制 PID、内存和 CPU。不存在宿主机 Python 或 venv 回退，Python `-I`、AST 检查或字符串黑名单都不算安全边界。服务启动时检查镜像，失败则不启动；未配置镜像时脚本型安装计划不兼容。
- 容器不挂载整个 Workspace、`DSH_HOME`、应用目录、数据库配置、Docker socket 或凭据；Docker 控制权只在可信平台 Runner 手中。运行时禁止联网安装依赖，新增依赖须发布新的环境镜像。
- Python 只能写任务输出，不能写企业业务系统。脚本结果是不可信工具输出，不能授予新权限；日志和文件可能含业务数据，只进入获授权的会话，审计不保存正文。
- 发布须同时满足依赖匹配、权限配置、真实脚本执行证据和管理员验收；只有一段回答或退出码为 0 都不足以认定业务效果合格。环境、入口或依赖变化后必须重新验证。

未完成（在此之前不得宣称完整的生产脚本平台）：版本化环境注册表与周期自检；包格式 v2 与显式入口配置；原始 CSV/XLSX 输入的授权暂存；输出收集、格式与安全检查，以及事务化 Artifact 发布；数据库调用记录、全局并发槽位、取消和重启恢复；非 root launcher、tmpfs 容量限制和目标 Mac mini 的隔离验收。

## 7. 自动任务（AG-03）

首版只做“按计划发起普通员工任务”，执行入口始终是 Run/Attempt → Runtime Adapter → DSH。

| 能力 | 规则 |
| --- | --- |
| 创建与启用 | 选择已发布版本、本人身份、确定性输入和 Workspace，配置每日、每周或手动以及 IANA 时区，本人确认启用 |
| 任务试运行 | 可选；Agent 发布证据和确定性准入检查仍必需 |
| 调度 | 单进程、单一调度所有者；额外实例拒绝进入调度与启动恢复，不支持多实例自动接管 |
| 执行隔离 | 每次触发新建独立 Session，固定 Agent Version，不带入原会话历史 |
| 停机遗漏 | 不补跑；停机期间的到期槽位合并为一条遗漏区间记录，恢复后从下一个未来槽位开始 |
| 准备中断 | 已受理但没有 Attempt 的 Run 收敛为失败，不续办 |
| 执行失败 | 不自动重试；用户“再次立即运行”产生新触发、新 Session 和新 Run |
| 已提交 Attempt | 复用 Run 恢复：queued 的 Attempt 重新领取并鉴权，Worker 丢失的活动 Attempt 失败 |
| 结果 | 进入该次 Session 的消息与成果，不新增投递状态机或外部通知 |

- **日历：** `manual`、`daily`（`HH:mm`）、`weekly`（`HH:mm` 加去重非空的 0–6，周日为 0）。预览和调度共用 `nextSlot()`；不存在的本地时刻跳过，重复时刻取第一次。启用、改规则或重新启用都从确认之后的下一个槽开始。
- **去重：** 定时 `trigger_id` 由 `(automation_id, schedule_revision, planned_slot_utc)` 摘要生成；手动由 `(automation_id, manual, request_idempotency_key)` 生成，并保存配置 revision 与请求指纹，同键异请求拒绝、同键重放返回原记录。唯一键为 `(tenant_id, automation_id, trigger_id)`。
- **原子受理：** 触发记录、Session、Run、关联和游标推进在一个事务中提交；受理时冻结执行配置（版本、身份、Workspace、授权上限、模板、文件版本），恢复时不读可变任务内容重建输入。执行状态不另存，通过 `run_id` 读取 Run。
- **重叠：** 锁定任务行后检查已受理且未结束的 Run（含无 Attempt 的 queued 和 cancel_requested），有则直接记为 skipped。
- **授权：** 后台身份由 identity/authorization 解析，不伪造 HTTP 身份，不保存 Cookie 或长期 Token。AI Hub 用户要求可用配置和信任窗口内的成功目录同步（读 `last_succeeded_at`；从未成功、失败或超窗均拒绝）；独立账号不依赖 AI Hub，但仍检查账号、租户和当前授权。`scopeCeiling` 与当前权限取交集。配置、启用、触发、执行前、活动期和结果读取各自复核；不可变 Manifest 的输入或权限超出当前许可时拒绝该 Attempt，不原地改写。只允许已批准且无需人工审批的能力，无法确定能否无人值守的工具一律拒绝。
- **暂停与停用：** 暂停停止新触发，清理排队和没有 Attempt 的 Run，不自动取消已开始且仍获授权的执行。`run-now` 只对已确认配置的 enabled 任务生效，paused 任务须先重新启用。停用是归档语义，任务连同历史执行记录不再可读，确认弹窗必须明示；需要保留历史时用暂停。
- **限额：** 不开放任务级 Token、金额或磁盘预算。`input_template.budget` 的 `timeoutSeconds`、`maxToolCalls`、`maxOutputBytes` 同时冻结为该次 Task 的累计上限，并收紧 Manifest limits，不超过 Agent 与平台上限。每用户和全局待处理数有上限，超限明确跳过并留证。自动任务并发上限为 `min(配置上限, capacity − 1)`，为交互任务保留至少 1 个 Worker；自动任务、对话摘要、验证案例与项目档案员等后台车道合计同样不超过 `capacity − 1`，各车道单独未满也不能合起来占满容量。调度器遇到后台任务超限时继续寻找可运行的交互任务，不让队首阻塞；容量确实不足以保留交互余量时，后台运行以 `BACKGROUND_CAPACITY_EXHAUSTED` 收敛（不是授权撤销）。项目档案整理的失败会计入该批成果的重试次数（上限 3 次），长期容量不足可能放弃该批输入，应先扩容再重试。
- **通用重试：** 通用 Run 重试入口拒绝自动任务来源，引导使用“再次立即运行”。`purpose='automation'` 由服务端设置，属于员工运行（交付成果），不是管理运行。
- **界面：** 显示固定版本、时区、下一次运行、默认限制、最近结果，以及跳过、遗漏和准备中断；启用时告知停机不补跑、失败不自动重试，不宣称任务必达或外部效果恰好一次。

未完成：真实 DSH、目录与工具收权、目标环境容量的 P2 验收；日历细节和事务/领取竞态的浏览器旅程。

## 8. Agent 岗位权限

Agent 是独立 AI 员工，权限与人类员工同构，由管理员在 Agent 详情的“岗位权限”中集中配置（`GET`/`PATCH /agents/:agentId/access`）。它向员工交付工作，也可在批准范围内按时间或事件主动工作；管理员自己验证、自己发布，没有提交审核流程。

- **三个问题：** 可见角色决定谁可以向它请求工作（`agents.visible_role_ids`，不授予执行权限）；岗位角色决定它能用哪些能力；数据范围决定它能接触哪些数据。三者都属于 Agent 而非版本，保存后立即生效，写 `agent.access.update` 审计，不作废验证证据。
- **版本不带权限：** 版本只记录能力（Skill、工具、MCP 范围）等内容，没有可见角色或数据范围上限；能力变化才需要重新验证。草稿接口与管理助手的草稿计划都不能修改岗位权限。
- **能力与角色对齐：** 页面列出每项能力需要的角色（多个任选其一）和数据范围，按表单实时标出“缺少角色 X，暂不可用”，可一键补齐。已声明的能力缺授权时阻断验证与执行；平台默认能力缺授权时只是不装配。
- **结果交付边界：** 员工请求时，Agent 用自己的授权工作，交给员工的数据范围不超过员工本人的数据范围（取两者交集）；主动任务用 Agent 自己的授权，按接收人可见范围交付。执行期撤权即停、工具策略和审批不变。
- **并发：** 修改携带读取时的 `revision`（`agents.access_revision`），过期修改返回 409。只改可见角色不推进执行身份的授权版本，因此不会作废已排队的执行；新增的角色必须当前有效，保留已停用的旧角色不报错（运行时不授予任何权限）。

## 9. Agent 验证与发布

Agent 在详情页 `/agents/:agentId` 一站式管理（S4）：职责与人格、能力、岗位权限、主动任务、经验、验证与发布、运行记录七个分区，分区可经 `?section=` 直达；旧的 `/agents/:agentId/release*` 地址重定向到“验证与发布”分区。草稿经验证后才能发布。接口见管理端 OpenAPI 的 `/agents/{agentId}/validations`、`/agents/{agentId}/publish`；表结构见[数据模型](../design/data-model.md)。

- **版本状态：** 草稿（可编辑，每个 Agent 最多一个）→ 待发布（`candidate`，开始验证时原地冻结，内容不可改）→ 已发布。验证开始后编辑配置会生成新草稿，旧验证结果不能发布新内容；页面提示“草稿已修改”。
- **验证前检查：** 可见角色、执行身份、能力依赖、能力所需授权、MCP 范围、验证案例与工具绑定全部通过才能开始验证，服务端同样拒绝。
- **案例：** 示例问题 + 启用中的主动任务输入 + Agent 的自定义测试问题（属于 Agent，最多 20 条、每条 1～2000 字，跨版本复用）。开始验证时快照进验证记录，之后的修改不影响本次验证。
- **运行：** 受理即返回，案例在后台 `agent-release-trial` 通道并行运行，最多 2 个，并始终为交互工作保留 1 个执行容量；页面轮询进度。每个案例经真实 Run/Attempt → DSH 执行。再次开始验证会取代旧验证并取消其未完成的案例。服务重启时未完成的案例标为“服务重启中断”，可单独重跑。
- **判定：** 固定三项机器检查（留下运行记录、执行成功、回答非空），未全部通过时只能判为不通过；判为不通过必须写原因。判定可修改，重跑清除该案例原判定，过期判定被拒绝。全部判定通过后才能发布。
- **与生产一致：** 验证运行与员工执行共用同一 Manifest 构造函数（`AttemptDispatcher.dispatch`），知识、Skill、工具集、绑定、审批、写入策略与限额一致。差异只有三处：执行授权受员工侧上限约束（下条）；`agent-release-trial` 隔离外部效果；没有工作空间，因此没有文件，也不注入经验。
- **员工侧上限：** 执行授权为 Agent 自身授权再受上限约束（`authorizeReleaseTrial` → `resolveAudienceCeiling`）：角色只保留可见角色，数据范围只保留授予可见角色或其有效成员的部分；Agent 多出的授权不进入验证。验证前检查“能力所需授权”同时按 Agent 授权与该上限核对，可见角色的员工够不到的能力在开始前即被拦下。平台默认工具也只固定可见角色可及的部分；项目空间按 Agent 全部岗位角色执行（3.3），但执行使用冻结的绑定，因此只由可见角色以外的岗位角色可及的默认工具在项目空间同样不会出现，该项给出不阻断的“验证不会覆盖”提示。升级提示：该上限之前冻结的待发布版本若包含这类默认工具，发布复核会以“可见角色或岗位权限收窄后不再获准的工具”要求重新验证。
- **外部效果隔离：** 平台写工具返回 `trial_only`；需人工审批的调用直接拒绝，不创建审批等待；MCP 调用不执行，页面对使用 MCP 的 Agent 提示，因此依赖 MCP 的 Agent 只能验证非 MCP 部分。
- **经验不进入验证：** 经验按个人、工作空间、全组织范围检索，验证无法代表具体员工所见；经验是非权威参考，内容已在审核环节人工核对。验证只检验 SOUL.md、Skill、工具与权限。
- **放宽不重新验证：** 放宽岗位权限或可见角色不作废验证，由审计和员工侧上限控制风险；收窄则在发布时复核。案例只有示例问题、主动任务与自定义问题，平台层的越权与注入防护由权限交集和工具策略保证。
- **发布：** 在 Agent 与执行身份锁内复核可见角色、执行身份、工具授权（收窄后不再获准的工具拒绝发布）、固定工具绑定（失效需重新验证，绑定变化时冻结为新版本）与 MCP 范围；通过后移动当前版本指针，写 `agent.release.publish` 审计。已停用的 Agent 发布后保持停用。
- **回滚与启停：** 回滚把当前版本指针移到任一曾发布的版本，不需要重新验证；启用/停用是 Agent 级状态，不动版本。三者都写审计；版本历史显示发布时间与发布人。旧的发布记录表已迁入审计事件。
- **草稿自动保存：** 职责与人格、能力两区编辑工作草稿，内容合法时停止输入后自动保存，携带读取时的修订；已被其他操作修改时提示重新载入，不覆盖。已发布或已冻结时第一次保存生成新的草稿版本。离开页面前先保存，内容不合法时确认是否放弃。创建只要求名称、说明与 SOUL.md。
- **经验：** 详情页“经验”分区按 Agent 列出经验申请（待审核、已发布、已拒绝），可查看来源 Run/Attempt 与内容并审核；拒绝必须填写原因。批准只发布不可变经验版本，不修改 SOUL.md、Skill、工具或权限。“正在使用的经验”列出每条经验的当前版本：停用、启用与回滚只移动当前版本指针（`PUT /experience-iterations/agents/:agentId/experiences/:entryId/current`），已发布版本不变，均须填写原因并写审计（`experience.iteration.entry.disable/enable/rollback`），携带读取时的当前版本，过期修改返回 409；停用后不再检索，排队或执行中引用它的 Attempt 在执行前复核时拒绝，回滚只影响之后的运行；来源授权撤回或已过保留期的版本不能设为当前版本。全局“经验迭代”页保留为汇总视图。
