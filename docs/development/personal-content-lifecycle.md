# 个人内容生命周期（B5）

本版执行 `logical-retention-v1`。权威响应为 `/api/workbench/v1/content-policy`，不是模型生成策略。保留期限 `null` 表示尚未批准清理时限，不表示已删除或可以任意清除。

| 操作 | 前台结果 | 数据与权限 |
| --- | --- | --- |
| 移除对话 | 历史和最近入口不再显示；不提供恢复；旧深链明确不可用 | Session 标记 archived；消息、Run/Attempt、文件、成果独立保留 |
| 对话文件与成果 | “我的文件”显示实际来源；原对话移除后不提供失效来源链接 | 仍需当前身份、对象和来源空间授权；可显式复用未移除且成功解析的同空间附件 |
| 移除文件 | 个人资源列表不再显示；停止下载及新任务引用 | 更新 removed_at/removed_by，保留不可变对象、解析、成果版本及历史 Run 引用；不得改写历史 Manifest |
| 账号停用/离职同步 | 登录 Session 撤销；历史、文件、新任务拒绝；在途执行依 A2 撤权检查停止交付 | 保留资源原作者与 Workspace；不自动转交领导或其他管理员；重新启用仍走当前授权 |
| 团队归档 | 现任成员按权限只读，成员被移出后拒绝 | 不等同于个人“移除对话”，不开放归档空间写入 |

本版无物理删除、清理定时器、自动到期销毁或隐式内容移交。企业必须在正式上线前明确保留期限、备份、审计例外和合法保留要求。后续清理是独立变更：先 dry-run 清单、检查历史引用/保留锁、审批，再实施。不要将所有旧 archived 数据自动加入物理清理队列。

删除/移除请求的幂等不豁免当前权限。个人内容的应用可见性不代表存储层对所有运维人员绝对不可见；运维/审计必须使用明确授权，不因平台管理员身份自动开放业务正文。

并发锁顺序：Workspace → Session → Run，与创建 Run 保持一致；仍有排队或运行中任务时先停止任务再移除对话。文件逻辑移除由 A1/A2 的输入复核拦截之后的访问，已经交付的数据不能回收。
