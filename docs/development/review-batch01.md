## 已固定的行为

1. A1：同一个 Workspace 内，本人的跨会话附件复用仍允许；跨 Workspace 隐式引用拒绝。本人上传不替代来源空间的当前权限。下载可以采用归档只读规则；新任务输入必须是活动空间且仍有权访问。
2. A2：个人任务和团队任务在实际执行前检查当前身份、固定能力及输入授权。旧 Manifest 不自动扩大权限，也不因重试换成新版本。团队再附加成员/角色检查。基础设施故障不伪装为撤权。
3. 8a：Skill 试运行进度、激活、Python、最终回答和发布证据按精确 Attempt 隔离；验证依据是测试启动时的固定内容，而非查询进度时重新贴标签。未绑定的历史测试不能冒充新策略证据。
4. 不修改已发布版本，不回写旧 Attempt，不覆盖已应用的 SQL 迁移。不建设其他模型/Agent 执行路线。
5. 本轮不改变导航、个人空间页面或 Skill 全依赖覆盖政策。C11 UI 门禁替换、8b 场景验收以及 C9/C10 是后续独立提交，不能混称已完成。

## 验证入口

`pnpm test:review:unit` 是本轮确定性回归入口；`pnpm test:review:integration` 使用明确配置的 `DSH_WORK_TEST_DATABASE_URL` 和一次性数据库。新用例随对应修复加入服务器脚本；CI 单独执行两类入口。

每项提交包含一个修复前应失败的回归样例，以及相邻功能正向/拒绝测试。源码检查、单测、真实 PostgreSQL 测试、真实 DSH 和目标部署验收分别记录；不得互相替代。

## 最少真实验收

- A1：旧团队附件在撤权后不能下载或进入个人 Run；本人同空间复用、现任团队成员共享文件使用正常。
- A2：个人任务排队期间停用账号/Agent，恢复 Worker 后不得开跑；恢复旧队列同样复核；数据库异常不导致错误放行。
- 8a：首个 Attempt 留有激活/脚本证据而失败，重试缺少这些证据不能通过；同版本修改草稿资源或依赖后不能凭旧试运行发布。

## 兼容与回滚

跨空间收紧是显式行为变化；旧已排队输入也按新授权复核。已有文件/空间/会话标识和已发布 Skill 保持。新迁移只增加证据元数据；回滚二进制不降低 Schema，但旧版本的宽松发布判据不能作为安全回滚路径（需临时关闭发布入口或继续运行修复版）。
