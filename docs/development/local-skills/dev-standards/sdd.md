# 规格驱动文档（SDD）

适用于在仓库 **`docs/SDD/`** 下维护「规格 + 实施计划」双文档、再落代码的团队（如 DSH workbench）。  
**不是**替代 `docs/design/`、`docs/development/` 等既有长文方案；增量功能、可验收交付优先走 SDD。

## 1. 目录结构（固定）

```text
docs/
└── SDD/
    ├── 规格文档/          # 做什么、行为边界、验收口径（产品 / 需求语言）
    │   └── YY-MM-DD 主题.md
    └── 实施计划/          # 怎么做、改哪些文件、测试与步骤（工程语言）
        └── YY-MM-DD 主题.md   # 或与规格同名的「主题 实现计划」标题，见 §2
```

- 根路径始终是 **`docs/SDD`**（`docs` 下的一级目录名 **`SDD`**，全大写）。  
- **规格**与**计划**成对出现；计划文首必须用相对链接指回同主题的规格文档。  
- 不在 `docs/SDD` 外再复制一份「通用开发规范」；工程共性见本 skill 的 [engineering.md](engineering.md)、[vue3.md](vue3.md)。

## 2. 文件命名

| 类型 | 路径 | 命名 |
|------|------|------|
| 规格 | `docs/SDD/规格文档/` | `YY-MM-DD 主题.md`（例：`26-10-20 团队空间输入条.md`） |
| 实施计划 | `docs/SDD/实施计划/` | 与规格**同一日期 + 同一主题**；标题可为 `主题 实现计划` |

日期前缀用于排序与追溯；主题用简短中文，与 PR / 提交 scope 可对齐。

## 3. 规格文档（`规格文档/`）应写什么

建议结构（可按主题增删节，但**行为与边界**必须写清）：

1. **文首元数据**：状态（如「已与需求方确认，待实现」）、确认日期。  
2. **范围**：本期做什么、明确**不做什么**（个人空间、独立路由、第二套执行链等）。  
3. **目标行为**：用户可感知的场景表（现在 vs 改后）。  
4. **交互 / 挂载 / 权限**：只读、归档、角色未知、加载中骨架等边界。  
5. **涉及文件**（可选表）：主要 Vue/TS 路径，便于评审对照。  
6. **验收**：可观察结果、业务语言；不预设尚未存在的 `data-testid`（E2E 阶段再固化）。

规格**不写**逐步命令、**不写**「先红后绿」任务勾选；这些放在实施计划。

## 4. 实施计划（`实施计划/`）应写什么

文首固定块（blockquote）建议包含：

- 面向实现者：任务顺序、TDD（先测后实现）、`- [ ]` 跟踪。  
- **规格链接**：`[主题](../规格文档/YY-MM-DD 主题.md)`。  
- **目标**一句话 + **架构**约束（如不新增接口、不改 DSH）。  
- **新建文件目录**（与 [vue3.md](vue3.md) §3 一致）：  
  - 组件：`apps/<app>/src/components/<feature-kebab>/<feature-kebab>.vue`  
  - 页面：`apps/<app>/src/views/<page-kebab>/index.vue`（同目录子块、私有 TS 均 kebab-case）  
  - **新建单测**：`apps/<app>/src/__test__/…`，路径**镜像**被测文件在 `src/` 下的位置  
- **不改**清单：明确不动的页面、包、接口。

正文建议包含：

| 区块 | 内容 |
|------|------|
| 文件职责表 | 创建/修改路径 + 一句职责 |
| 分步任务 | 每步：测什么、改什么、跑什么 `vitest` 路径 |
| 规格覆盖核对 | 规格章节 ↔ 任务/文件的矩阵 |
| 手工验收（可选） | 浏览器可观察步骤，与 `e2e/TEST-CATALOG.md` 衔接时注明 |

实施计划里的路径写**仓库内绝对逻辑路径**（含 monorepo 的 `apps/workbench-web/...`），避免只写「新建组件」而无目录名。

## 5. 实现时的加载顺序

1. 读 **`docs/SDD/规格文档/<本期>.md`**，确认范围与验收。  
2. 读 **`docs/SDD/实施计划/<本期>.md`**，按任务顺序执行；目录/单测规则以计划 + [vue3.md](vue3.md) 为准。  
3. 再读 **`AGENTS.md`**、架构文档（如 Agent/DSH 统一执行约束）。  
4. 对照**邻近平行文件**（如已有 `team-space-composer/`）保持风格一致。

冲突时：**SDD 本期文档 > 本 skill 通用条 > 个人习惯**。SDD 未写的细节用 skill 补；SDD 明确写的（如「不新增 E2E」）必须遵守。

## 6. 与其它文档的关系

| 文档 | 关系 |
|------|------|
| `docs/design/*.md` | 长期产品/界面基线；SDD 只做增量，不重复全文 |
| `docs/development/*.md` | 架构、端口、测试分层；SDD 引用约束，不复制 |
| `docs/superpowers/specs/` | 其它仓库可能用此路径；**本仓库增量规格以 `docs/SDD` 为准** |
| `docs/项目-业务约定.md` | 路由、错误码、命名；与 SDD 互补 |

## 7. 新建一期 SDD 的检查清单

- [ ] `docs/SDD/规格文档/YY-MM-DD 主题.md` 已写清范围与不做什么  
- [ ] `docs/SDD/实施计划/YY-MM-DD 主题.md` 已链回规格，并列出文件职责 + 测试路径  
- [ ] 新建组件 / 页面符合 kebab 目录（页面含 `index.vue`）；**新建**单测在 `src/__test__/` 镜像路径下  
- [ ] 实现完成后更新规格**状态**（如「已实现」）或在本期计划勾选任务（按团队习惯）
