# main 流程逻辑断点：目标机只读取证提问（2026-10-21）

## 使用方式

把本文件交给目标机上的操作者或智能体。只采集已有状态和已有日志，不发布、不重启、不跑迁移、不修改数据库/对象存储，不重新触发生产 Agent 任务。所有标识、文件名、人员名、消息正文、Cookie、Token、密钥和连接串必须脱敏。

本轮要回答的是：目标机是否已经运行本地审阅基线，以及下列断点在真实数据/代理/存储下是否已有证据。不要把历史 `v2026.10.19-01` 的结果当作当前答案。

## A. 运行基线（必答）

请返回：

1. 当前 `active-release`、`current` 实际指向、`release.json.version`、`release.json.commit`。
2. 当前进程命令行所指向的 Release 路径；确认不是只看源码 checkout。
3. 数据库已应用迁移的最大文件名，并明确回答 `0082_business_directory_all_providers.sql`、`0083_file_extraction_attachments.sql` 是否存在于运行 Release、是否已应用。
4. `server/config/dsh/runtime-lock.json` 的 DSH version/commit/profile，以及 `DSH_RUNTIME_COMPATIBILITY` 是 SET、EMPTY 还是 MISSING。
5. `/health/live`、`/health/ready`、`/health` 的状态和采集时间；只返回状态字段，不返回内部地址或敏感配置。

期望对照基线：

```text
main commit: 8277d76b0f470585421fb328ab45a6e53e26c2f0
releaseVersion: 2026.10.20-05
latest migrations in source: 0082, 0083
```

若任一项不同，先记录为“版本不一致”，不要继续把行为差异归因于代码缺陷。

## B. 团队文件上传限制与失败形态

请从最近 7 天已有日志中，按下列维度汇总团队文件上传请求，不输出文件名或正文：

- 首次上传 / 上传新版本；
- 调用者角色：owner / admin / member / viewer / unknown；
- 扩展名分组；
- 大小区间：0 B、1 B–1 MB、1–20 MB、超过 20 MB；
- HTTP 状态、产品错误码、时间、脱敏 requestId；
- 是应用返回 4xx/5xx，还是 Nginx/代理在到达应用前拒绝；
- 若是 413，返回实际 `client_max_body_size` 和任何上游 body limit；
- 若是解析失败，返回 `parse_status` 和错误分类，不返回正文。

请明确回答：

1. viewer 是否在页面上看到首次上传按钮？点击后实际响应是什么？只做已有截图/日志分析；不要为了验证新建文件。
2. 成功上传后是否必须刷新才出现“引用到对话”？如有现成浏览器录屏/截图，请给出时间和版本。
3. 解析失败后，Files 列表里是否出现 failed 文件？用户重试是否产生两个逻辑文件？
4. 最近 7 天是否存在相同用户、同一空间、短时间内多次同大小/同类型上传失败的模式？只返回计数和脱敏哈希。

5. 需要全局收件箱、团队空间卡片未读 badge，还是只要求空间内提醒？

5. 身份角色/数据范围在会话存续期间变化后，前端是否需要完整刷新才能更新入口；只返回行为结论，不返回人员或权限明细。
