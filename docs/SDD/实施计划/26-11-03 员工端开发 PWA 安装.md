# 员工端开发 PWA 安装 实现计划

> 面向实现者：按任务顺序执行，先写失败测试再实现；步骤用 `- [ ]` 跟踪。  
> 规格：[26-11-03 员工端开发 PWA 安装](../规格文档/26-11-03 员工端开发 PWA 安装.md)。  
> 目标：现有员工端开发命令启动后，Chrome 地址栏出现 PWA 安装入口；同时修复生产 `dist` 缺少 `push-sw.js` 的缺陷。  
> 架构：保留共享品牌资源作为 Vite `publicDir`；新增共享插件把员工端 `public` 文件在开发时服务、构建时复制。只给员工端打开 `vite-plugin-pwa` 的开发 Service Worker。  
> 新建单测：`apps/workbench-web/src/__test__/vite-extra-public.test.ts`、`vite-pwa-options.test.ts`、`register-app-pwa.test.ts`。  
> 不改：管理端默认开发行为、生产 manifest 字段、Web Push 协议、`/api` 与 `/auth` 代理链路。

## Global Constraints

- 不新增第三方依赖。
- 生产 PWA 保持 `registerType: 'autoUpdate'`、现有 manifest 字段、图标与 Workbox 生产配置语义。
- 开发导航回退只允许 `/` 与 `/workbench/`。
- 管理端默认不注册开发 Service Worker，也不暴露 `push-sw.js`。
- 当前工作区已有无关未提交改动；本次执行不执行 `git commit` / `git push`。
- 验证只使用 `package.json` 已存在的脚本。

## Review Focus

- 路径穿越：请求 `/../secret.js` 或编码后的 `%2e%2e` 不能读出 `publicDir` 之外的文件。
- MIME 类型：`push-sw.js` 必须是 `text/javascript`，否则 Service Worker 的 `importScripts` 会失败。
- 覆盖顺序：员工端 `public` 文件与品牌资源同名时，员工端文件应优先。
- 构建顺序：`vite build` 在 Vite 复制品牌资源后，还必须把 `push-sw.js` 写入 `dist`。
- 开发回退范围：`/workbench` 可离线回退，`/conversations/1`、`/api/*`、`/auth/*` 不应被导航回退吞掉。

`apps/workbench-web/src/__test__/vite-extra-public.test.ts`：

```ts
import { mkdtemp, mkdir, readFile, rm, writeFile } from 'node:fs/promises'
import { tmpdir } from 'node:os'
import { join } from 'node:path'

import { afterEach, describe, expect, it } from 'vitest'

import {
  copyExtraPublicDir,
  extraPublicContentType,
  resolveExtraPublicFile,
} from '../../../shared/vite-extra-public'

let rootDir = ''

async function createFixture() {
  rootDir = await mkdtemp(join(tmpdir(), 'dsh-extra-public-'))
  const publicDir = join(rootDir, 'public')
  const outDir = join(rootDir, 'dist')
  await mkdir(join(publicDir, 'nested'), { recursive: true })
  await writeFile(join(publicDir, 'push-sw.js'), 'self.addEventListener("push", () => {})\n')
  await writeFile(join(publicDir, 'nested', 'icon.png'), 'png')
  return { publicDir, outDir }
}

afterEach(async () => {
  await rm(rootDir, { recursive: true, force: true })
})

describe('vite extra public', () => {
  it('resolves existing files and rejects paths outside the public directory', async () => {
    const { publicDir } = await createFixture()

    expect(resolveExtraPublicFile(publicDir, '/push-sw.js')).toBe(join(publicDir, 'push-sw.js'))
    expect(resolveExtraPublicFile(publicDir, '/nested/icon.png')).toBe(join(publicDir, 'nested', 'icon.png'))
    expect(resolveExtraPublicFile(publicDir, '/missing.js')).toBeUndefined()
    expect(resolveExtraPublicFile(publicDir, '/../package.json')).toBeUndefined()
    expect(resolveExtraPublicFile(publicDir, '/%2e%2e/package.json')).toBeUndefined()
  })

  it('maps service worker and icon files to usable MIME types', () => {
    expect(extraPublicContentType('push-sw.js')).toBe('text/javascript')
    expect(extraPublicContentType('icon.png')).toBe('image/png')
    expect(extraPublicContentType('icon.svg')).toBe('image/svg+xml')
    expect(extraPublicContentType('icon.unknown')).toBeUndefined()
  })

  it('copies all files recursively to the build output', async () => {
    const { publicDir, outDir } = await createFixture()

    copyExtraPublicDir(publicDir, outDir)

    await expect(readFile(join(outDir, 'push-sw.js'), 'utf-8')).resolves.toContain('self.addEventListener')
    await expect(readFile(join(outDir, 'nested', 'icon.png'), 'utf-8')).resolves.toBe('png')
  })
})
```

- [ ] **Step 3: 在 `apps/shared/vite-extra-public.ts` 实现接口**

实现要求：

- `resolveExtraPublicFile` 解码 URL path，去掉开头 `/`，用 `node:path` 解析后确认结果仍在 `publicDir` 内且是普通文件；越界、目录、缺失都返回 `undefined`。
- MIME 映射至少包括 `.js`/`text/javascript`、`.json`/`application/json`、`.webmanifest`/`application/manifest+json`、`.png`/`image/png`、`.svg`/`image/svg+xml`、`.ico`/`image/x-icon`、`.webp`/`image/webp`、`.woff`/`font/woff`、`.woff2`/`font/woff2`、`.html`/`text/html`。
- `copyExtraPublicDir` 使用 Node `cpSync(..., { recursive: true, force: true })`。
- `extraPublicDir` 返回 Vite 插件：开发模式在 `configureServer` 中先匹配额外目录文件并设置 `Cache-Control: no-cache`、正确 MIME、文件大小后流式返回；构建模式在 `writeBundle` 中调用复制函数。HEAD 请求只返回响应头。

import { describe, expect, it } from 'vitest'

import { createDshWorkPwaOptions } from '../../../shared/vite-pwa-options'

const manifest = {
  name: 'dsh-work 员工 AI 工作台',
  short_name: 'dsh-work',
  description: 'dsh-work 员工 AI 工作台',
  start_url: '/workbench',
  id: '/workbench',
}

describe('dsh work pwa options', () => {
  it('keeps dev PWA disabled by default', () => {
    const options = createDshWorkPwaOptions(manifest)

    expect(options.devOptions?.enabled).toBe(false)
  })

  it('enables the classic dev service worker with a narrow navigation allowlist', () => {
    const options = createDshWorkPwaOptions(manifest, { enableDevPwa: true })

    expect(allowlist.some((pattern) => pattern.test('/conversations/1'))).toBe(false)
    expect(options.workbox.importScripts).toEqual(['push-sw.js'])

})
