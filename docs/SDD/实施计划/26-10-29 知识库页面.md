# 知识库页面 实现计划

> **面向实现者：** 按任务顺序做。每个任务先写失败测试，再写让该测试通过的最少代码。用 `- [ ]` 跟踪。完成一个任务并看到测试通过后再进入下一个。不要自行 git commit，除非执行者被明确要求提交。
>
> **规格：** [26-10-29 知识库页面](../规格文档/26-10-29%20知识库页面.md)
>
> **目标：** 员工在现有壳层内只读查阅 WeKnora 知识库；浏览器只持有 dsh-work 会话。
>
> **架构：** WeKnora 调用只发生在 `server`。前端走现有 `/api/workbench/v1` 客户端。不新增 Agent 执行链路，不改 PostgreSQL 企业知识模块的检索与引用。换票与绑定的对方契约以实现时的 WeKnora 规格为准，不在 dsh-work 里重做一套登录。
>
> **技术栈：** 员工端 Vue 3 + Vite + Element Plus；服务端 Node.js、`node:test`。接口信封与 `docs/development/openapi-workbench.json` 一致：成功 `{ data, meta }`，失败 `{ error }`。
>
> **新建文件目录：**
>
> - 页面：`apps/workbench-web/src/views/<page-kebab>/index.vue`，同目录其它文件 kebab-case。SFC 块顺序为 `template`、`script setup`、`style`。
> - 新建组件：`apps/workbench-web/src/components/<feature-kebab>/<feature-kebab>.vue`。
> - 新建前端单测：`apps/workbench-web/src/__test__/…`，子路径镜像 `src/`。不在 `views/` 或 `components/` 旁新建 `*.test.ts`。已有旁路测试只改断言，不搬迁。
> - 服务端单测放在被测文件旁的 `*.test.ts`，与现有 `server/src` 一致。
>
> **不改：**
>
> - `server/src/modules/knowledge/`（平台企业知识）及其 Run 引用
> - 管理端页面与 `/api/admin/v1`
> - DSH、Runtime Adapter、MCP 连接器装配
> - B 模式主导航的四个入口
> - 用 iframe 或外链打开 WeKnora 作为查阅方式

## 任务 1：配置与换票客户端

- 两个环境变量都为空：`configured` 为 false。
- 只有基址或只有密钥：false。
- 都有值：基址去掉尾部斜杠。

`server/src/modules/weknora/client.test.ts`  
用本机临时 HTTP 服务，不连接真实 WeKnora。

- 换票请求带集成密钥，正文含 `subject` 或 `ai_hub_user_id`，不含密码。

运行：

```bash

```

`config.ts`、`client.ts`。WeKnora 路径与 JSON 字段名以实现当日的 WeKnora 规格为准；映射到规格 §7 的 camelCase。日志不打印令牌和密钥。

## 任务 2：绑定表与访问决策

- [ ] **步骤 1：写失败测试**

`server/src/modules/weknora/access.test.ts`，用假的 client 与 link store。

- 未配置：不调用换票。
- 目录换票成功：`source` 为 `directory`，不要求事先有绑定行。
- 目录未开通且无绑定行：待绑定。
- 无目录身份、有绑定行：用 `weknora_user_id` 换票，`source` 为 `bind`。
- 目录换票得到的用户与绑定行不同：以目录用户为准，并覆盖绑定行。
- 令牌缓存未过期时不重复换票；对方 401 后丢弃缓存并再换一次。

运行：

```bash
pnpm --filter @dsh-work/server exec node --experimental-strip-types --test src/modules/weknora/access.test.ts
```

- [ ] **步骤 2：实现**

迁移 `0110_user_weknora_links.sql`、`link-store.ts`、`session-cache.ts`、`access.ts`。迁移只建表，不回填。

## 任务 3：HTTP 路由

- [ ] **步骤 1：写失败测试**

`server/src/http/workbench/weknora-routes.test.ts`，沿用工作台路由测试里已有的会话夹具方式；WeKnora 用任务 1 的假客户端。

- 无会话：401。
- `GET .../status` 在未配置、待绑定、目录已连接三种情况下的 `data` 与规格 §7 一致。目录未开通时 `directoryAccount` 为 `missing`。未配置时不调用 WeKnora，`directoryAccount` 为 `none`。JSON 里没有 `accessToken`、`token`、`secret`。
- 待绑定时 `POST .../bind/start` 返回 `data.url`；目录已连接时 409。
- 回调 `state` 错误：302 到 `/knowledge?bind=failed`，绑定表无新行。
- 回调成功：写入绑定并 302 到 `/knowledge`。
- 未连接时 `GET .../knowledge-bases` 为 409，`error.code` 为 `weknora_not_linked`。
- 未配置时该列表为 503，`error.code` 为 `weknora_not_configured`。
- 已连接时列表 `data.list` 为数组；检索空 `query` 为 400。
- `DELETE .../link` 后绑定行消失；若目录仍可换票，随后 `status.linked` 仍为 true。

运行：

```bash
pnpm --filter @dsh-work/server exec node --experimental-strip-types --test src/http/workbench/weknora-routes.test.ts
```

- [ ] **步骤 2：实现**

`weknora-routes.ts` 并在 `main.ts` 挂到工作台前缀。补 OpenAPI。`.env.example` 增加两个变量说明。

错误对象沿用现有工作台错误构造，补全 `object`、`suggestion`、`traceId`。
