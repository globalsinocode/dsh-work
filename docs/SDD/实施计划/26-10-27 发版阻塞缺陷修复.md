# 发版阻塞缺陷修复实施计划

> **面向 Agent 实现者：** 必须使用 `executing-plans` 逐任务执行（若用户明确要求子 Agent，才可使用 `subagent-driven-development`），用 `test-driven-development` 保持先红后绿，完成前使用 `verification-before-completion` 核验证据。所有进度使用 `- [ ]` 跟踪。
>
> **规格：** [发版阻塞缺陷修复规格](../规格文档/26-10-27 发版阻塞缺陷修复.md)

**目标：** 在执行时最新的 `dev` 上恢复合并遗漏的首轮前置修复，关闭 Agent 新建、团队 Run 终态、项目任务对话和三组管理端/自动化浏览器阻塞，使 release `2026.10.26-01` 重新具备进入发布验证的条件。

**架构：** 现有 Run/Attempt、Runtime Adapter 与 DSH 是唯一 Agent 执行链路。HTTP 解析只做形状校验，领域服务统一产生权限缺省；工作空间事件用真实请求人满足用户外键，用安全元数据表达系统/Agent；浏览器夹具复用生产服务组合，不在产品代码中增加测试旁路；任务对话以当前 `ConversationView` 为主干逐块恢复。

**技术栈：** TypeScript、Node.js test runner、PostgreSQL、Vue 3、Pinia、Element Plus、Playwright、pnpm。

- 只在 `dev` 开发。第一次实现提交前按仓库规则对齐 `origin/dev`，但不覆盖工作区已有未跟踪文档。
