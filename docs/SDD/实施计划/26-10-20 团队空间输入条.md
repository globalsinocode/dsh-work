# 团队空间输入条 实现计划

> **面向实现者：** 按任务顺序做。每步先写测试并看到失败，再写最少实现。步骤使用 `- [ ]` 跟踪。提交只在用户明确要求时执行；未要求时停在工作区改动。
>
> **规格：** [26-10-20 团队空间输入条](../规格文档/26-10-20 团队空间输入条.md)

**目标：** 团队空间里，历史列表和点进会话后共用同一条底栏输入；「新对话」仍在页面中部，但是同一个输入组件的另一个实例。切换历史与会话时底栏不卸载，草稿按上下文分开，Tab 使用空间页已经加载的 Agent 列表。

**架构：** 不新增接口，不改 DSH。`TaskComposer` 继续负责输入、附件、`@` / Tab 和发送按钮，只增加读写草稿的方法。新组件 `team-space-composer.vue` 包住它，不发请求、不调用建会话或续写。底栏挂在 `WorkspaceDetailView`，放在历史列表与内嵌会话切换之外。发送仍调用现在的发起、讨论和续写函数，由空间页按当前上下文选择。

**新建文件的目录：** 每个新组件单独一个目录，目录名与文件名都用 kebab-case。本功能的组件目录是 `apps/workbench-web/src/components/team-space-composer/`，组件文件是 `team-space-composer.vue`。该组件专用的桥放在同一目录，不要在 `components` 根下再放散文件。**新建单测**一律放在 `apps/workbench-web/src/__test__/`，子路径镜像被测文件在 `src/` 下的位置（本功能组件测为 `src/__test__/components/team-space-composer/`）；不要在 `components/`、`views/` 等生产目录旁新建 `*.test.ts`。已有旁路测试（如 `src/views/WorkspaceDetailView.test.ts`）仍留在原处，只做修改。Vitest 的 `include` 已是 `src/**/*.test.ts`，`__test__` 下的测试会被跑到，不必改配置。

**技术栈：** Vue 3 `<script setup lang="ts">`、现有 `TaskComposer`、Vitest + `@vue/test-utils`。不新增 npm 依赖。不新增 E2E；单测覆盖挂载、草稿和「嵌在空间内不再自带输入条」。

**不改：** 个人空间、工作台首页、独立 `/conversations/:id` 的输入、服务端、DSH、会话与 Run 的接口语义。

### 任务 1：输入框能按上下文换草稿

**文件：**
- 修改：`packages/workbench-components/src/TaskComposer.vue`
- 创建：`apps/workbench-web/src/components/team-space-composer/team-space-composer.vue`
- 测试：`apps/workbench-web/src/__test__/components/team-space-composer/team-space-composer.test.ts`

`TaskComposer` 用 `defineExpose` 提供：

```ts
export interface ComposerDraft {
  prompt: string
  files: File[]
  mentions: Array<{ id: string; name: string; start: number }>
}

getDraft(): ComposerDraft
setDraft(draft: ComposerDraft): void
```

`setDraft` 覆盖文字、文件和已选提及，并关掉正在打开的 `@` 浮层。不重置工作空间 id。

`team-space-composer.vue` 的属性：

| 属性 | 含义 |
| --- | --- |
| `placement` | `'stage'` 或 `'dock'`。`dock` 把 `compact` 传给 `TaskComposer`。 |
| `contextKey` | 当前草稿键。 |
| `mentionOptions` | 空间页传入的可 @ 成员，可为空数组。 |
| `workspaceId` / `workspaceName` | 传给 `TaskComposer`，空间锁定。 |
| `running` / `stopping` | 仅底栏在看某次执行时为真。 |
| `blockedReason` | 沿用现有拦截文案；不能写时父级不挂组件，这里只保留「引用文件检查中」这类暂时原因。 |

事件：`submit` 负载在现有字段上增加 `contextKey`；`stop`；`draft-change` 在 `contextKey` 将要变化前抛出旧键和 `ComposerDraft`。父级保存后，组件对新键调用 `setDraft`（没有则空草稿）。

3. 提交事件的 `contextKey` 等于当前键。调用负载里的 `confirm` 后当前草稿被清空，另一键的草稿还在。

### 任务 2：底栏挂到空间页，对话页在空间内不再自带输入

**文件：**
- 创建：`apps/workbench-web/src/components/team-space-composer/team-composer-bridge.ts`
- 修改：`WorkspaceDetailView.vue`、`ConversationStarter.vue`、`ConversationView.vue`
- 测试：`WorkspaceDetailView.test.ts`、`ConversationView.test.ts`

桥的形状：

```ts
export interface TeamComposerBridge {
  sessionId: string
  running: boolean
  stopping: boolean
  stop: (() => void) | null
  submitSession: ((payload: ComposerSubmit) => void) | null
  submitFollowUp: ((payload: ComposerSubmit) => void) | null
}
```

空间页 `provide` 这份桥。内嵌 `ConversationView` 在目标加载后写入 `sessionId`、`running`、`stopping` 和三个函数，卸载或离开该会话时清空。函数体就是现在的 `stopCurrentRun`、`submitSessionMessage`、`submitFollowUp`，不要复制一套请求。

空间页收到底栏 `submit` 后：

| `contextKey` | 调用 |
| --- | --- |
| `history` | `ConversationStarter` 现有的发起函数（抽成可供父级调用的方法，或把 `submitTask` 逻辑挪到空间页能调用的函数，仍走 `createSession` / `createTask`） |
| `session:*` 且当前没有 Run 详情 | `bridge.submitSession` |
| `session:*` 且当前正在看 Run | `bridge.submitFollowUp` |

`stop` 调用 `bridge.stop`。

模板结构：底栏放在 `workspace-conversation-pane__body` **外面**，这样 `RouterView` 与历史列表的 `v-if` 不会拆掉它。历史布局里删除 `composer-only` 的 `ConversationStarter`。团队「新对话」里的 `TaskComposer` 换成 `placement="stage"` 的 `team-space-composer.vue`，`contextKey` 固定为 `stage`。

嵌在空间内时，`ConversationView` 两处 `TaskComposer`（会话模式与 Run 续写）都不渲染。只读说明和归档说明留在对话页。独立对话页的 `v-if` 条件加上「不是空间内嵌」。

删除仅为底栏提前拉成员而存在的重复逻辑：空间内嵌时，`ConversationView` 不再为输入条调用 `loadAgentMembers`。`workspace-agent-context.ts` 若没有别的读者，一并删除。空间页已有的 `loadAgentMembers` 仍是唯一来源，列表通过属性传入中部与底栏两个 `team-space-composer` 实例。
