# 同事私聊 实现计划

> 面向实现者。规格确认前不要开工。确认后按任务顺序做，每步先写测试再写实现。
>
> 规格：[26-11-03 人与人聊天](../规格文档/26-11-03 人与人聊天.md)
>
> 目标：工作台后端提供两人纯文本私聊。调用方是移动端 `dsh-work-mobile`。消息单独存储，不进入空间会话，也不创建 Run。
>
> 架构：继续用现有工作台身份与 `{ data, meta }` 信封。禁止把私聊写成 `sessions` / `messages`，禁止在发送时调用 Runtime Adapter 或 DSH，禁止新增第二套 Agent 循环。禁止改 `apps/workbench-web`。禁止把 `peer` 放进 `GET /me/conversation-targets`。
>
> 后端测试与被测模块同目录，沿用 `node --experimental-strip-types --test`。集成测试使用可丢弃库，不连接业务库 `dsh_work`。
>
> 不改：`apps/workbench-web`、`apps/admin-web`、`GET /member-candidates`、`GET /me/conversation-targets` 的返回种类、`POST /me/conversation-targets/:type/:id/read` 的 `agent | group` 校验、个人空间会话、项目空间共享讨论与 @、任务对话、Agent 执行链路。移动端页面、路由和通讯录点击不在本仓库。

## 任务

### 1. 迁移与领域类型

测什么：配对键把两个用户 id 按字符串升序放入 `user_low` / `user_high`；相同 id 拒绝；内容去空白后为空或超过 20000 拒绝。

改什么：`direct-conversations.ts` 与迁移 `0117`。表结构以规格 §6 为准。`conversation_read_states` 的 check 改为 `target_type in ('agent', 'group', 'peer')`。索引：`direct_messages (tenant_id, conversation_id, created_at, id)`，`direct_conversations (tenant_id, last_message_at)`。

```bash
pnpm --filter @dsh-work/server exec node --experimental-strip-types --test src/modules/workbench/application/direct-conversations.test.ts
```

### 2. 写入、读取、隐藏与已读

测什么：

- 两人并发各自 `POST .../messages` 只产生一条 `direct_conversations`，两条消息都在其中。
- 第三人读取消息为 404，响应体不含正文。
- 对方停用后 `canSend` 为 false，再次发送为 400，已有消息仍可读。
- 隐藏后 `GET /me/direct-conversations` 不含该行；对方新消息后 `hidden_at` 清空且历史仍在。
- 未读不计本人消息，封顶 100；已读只进不退；对从未聊过的用户标记已读返回 404。
- 发送前后 `sessions`、`messages`、`runs` 计数不变。
- `GET /me/conversation-targets` 在已有私聊时仍只返回 `agent` 与 `group`。

改什么：`postgres-direct-conversation-service.ts`、`direct-conversation-routes.ts`，在工作台路由注册处挂上。创建会话用插入冲突后重读，保证唯一约束。

```bash
pnpm --filter @dsh-work/server exec node --experimental-strip-types --test src/http/direct-conversations-api.integration.test.ts
```

### 3. 通知

测什么：乙收到甲的私聊时产生一条 `collab_unread`，`tag` 为 `collab:peer:{甲的用户 id}`，`url` 为 `/c/chats/peer/{甲的用户 id}`，`targetType` 为 `peer`，`targetId` 为甲的用户 id，`sessionId` 为私聊 id。甲自己不收到。正文不超过 120 字。

改什么：`web-push-dispatch.ts` 与文案。没有推送订阅时不报错。不按端过滤订阅。

```bash
pnpm --filter @dsh-work/server exec node --experimental-strip-types --test src/http/web-push-api.integration.test.ts
```

### 4. 文档

规格覆盖的行为写进功能规则 §2.2c、数据模型、项目空间方案 D23。D23 改写后保留「群组必须有 Agent」和「群组即项目空间」，并写明 PC 员工端不增加私聊入口。

本仓库不新增 Playwright，也不改 `e2e/catalog/`。移动端旅程由 `dsh-work-mobile` 在接这些接口时登记。
