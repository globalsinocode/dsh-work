# 发版阻塞缺陷修复规格

## 1. 背景与基线

`release-2026.10.26-01-dev-merge-defects.md` 记录了合并后 5 个仍阻塞项，并声称另有 5 个首轮修复已经落在本地 `d8e12f0`。本规格以当前可见仓库为准重新核对：当前 `dev` 为 `1768573`，仓库中不存在 `d8e12f0`，且首轮修复对应的会话激活、`0106` 迁移、个人工作台浏览器组合根、Agent 可见角色授权和工具服务组合仍未落地。

因此，本轮不是只处理参考文档“第二部分”的 5 项，而是先恢复当前 `dev` 缺失的首轮前置修复，再关闭经代码核对确认的 5 个发版阻塞项。所有实现和验收以执行时最新的 `dev` 快进后继为准；若基线继续变化，先重跑窄失败，不按旧行号机械修改。

## 2. 目标

1. 新建 Agent 的最小表单请求可创建草稿，未提交的访问字段继续由现有领域归一化产生安全缺省值。
2. 团队空间 Run 完成或失败后，动态和通知可以可靠持久化，既满足用户外键约束，又能展示为系统或 Agent 事件。
3. 项目任务对话恢复“交给 Agent / 仅评论”、执行规则、定时执行折叠、完成任务和返回任务等完整交互，同时保留当前会话页的附件、成果预览、断点重试和幂等保护。
4. 自动化、Agent 日常任务、MCP 管理和 Agent 能力浏览器套件与当前产品契约一致；只修已确认的夹具或验收漂移，不用产品旁路迁就测试。
5. 恢复当前分支缺失的首轮修复，使个人工作台、项目空间和管理端浏览器组合根具备完整依赖，数据库约束包含两条合并线的合法事件值。
6. 形成分层、可复核的 P0/P1/P2 证据，在证据不足时明确标记，不用 Mock 或 P0 冒烟宣称真实 DSH/OIDC 链路已通过。

## 3. 非目标

- 不改变 DSH 作为唯一 Agent 执行引擎的架构，不新增模型直连、第二套 Agent Loop 或生产降级执行器。
- 不在本轮扩展 Agent 新建弹窗以配置角色和数据范围；这些字段仍在后续“角色与权限”步骤维护。
- 不创建可登录的 `system` 用户，不删除或放宽 `workspace_activity_events.actor_user_id` 的用户外键。
- 不改变 PF-MCP-01 首次以缺少凭据得到 `MCP_AUTHENTICATION_REQUIRED` 的预期流程。
- 不通过降低断言、固定延时、静默重试、共享可变状态或扩大超时来制造绿灯。
- 不修改 `releaseVersion`，不推送，不快进 `main`，不打 tag，不创建 Release；发布动作另行授权。

## 4. 已确认的产品与技术决策

### 4.1 Agent 草稿访问字段

`visibility`、`roleIds`、`dataScopes` 在领域输入中是可选字段，`normalizeConfiguration` 已定义安全缺省：可见范围为“指定角色”，角色和数据范围为空。HTTP 解析层必须允许字段缺失，但字段一旦出现仍须严格校验类型；`null`、对象和混合数组不得被当成“未提交”。前端新建弹窗保持最小表单，不重复实现领域缺省。

### 4.2 Run 终态事件身份

推荐并计划采用以下口径，但实现前仍保留一次产品确认门：

- `actor_user_id` 写真实 `requestedBy`，满足外键并保留可审计的触发人。
- `safe_metadata.actor = 'system'` 表达事件由系统生成；可选的 `agentDisplayName` 表达由哪个 Agent 完成。
- 读侧对 Run 完成/失败事件优先展示非空 `agentDisplayName`，否则展示“系统”；不把请求人的姓名误呈现成执行者。
- 收件人仍只有请求人，沿用现有去重键；不会因为演员字段改为请求人而扩大通知范围。

若产品不接受此口径，停止该项实现并记录决策，不自行切换到虚拟用户或放宽外键方案。

### 4.3 任务对话恢复方式

历史提交 `4b4073a` 仅作为行为和局部代码参照。不得整文件 checkout、覆盖或直接接受 3-way 合并结果。实现应以当前 `ConversationView.vue` 为主干，按测试驱动逐块恢复任务状态、发送模式、时间线与操作区，并逐项保留当前加固线能力。

### 4.4 自动化与其余单例红灯

- AU-01 的真实问题是测试仍按“自动任务：”查找区域，而当前产品可访问名称为“定时任务：”；现有账号恢复和串行配置已经存在，不再加入重复修复。
- AE-05 的管理端夹具缺少 `GET /api/admin/v1/identity/users`，应补只读测试路由及生产一致的分页响应。
- PF-MCP-01 的首次 422 是认证前置步骤的预期证据，不修改产品认证流程。
- Agent 能力 P1 仍按旧的多步创建弹窗操作，而当前流程是“创建并继续配置”后进入草稿页；更新旅程以覆盖当前四步草稿编辑和持久化定义。

## 5. 功能需求

### FR-01 草稿会话首写激活

- 新建会话处于 `draft` 时，首次发送讨论消息或首次启动 Run 应在写权限校验成功后、读取附件或写入消息/Run 前激活会话。
- 激活必须幂等；相同幂等键重试不得产生重复 Run 或跳过既有授权。
- 读取、无权写入和已归档会话不得被激活。

### FR-02 工作空间事件约束恢复

- 新迁移必须把 `0093` 项目空间值与 `0087` 讨论/Run 值做并集，而不是覆盖任何一方。
- `kind` 至少同时允许 `discussion_posted`、`member_mentioned`、`run_completed`、`run_failed` 及当前项目空间事件。
- `object_type` 至少同时允许 `session`、`run` 及当前项目空间对象。
- 升级测试必须从历史迁移状态执行到最新版本，并验证两组值都可写入。

### FR-03 浏览器组合根完整

- 个人工作台 P1 夹具在浏览器模式下提供偏好、会话目标、通知计数、项目、项目档案、成员、生命周期、用量、时间线和任务所需端口。
- 夹具复用生产服务和路由注册，不在前端增加测试专用回退。
- 项目空间浏览器夹具发布 Agent 后通过 `PostgresAgentAccessService` 显式授予 `role-employee` 可见角色。
- 两个管理端浏览器夹具使用 `PostgresToolConnectorService` 注册工具路由，构造方式与生产组合根一致。

### FR-04 Agent 草稿解析兼容

- 创建和更新请求均允许省略 `visibility`、`roleIds`、`dataScopes`。
- 省略后由服务层统一归一化；HTTP 层不得复制另一套缺省常量。
- 显式传入合法值时保持原值；显式传入非法类型时返回 422，错误响应不得回显敏感请求内容。

### FR-05 Run 终态动态与通知

- 成功与失败终态都能写入工作空间事件，写入失败不得再因不存在的 `system` 外键发生。
- 数据库存储真实请求人、系统语义和 Agent 展示名；读侧展示符合 4.2。
- 同一 Run 的同一终态使用稳定去重键，重复交付不产生重复动态或通知。
- 收件人为请求人，不向空间全员扩散。

### FR-06 项目任务对话

- Agent 任务默认“交给 Agent”；员工任务仅允许评论。
- 活跃 Run 期间不可再次交给 Agent，但仍可按既有规则评论。
- 已完成任务仅允许评论，并允许有权限用户从会话页完成或返回任务。
- 首次交给 Agent 通过 `ProjectTaskPanel` 提供的任务桥启动；后续执行复用当前 Run/Attempt、附件和幂等链路。
- 定时执行显示规则标签、原因标签和执行气泡；连续无变化结果按既有规则折叠。
- 评论和 Agent 执行在消息时间线中有可感知区分，顺序与触发消息一致。
- 工作模式与协作模式的任务路由均保持可用。

### FR-07 测试旅程对齐

- AU-01 使用现有 `taskCard` 或“定时任务：”可访问名称定位，不改产品文案。
- AE-05 能加载活动用户并配置接收人。
- PF-MCP-01 先验证缺凭据失败，再设置 Bearer 凭据并验证能力变更确认；不跳过第一步。
- Agent 能力 P1 从当前新建弹窗进入草稿页，在“职责与人格”写入说明，在“能力”选择 MCP，等待“已保存”，再从版本定义验证持久化；重复创建冲突、包和 Runtime 证据继续保留。

## 6. Agent 生命周期与安全影响

| 生命周期环节 | 本轮影响 | 约束 |
| --- | --- | --- |
| 定义 | 只调整草稿 HTTP 可选字段和现有编辑旅程 | 缺省由领域服务单点归一化 |
| 能力依赖 | 修复测试组合根和 MCP 能力旅程 | 不增加新工具、不绕过工具准入 |
| 发布 | 恢复 Agent 发布链路的可达性 | 发布门、试运行证据、版本封存保持不变 |
| 执行 | 首次会话激活；任务对话仍走 Run/Attempt/DSH | 禁止第二套 Agent Loop |
| 持久化等待 | 无新增 | 不扩大触发条件 |
| 记忆/委派 | 无新增 | 不改变现有授权和范围 |
| 通知 | 修复终态演员存储和展示 | 收件人不扩大，元数据只放安全字段 |
| 审计 | 保留真实请求人，可区分系统生成事件 | 不创建虚拟可登录身份，不丢触发人 |

## 7. 验收标准

### AC-01 基线前置修复

- 当前 `dev` 上首条讨论和首个 Run 可以激活草稿会话。
- 最新迁移包含合并线两侧所有事件值。
- 个人工作台、项目空间和管理端浏览器夹具不再因缺路由、缺组合根或错误工具服务启动失败。

### AC-02 Agent 新建与权限缺省

- 管理端当前最小创建请求返回 201，并进入草稿编辑页。
- 新建 Agent 的可见角色、执行角色和数据范围为空，不因兼容而扩大权限。
- 显式错误类型仍返回 422。

### AC-03 团队 Run 终态

- 成功与失败各有数据库级覆盖：事件写入、真实请求人、系统元数据、展示名、收件人和去重均符合要求。
- 项目空间浏览器旅程能观察到终态气泡/动态，不再出现 `system` 外键错误。

### AC-04 任务对话

- `ConversationView` 单测覆盖 Agent/员工/运行中/已完成/定时执行/首次启动六类状态。
- PS-E2E-07、PS-E2E-08 及协作模式对应旅程在 P1 环境通过。
- 当前附件、成果预览、导出、重试和输入快捷键测试保持通过。

### AC-05 其余浏览器门禁

- `automation`、`agent-principal`、`agent-routines`、`agent-capabilities`、`mcp-admin` 配置分别通过。
- PF-MCP 首次认证失败仍被明确断言；不得把它隐藏成成功。

### AC-06 分层绿灯

- 类型检查、静态校验和相关单元测试通过。
- 相关 PostgreSQL 集成测试在专用可丢弃数据库通过。
- 点名 P1 浏览器套件通过；发布前再运行完整浏览器套件。
- P2 真实 DSH/OIDC 若未执行，在验证日志中标为未覆盖，不得写“真实链路已验证”。
