# 26-10-20 团队空间输入条

**状态：** 已与需求方确认，待实现。
**确认日期：** 2026-10-20

本文只统一团队空间里输入条的外观、挂载和草稿。不新增对话接口，不新增第二套 Agent 执行链路。个人空间、工作台首页、独立对话页不在本期。

## 1. 要达成的效果

员工在团队空间里切换「历史对话」和某条会话时，底部始终是**同一条输入**。上半部分可以在历史列表和会话内容之间更换，输入条不拆掉再挂上，也不要等会话加载完才变成「可以 Tab 选择 Agent」的另一种样子。

Agent 成员由进入该团队空间时加载一次。列表还没回来时，输入条外观和底部提示与列表回来之后相同；Tab 在列表为空时不插入提及，列表到达后立即可用，不必再等一轮。

「新对话」仍是页面中部的输入，不并进底栏。它与底栏使用同一个输入组件，用属性区分场合，但是**另一个实例**。

## 2. 现在的行为

| 位置 | 现在 |
| --- | --- |
| 团队空间「新对话」 | 页面中部一整块发起区（欢迎语、常用任务、输入框）。输入是 `ConversationStarter` 里的 `TaskComposer`。 |
| 团队空间「历史对话」 | 上方会话列表，下方另挂一条 `composer-only` 的 `ConversationStarter`。与「新对话」不是同一个实例。 |
| 从历史点进某条会话 | 列表和底栏一起卸掉，改由内嵌对话页自己的 `TaskComposer`。会话内容未返回前先是整页骨架，此时没有输入条。Agent 成员要等会话目标解析后再取一次，Tab 会晚一会儿才可用。 |
| 从会话返回 | 若链接未带历史视图，会回到「新对话」的中部输入，而不是历史底栏。 |
| 只读成员、已归档空间 | 不提供可发送的输入，并显示只读或归档说明。 |

`TaskComposer` 已经负责输入、附件、`@` / Tab 和发送按钮。两套体验来自外层各挂一次，而不是输入框本身有两套实现。

## 3. 输入条怎么挂

只涉及团队空间的对话页签。

| 场合 | 输入条 |
| --- | --- |
| 「新对话」 | 留在页面中部，欢迎语和常用任务仍在页面上。使用同一个输入组件的**中部实例**。 |
| 「历史对话」列表 | 列表在上，**底栏实例**在下。 |
| 点进某条会话或其中一次执行 | 会话内容在上，**同一个底栏实例**仍在下。不因为进入会话而换成对话页内部的另一条输入。 |
| 从会话返回历史 | 底栏实例仍在，上半部分回到历史列表。 |

底栏实例挂在团队空间页上。在历史列表与会话之间切换时不卸载。离开该团队空间、或整页刷新后，可以重新挂上。

「新对话」与「历史对话」的布局不同：从中部输入切到底栏，允许换成底栏那个实例。这不是历史与会话之间的切换。

不能写时不显示输入条：

- 空间已归档：对话页签保持只读历史，不出现中部输入，也不出现底栏。说明仍用现有归档文案。
- 当前角色为只读成员或角色未知：不出现底栏。查看会话时沿用现有「仅可查看，不能发言」说明。宁可漏开，不可显示一条看起来能发送的输入。

成员列表未返回、或返回为空时，可写成员仍看到这一条输入，不换成骨架或另一种输入框。

## 4. 同一个组件，用属性区分

中部实例和底栏实例都是同一个输入组件，内部仍用现有 `TaskComposer`。组件不请求 Agent 成员，不调用建会话、发讨论或续写接口。

由空间页传入的差异包括：

| 属性 | 作用 |
| --- | --- |
| 场合 | 中部发起，或底栏。底栏使用紧凑输入。 |
| 成员列表 | 空间页已经加载的、当前可发起对话的 Agent。`@` 与 Tab 只用这份列表。 |
| 能否写入 | 不能写时由页面不挂该组件，而不是组件里做一套只读样式。 |
| 草稿上下文 | 见第 5 节。组件按这个上下文读写未发送内容。 |
| 执行状态 | 当前正在看的执行可以停止时，发送按钮变为停止，行为与现在的停止本轮执行相同。 |

底部提示在可写的团队输入上始终是同一句：Tab 选择最近或首位 Agent，按住 Tab 再按 1～9 按列表顺序选择，Enter 发送，Shift+Enter 换行。不随成员列表是否已经返回而改成另一句。

Tab 的选择规则与现在相同：松开 Tab 插入该空间最近一次成功 @ 过的 Agent，没有记录则用列表第一位；按住 Tab 再按 1～9 插入列表对应项。列表为空时按键不插入内容。

## 5. 草稿

未发送内容按上下文分开保存，至少包括已输入文字、已选文件和已选提及。

| 上下文 | 谁在用 |
| --- | --- |
| 中部「新对话」 | 只属于中部实例。与底栏互不影响。 |
| 底栏「从历史发起」 | 人停留在历史列表、尚未进入某条会话时。 |
| 底栏「某一条会话」 | 人正在看该会话或其某次执行时。每条会话一份。 |

切换上下文时，先记下当前这份，再显示目标那份。从历史列表点进会话后，历史里打到一半的字不会出现在该会话的输入里；返回历史列表时，那些字还在。换一条会话则换成那一条自己的草稿。

发送成功后，只清空当前上下文的草稿。发送失败时保留文字、附件和提及，便于直接重试。

草稿只留在当前打开的团队空间页里。离开该空间或刷新页面后不恢复。不写入账号或服务端。

## 6. 发送

输入组件在发送时交出：文字、附件、提及，以及当前草稿属于哪一个上下文。空间页决定调用哪条现有逻辑：

| 当前所在 | 发送 |
| --- | --- |
| 「新对话」或历史列表 | 与现在从空间发起相同：显式 @ 或唯一可用成员时发起执行；否则在允许时开一条不产生执行的讨论。带附件却没有可用 Agent 时，仍提示需要 @Agent，并保留输入。 |
| 某条会话 | 与现在在该会话中发送相同：@ 成员则发起执行并进入该次执行；不 @ 则发送讨论消息。带附件却未 @ 时仍拦截并保留输入。 |
| 某次执行 | 与现在的续写相同，包括讨论消息与 @ 后续写执行。可以停止时，主按钮停止本轮执行，不另做按钮。 |

不新增接口。个人空间的发起规则不因本组件而改变（本期也不改个人空间）。

## 7. 不在本期

## 8. 改动范围

只改员工端团队空间的输入挂载与草稿。不改 DSH，不改会话与 Run 的接口语义。

| 位置 | 改动 |

## 9. 验收

1. 在团队空间从历史列表点进一条会话再返回，底部输入没有被整页骨架替换，也没有换成另一套提示后才可以 Tab。
2. 在历史底栏输入一段未发送文字后点进会话，会话输入为空；返回历史后，那段文字还在。两条会话的未发送文字互不影响。
3. 「新对话」中部输入与历史底栏的未发送文字互不影响。从「新对话」切到「历史对话」时，输入从中部变为底栏。
4. Agent 成员列表返回前后，底栏外观和底部提示相同。列表返回后，Tab 能按第 4 节插入 Agent。
5. 在历史列表发送、在会话中发送、在执行中续写或停止，结果与本期改动前的对应操作一致；失败时输入仍在。
6. 只读成员看不到可发送的底栏；已归档空间不出现中部输入或底栏。
7. 个人空间、工作台首页、独立对话页的输入与本期改动前一致。
