## 2. 安全不变量

### 2.1 Agent 执行身份回填

- 可见角色只控制谁能发现和使用 Agent，不得成为 Agent 的执行角色来源。
- 已应用的 `0066_agent_principal_grants.sql` 不修改；新增后继迁移 `0109_agent_principal_role_backfill.sql` 收紧历史数据。
- 存在成功的 `agent.principal.update` 审计时，视为管理员已显式确认当前执行角色，迁移保留该角色集合。
- 默认助手的执行角色固定收敛为 `role-employee`。
- 其余无法证明经过显式授权的历史 Agent 清空执行角色，后续执行 fail closed，要求管理员重新配置。
- 发布前必须输出受影响 Agent 清单；迁移不可逆地收紧授权，不尝试从展示字段恢复角色。

### 2.2 MCP 能力批准快照

- Connector 首次登记可直接形成批准快照。
- 后续检查时，只有名称和 Schema 均未变化的已批准能力继续生效。
- 新能力或 Schema 变化只进入 `pendingCapabilities`，Connector 状态为 `changes_pending`。
- 只有显式确认才用当前发现结果覆盖批准快照。
- Runtime Manifest 只读取已批准能力；管理页分别显示生效数量与待确认数量。
- 旧 MCP 服务和统一 Tool Connector 服务必须共用同一纯函数，禁止两套合并语义继续漂移。

## 3. 生产契约

### 3.1 授权错误码

- 执行期复核继续使用 `authorization_denied`。
- 服务层普通业务拒绝使用 `permission_denied`。
- 成员资格撤销、角色停用、数据范围撤销分别从事实来源抛出 `permission_revoked`、`role_disabled`、`data_scope_revoked`，不得按中文消息推断。
- 员工 HTTP 边界把普通 `permission_denied` 统一投影为 `authorization_denied`，但保留三个撤权专用码；管理端保留 `permission_denied`。

### 3.2 Agent 管理 API

服务端和 OpenAPI 既有固定路由不变：`PATCH /agents/draft`、`PATCH /agents/status`、`POST /agents/rollback`。管理端客户端改为把 `agentId` 放入 body，不创建 `/:agentId/...` 变体。

### 3.3 项目任务与运行投影

- `run.completed` 把任务连续失败状态记为 `succeeded`；`run.failed` 记为 `failed`；用户取消不计入连续失败。
- Run 查询投影稳定提供可空 `TaskRun.stoppedBy`；线程稳定提供可空 `stoppedByName`。
- 首条任务消息产生的 `discussion_posted` 保留；测试只断言必要动态存在。
- 只修复 `41eb100` 仍能复现的简报/档案版本固定、完整 `ProjectTask` 返回、工具装配、显式 Skill Manifest、Tool 结果投影、文件版本状态机与解析失败 422。

- MCP 租户容量上限为 20。
- 迁移测试以 `0109` 为最新尾部；旧迁移幂等测试只断言自己负责的列，升级夹具按依赖逆序显式清理。
