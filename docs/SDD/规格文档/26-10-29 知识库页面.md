# 员工端知识库页面（WeKnora）

**状态：** 部分实现（2026-10-29：dsh-work 壳层与 BFF 已落地；WeKnora 换票待对接）
**分类：** 员工工作台新增页面（只读查阅 + 账号连接）  
**范围：** 在 dsh-work 员工端壳层内打开 WeKnora 知识库。浏览器只访问 dsh-work。WeKnora 仍是知识库的权威系统。

实施步骤见 [26-10-29 知识库页面](../实施计划/26-10-29%20知识库页面.md)。

WeKnora 必须提供的换票与绑定接口，以 WeKnora 仓库同日规格为准：`G:\workspace\GD-SaiiKen\WeKnora\docs\SDD\规格文档\26-10-29 dsh-work 知识库换票.md`。本文不复制该接口的实现步骤。

## 1. 要达成的事

员工在工作台里点「知识库」，留在当前壳层（A 工作模式侧栏或 B 协作模式侧栏）里看到自己在 WeKnora 中有权看到的知识库，点进某一个库后可以检索并预览文档。

身份用已经登录的 dsh-work 会话。AI Hub 账号在两边都已开通时，打开页面即可查阅，不再输入 WeKnora 密码。仅有 dsh-work 本地账号、或企业身份尚未对上 WeKnora 账号时，在同一页面完成一次绑定；绑定完成后的查阅不再离开工作台。

成功时：

- 地址在 dsh-work 自己的站点上（`/knowledge`、`/knowledge/:kbId`），页面是工作台组件，不是嵌入框，也不是跳到 WeKnora 站点继续使用。
- 浏览器拿不到 WeKnora 的访问令牌、API Key 或集成密钥。
- 员工 A 看不到员工 B 在 WeKnora 里无权阅读的库和文档。
- 未配置 WeKnora、尚未绑定、知识库为空、服务不可用，各自有明确说明，不用空列表冒充「没有库」。

## 2. 现状

- 员工端 A 模式主导航为「新对话、Skill 广场、AI 同事、项目空间、定时任务」。B 模式主导航为「对话、AI 同事、群组、定时任务」；Skill 广场、我的文件、历史对话在头像菜单。没有知识库入口。共用页不带 `meta.mode`，两种模式共用同一地址，壳层随当前模式变化（`App.vue`）。
- dsh-work 已有 PostgreSQL 企业知识（Run 引用与引用脚注）。那是平台自己的知识数据，不是 WeKnora。
- 员工身份为 AI Hub OIDC 或本地账号。OIDC 用户的 `subject` 与目录用户标识由现有会话提供。
- WeKnora 已有知识库 HTTP API 与目录身份（ai-hub `user_id` / `subject`）。它没有「用 dsh-work 会话直接登录」的入口。API Key 上的 `signed_token` 主体是外部 API 用户，不能当作该员工的网页登录身份，本期不使用。

- 不在 dsh-work 收集或保存 WeKnora 密码。
- 不上传、删除、移动、共享、重新解析文档，不改知识库设置，不做 Wiki、自动化、工具箱、组织管理。
- 不在本期把 WeKnora 接进 Agent 的工具或 MCP。对话里的企业知识引用保持现有 PostgreSQL 知识模块。
- 不新建第二套 Agent 执行链路，不在浏览器里直接调用模型。
- 不自动在 WeKnora 开户。目录里没有这个人时，页面说明账号尚未开通，请联系管理员。
- 不做多空间切换。换票返回的那个空间就是本期能看到的空间（该用户的个人空间；WeKnora 列表里已经包含的、此人有权看到的共享库一并展示）。

- 不把 WeKnora 令牌写入审计正文、前端响应或日志。

## 5. 身份

打开知识库相关接口时，服务端只认当前 dsh-work 员工会话。浏览器传入的用户标识不能当作 WeKnora 用户。

连接结果只有三种：

| 状态 | 条件 | 页面 |
| --- | --- | --- |
| 未配置 | 未设置 WeKnora 基址或集成密钥 | 「知识库尚未配置」 |
| 已连接 | 下面两条之一成立 | 知识库列表 |
| 待绑定 | 已配置，但既不能按目录对上，也没有绑定记录 | 「连接知识库账号」 |

已连接的判定，按这个顺序，命中即停：

1. **目录。** 当前用户是 AI Hub 身份，且 WeKnora 按 `subject` 或 ai-hub `user_id` 能换出该用户的会话。不写绑定表。
2. **绑定记录。** `user_weknora_links` 里有该 dsh-work 用户。用其中的 WeKnora 用户标识换票。
3. 否则为待绑定。

目录换票成功时，即使存在指向另一个 WeKnora 用户的绑定记录，也以目录身份为准，并在服务端把该绑定记录改成目录返回的用户。换票接口返回「账号尚未开通」时，不创建绑定，页面保持待绑定或开通说明（见 §6）。

本地账号没有目录身份，只能走绑定。AI Hub 账号在目录中找不到时，同样走绑定；绑定到的 WeKnora 账号必须是本人登录 WeKnora 后确认的那个账号。

### 5.1 绑定（仅待绑定）

员工点击「连接知识库账号」后，同一窗口打开 WeKnora 的绑定登录（该部署已有的密码登录或企业登录）。dsh-work 在跳转前写入一次性 `state`（仅服务端保存，10 分钟，用后即废）。

WeKnora 在本人登录成功后，把一次性 `bind_code` 重定向到 dsh-work 的回调。dsh-work 校验 `state`，用集成密钥向 WeKnora 换得 WeKnora 用户标识，写入 `user_weknora_links`（`link_source = bind`），再回到 `/knowledge`。

`state` 对不上、过期或已使用：回到 `/knowledge` 并说明连接未完成，不写入绑定。

绑定记录可以在知识库页解除。解除只删 dsh-work 的绑定行，不删除 WeKnora 账号或知识库。解除后页面回到待绑定。目录身份已能换票时，不提供解除（解除了仍会按目录连上）。

### 5.2 换票缓存

服务端可以按「dsh-work 会话 + WeKnora 用户」缓存 WeKnora 访问令牌，时长不超过对方返回的过期时间，且不超过 10 分钟。缓存不落库、不进浏览器。对方返回 401 时丢弃缓存并换票一次；仍失败则本次请求失败，页面说明知识库暂时无法访问。

dsh-work 会话结束、用户停用或解除绑定时，丢掉该用户的缓存。

## 6. 页面

三块都在员工端壳层的主内容区，使用现有工作台组件与样式。加载中显示占位，失败显示原因和「重试」。

### 6.1 列表 `/knowledge`

已连接时列出当前换票空间内、该用户有权看到的知识库。每条至少有名称。有简介、文档数、最近更新时间时一并显示。

点击一条进入 `/knowledge/:kbId`。

列表为空时说明「还没有知识库」，不显示「尚未配置」或「请先连接」。

### 6.2 库内 `/knowledge/:kbId`

- 标题为该库名称，可回到列表。
- 文档列表：标题、更新时间（接口有则显示）。
- 检索框：提交后在**当前库**内检索，结果列出文档标题与摘要。点击结果在本页打开预览。
- 无权或不存在的库：说明「无法打开该知识库」，不展示库名以外的猜测，并提供回到列表。HTTP 为 404。

### 6.3 预览

在库内页打开预览，不新开 WeKnora 站点。

- 浏览器可直接显示的类型（PDF、纯文本、Markdown、图片）在页面内显示。
- 其他类型提供「下载」，下载仍走 dsh-work 接口，由服务端向 WeKnora 取文件。
- 预览失败时留在库内页并说明无法预览。

### 6.4 待绑定与未开通

待绑定：说明需要连接知识库账号，主按钮为「连接知识库账号」。

`directoryAccount` 为 `missing` 且尚未绑定成功时：说明知识库账号尚未开通，请联系管理员，并仍显示「连接知识库账号」（供目录邮箱与旧 WeKnora 账号不一致时走 §5.1）。`directoryAccount` 为 `none` 时只显示连接说明，不显示「尚未开通」。

未配置：只说明尚未配置，不显示连接按钮。

## 7. 员工端接口

前缀 `/api/workbench/v1`。成功体为现有工作台信封 `{ "data", "meta" }`，字段 camelCase。失败为现有 `{ "error": { "code", "message", "object", "suggestion", "traceId" } }`。不使用 `{ code, data, msg, message }` 信封。

未登录 401。已登录即可调用下列接口，不另设角色。WeKnora 侧的拒绝原样变成 dsh-work 的 403 或 404，不把对方堆栈返回浏览器。

| 方法 | 路径 | `data` |
| --- | --- | --- |
| `GET` | `/integrations/weknora/status` | `{ configured, linked, source, canUnlink, directoryAccount }`。`source` 为 `directory`、`bind` 或 `null`。`directoryAccount` 为 `none`（当前不是 AI Hub 身份）、`missing`（是 AI Hub 身份但 WeKnora 返回账号尚未开通）、`linked`（目录换票成功）。未配置时 `configured` 与 `linked` 均为 false，`directoryAccount` 为 `none`，且不调用 WeKnora。`canUnlink` 仅在存在绑定记录且当前 `source` 不是 `directory` 时为 true |
| `POST` | `/integrations/weknora/bind/start` | `{ "url": "<WeKnora 绑定地址>" }`。未配置 503，已由目录连上 409 |
| `GET` | `/integrations/weknora/bind/callback` | 浏览器跳转，不返回 JSON。成功 302 到 `/knowledge`；失败 302 到 `/knowledge?bind=failed` |
| `DELETE` | `/integrations/weknora/link` | `{ "ok": true }`。没有绑定记录时同样成功。目录身份仍可换票时，删除绑定记录不影响下一次 `status.linked` |
| `GET` | `/integrations/weknora/knowledge-bases` | `{ "list": [ { "id", "name", "description", "documentCount", "updatedAt" } ] }`。没有的字段省略，不用 0 填充未知的文档数 |
| `GET` | `/integrations/weknora/knowledge-bases/:id` | `{ "id", "name", "description" }` |
| `GET` | `/integrations/weknora/knowledge-bases/:id/documents` | `{ "list": [ { "id", "title", "updatedAt" } ] }` |
| `POST` | `/integrations/weknora/knowledge-bases/:id/search` | 正文 `{ "query": "<非空字符串>" }`。`data` 为 `{ "list": [ { "documentId", "title", "snippet" } ] }` |
| `GET` | `/integrations/weknora/documents/:id/content` | 文件字节。`Content-Disposition` 为附件或内联由类型决定。查询参数 `disposition=inline` 只允许 PDF、纯文本、Markdown、图片 |

未连接时，列表、详情、文档、检索、内容一律 409，`error.code` 为 `weknora_not_linked`。未配置时这些接口 503，`error.code` 为 `weknora_not_configured`。WeKnora 超时或网络失败 503，`error.code` 为 `weknora_unavailable`。

列表本期一次返回对方给出的全部可见项，不做分页参数。对方若分页，服务端把各页收齐后再返回；单次最多收 20 页，超过则 503 并说明结果过多，不静默截断。

## 8. 数据

新表 `user_weknora_links`：

| 列 | 含义 |
| --- | --- |
| `user_id` | dsh-work 用户，主键 |
| `weknora_user_id` | WeKnora 用户标识 |
| `link_source` | `bind`（目录自动连上的不依赖此行；若因目录覆盖而改写，改为 `directory`） |
| `linked_at` | 写入或覆盖时间 |

不保存 WeKnora 访问令牌、刷新令牌或密码。

## 9. 配置

| 变量 | 含义 |

## 10. 验收

业务语言，不预设尚未存在的测试选择器。

1. 工作模式主导航为「新对话、Skill 广场、AI 同事、项目空间、知识库、定时任务」。点「知识库」进入 `/knowledge`，侧栏仍在，地址仍在工作台站点。
2. 协作模式主导航仍是四个入口。头像菜单有「知识库」，打开后地址同为 `/knowledge`，壳层仍是协作模式。切换模式不改变该地址。
3. 未配置时，页面说明尚未配置，没有连接按钮，列表接口不可用。
4. AI Hub 用户且 WeKnora 能按该身份换票时，打开即见知识库列表，过程中没有 WeKnora 登录页。
5. 本地账号或尚未开通的企业账号看到连接说明。完成一次绑定后看到列表。中途取消或 state 无效时仍停留在工作台并说明未完成，不产生绑定。
6. 点进一个库可看到文档，检索只返回该库的结果，预览或下载发生在工作台内。另一个用户无权的库地址显示无法打开。
7. 浏览器网络记录里的知识库请求都发往 `/api/workbench/v1/integrations/weknora/`，响应里没有 WeKnora 访问令牌。
8. 未连接时不能列出库。解除绑定后，仅靠绑定连接的用户回到连接说明；仍能按目录换票的用户列表保持可用。

P0 冒烟使用夹具状态（未配置或一条合成库），不连接真实 WeKnora。真实换票、目录账号与文件字节属于 P2，不能用冒烟通过代替。
