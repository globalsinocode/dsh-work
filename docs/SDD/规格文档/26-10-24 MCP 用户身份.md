# 26-10-24 MCP 用户身份

**状态：** 已实现（2026-10-24）。
**确认日期：** 2026-10-24

管理员仍在现有「MCP 连接器」里登记外部 MCP。新增一种认证方式：员工用自己的账号向该上游授权，之后每次执行只携带这名员工的访问令牌。上游因此按该员工在原系统里的身份和权限返回数据。

平台继续做登记、能力快照、Agent 使用范围、执行前复核和逐调用审计。平台不代替上游做数据过滤，也不把 MCP 工具复制成平台 Tool。执行仍走现有 Run / Attempt、Runtime Adapter 与 DSH，不新增第二套 Agent 循环。

本文描述目标行为。当前代码里的 MCP 只有 `none` 与 `bearer`，凭据挂在连接器上、全体员工共用一个上游身份。该行为在本规格落地前保持不变。

## 1. 范围

本期做：

- 管理端登记「用户授权」型 MCP：填写上游地址和 OAuth 客户端资料，用登记人自己的授权做一次连通性证明和工具发现。
- 员工在用户中心授权、查看状态、解除授权。发起对话或自动任务时，若本次要用到尚未授权的连接器，当场引导授权。
- 运行时按**本次人类主体**取出该人的令牌，注入现有的 DSH 子进程环境变量。Manifest 只多记主体和凭据版本，不记令牌明文。
- 未授权、授权失效、令牌刷新失败时拒绝或移出本次装配，**绝不改用连接器级 Bearer、管理员的令牌或其他员工的令牌**。

本期不做：

- 不改 `none`、`bearer` 连接器的登记、存储、注入和共用上游身份。
- 员工不能自建、修改或删除 MCP。不增加第六个主导航入口。
- 不做逐 Agent Grant、逐 Tool 勾选，也不做第二套连接器审核。
- 不做动态客户端注册（DCR）、设备码、扫码弹窗、CLI 托管登录、手填个人 PAT。上游若只接受一把共享密钥，继续用现有 `bearer`，那不算「用户自己的身份」。
- 不支持 MCP Resources、Prompts、stdio。传输仍是 Streamable HTTP。
- 不在 URL 查询参数里放令牌。不把令牌写入 Manifest、补丁文件、接口响应、日志或前端存储。
- 平台不解析、不裁剪 MCP 工具返回的业务数据。上游权限由该员工的令牌决定。

## 2. 两种认证并列

一个 MCP 连接器只有一种认证方式，登记后不可改成另一种。要换方式须删除后重新登记。

| 认证方式 | 谁持有上游身份 | 员工要做什么 |
| --- | --- | --- |
| 无认证 `none`、Bearer `bearer` | 连接器级。Bearer 仍是平台保管的一把令牌，所有获准调用看到同一个上游身份 | 无。沿用现在的管理端录入和轮换 |
| 用户授权 `user_oauth` | 每一名完成授权的员工各有一套访问令牌和刷新令牌 | 用自己的账号完成一次授权；可随时解除 |

`user_oauth` 的客户端标识（`client_id`，以及可选的 `client_secret`）属于连接器，全租户一份。`client_secret` 只在向令牌端点换票时使用，加密存放，规则与现有连接器级密文相同。员工令牌是另一批密文，见第 5 节。

## 3. 管理端登记

入口仍是管理端「Agent 治理 → MCP 连接器」。列表、容量（租户最多 20 个、单次 Attempt 的既有上限）、启停、删除、健康状态和能力摘要的门禁保持不变。`connector-dsh-workspace` 仍不出现在此页。

选择「用户授权」时，管理员填写：

| 字段 | 要求 |
| --- | --- |
| 名称、上游权限说明 | 与现在相同。权限说明只描述边界，平台不按这段文字过滤数据 |
| MCP 地址 | HTTPS 的 Streamable HTTP 端点，作为受保护资源 |
| 授权端点、令牌端点 | HTTPS。授权端点的源站是唯一允许跳转的授权页，防止把员工带到未登记域名 |
| 客户端标识 | 管理员向该上游预先注册的 `client_id`。本期不自动注册客户端 |
| 客户端密钥 | 可空。为空时只使用 PKCE。不为空时加密保存，页面不回显 |
| 权限范围 scope | 至少一项。员工授权时原样申请，员工不能在页面上改范围 |
| 受众 resource | 默认同 MCP 地址。令牌若是 JWT，换票后必须校验 `aud` 等于该值、`iss` 的源站等于授权端点的源站、且未过期。对不上就拒绝保存授权。本期不以发现文档另行推断签发方。不透明令牌不做这些声明校验，但只允许发给这个 MCP 地址 |

「测试连接」不接收管理员粘贴的用户令牌。步骤是：

1. 当前管理员若还没有这份连接器的有效授权，先走第 4 节的同一套授权。连接器尚未入库时，换到的令牌只保存在这名管理员的本次测试会话里，10 分钟内未点击「添加 MCP」、或中途修改登记字段，即销毁，不成为可被执行引用的授权。
2. 只用**这名管理员自己的**访问令牌让 DSH 做一次 `tools/list`。
3. 没有工具、或发现到 Resources / Prompts 以外的空能力，测试失败，与现在一样不入库。
4. 成功后展示工具名、描述和输入 Schema。修改任一登记字段会使测试结果失效。
5. 「添加 MCP」再次用这名管理员的令牌复核。成功后写入连接器、能力摘要，并把这次授权记在**该管理员**名下。这把令牌只供这名管理员以后自己的调用和自己发起的健康检查，不是全员回退凭据。

健康检查：

- 操作者本人已授权：用其令牌复核端点与能力摘要。摘要漂移、端点失败时，沿用现有降级 / 待复核，已固定的旧 Attempt 在下次复核时拒绝。
- 操作者本人未授权：不改连接器健康状态，提示「需要先用你自己的账号授权，才能复核」。禁止借用其他员工或登记时留下的令牌。

停用后，任何人的新 Attempt 都不再装配它；已有员工授权保留，重新启用后仍可用，不必每人重授权。删除时解除全部员工授权并销毁对应密文，进行中的 Attempt 在下一次授权复核失败并收敛为授权已撤销。

## 4. 员工授权

员工看到的是「哪些已登记的用户授权连接器、我是否已授权」，不是登记表单。

两个入口，同一套授权记录：

- **用户中心**（现有 `/settings`，不进主导航）增加一节「外部连接」。列出本租户已启用的 `user_oauth` 连接器：名称、上游权限说明、工具数量、我的状态。没有此类连接器时说明「管理员尚未登记需要个人授权的外部连接」。
- **发起执行时**：本次 Agent 范围解析后，若有尚未授权或需要重新授权的 `user_oauth` 连接器，在发送前说明名称，并提供授权。授权完成回到原页面，不另开主导航。

状态只有四种：未授权、已授权、需要重新授权、连接器已停用。页面不显示令牌、刷新令牌、`client_secret` 或密文。

授权过程：

1. 仅已登录员工可开始。交易在服务端生成，包含一次性 `state`、PKCE（S256）和过期时间（10 分钟），并绑定租户、当前用户、目标连接器。
2. 浏览器只跳到该连接器登记的授权端点。回调必须回到平台自己的地址，且 `state` 与**当前会话里的同一用户**一致。不一致、过期或重复使用都拒绝，不换票。
3. 用授权码向登记的令牌端点换票。访问令牌与刷新令牌加密后记在该用户与该连接器的授权上。已有授权再次完成时覆盖旧密文并递增版本。
4. 员工可解除授权。只销毁自己的密文，不影响他人，也不停用连接器。解除后新的执行按第 6 节处理；已开始且固定了该版本的 Attempt，在复核时拒绝继续使用。

令牌刷新由平台在解析本次运行凭据时做，员工无感。刷新必须轮换：上游若返回新的刷新令牌，立刻替换旧的。刷新失败把状态改为「需要重新授权」，废弃这对令牌，不把过期访问令牌继续交给 DSH。

平台登录（OIDC 或本地账号）只证明「是哪一名员工」。上游账号可以不同。平台不把平台会话令牌当作 MCP 令牌。

## 5. 凭据归属

连接器级密文（现有 Bearer、以及可选的 `client_secret`）保持现在的加密：主密钥来自 `DSH_CREDENTIAL_MASTER_KEY`，附加认证数据绑定租户和凭据引用。

员工访问令牌和刷新令牌单独存放，附加认证数据在租户和凭据引用之外**再绑定该员工主体**。密文不能改挂到另一名员工或另一个连接器后解密。明文只在服务端准备本次 Attempt 时解密，随现有环境变量进入该 Attempt 的 DSH 子进程，补丁文件里仍然只写环境变量引用。

接口、管理端、员工端、审计详情和日志都不返回令牌。审计继续记录发起人；用户授权调用额外记录所用的授权主体，且必须与本次注入令牌的主体是同一人。

## 6. 一次执行到底用谁

求交顺序固定为：

1. Agent 版本已发布的 MCP 范围（`none` / `selected` / `all`），规则与现在相同。不新增逐 Agent 授权。
2. 连接器仍启用、健康检查门禁与能力摘要仍与 pin 一致。
3. 其中 `user_oauth` 再与**本次人类主体**的有效授权求交。

人类主体：

| 入口 | 主体 |
| --- | --- |
| 员工发起的对话、团队空间发言 | 当前登录员工（发起人），不是 Agent 的执行身份 |
| 自动任务 | 该自动任务的所有者。不使用当时正在查看页面的其他人 |
| 没有人类所有者的系统触发 | 不能使用任何 `user_oauth` 连接器 |

同一 Attempt 从准备到结束都固定这名主体和当时的凭据版本。中途不换人，也不把后授权的连接器追加进已经开始的 Attempt。

未持有有效授权时：

| Agent 范围 | 行为 |
| --- | --- |
| `selected`，其中包含该 `user_oauth` 连接器 | **拒绝本次准备**。明确列出缺哪几个连接器。不静默跳过，不改用 `bearer`，不改用别人的授权。员工可先授权再重试 |
| `all` | 从**本次**装配中移出尚未授权或需要重新授权的 `user_oauth` 连接器，发送前告诉员工哪些被移出。模型提示和工具白名单里都不出现它们。已授权的照常装配。移出不是删除连接器，也不把范围改写成另一份 Agent 配置 |
| `none` | 与现在一样，不装配 MCP |

`selected` 在试运行和正式执行上同一口径。`all` 在没有可用 MCP 时，仍不得伪造「外部能力已完成」。

自动任务在运行点按所有者现查授权，不在启用任务时复制令牌。所有者对某个 `selected` 连接器未授权或刷新失败时，这一次运行失败并留下可理解原因；不改派给管理员。

## 7. 固定与复核

Manifest 里现有的六项（连接器、服务名、传输、端点、认证方式、能力摘要）仍然必填，且仍要求网络策略为允许列表。`user_oauth` 再固定两项：授权主体、凭据版本。令牌值不在其中。

认领后、启动 Runtime 前，以及排队后的复核，除现在的端点、摘要、启停、凭据版本外，再核对：主体仍是这名员工、授权仍有效、版本未被解除或轮换掉。任一不成立则 `authorizationDenied`，并按现有路径收敛为授权已撤销。失败时不得改用连接器级凭据重试。

DSH 仍只调用白名单内、且属于已批准能力摘要的工具。上游若因该员工权限较少而拒绝某个工具，这次调用失败并记入现有 MCP 调用审计，不扩大白名单。摘要之外的工具即使上游愿意执行，平台侧也不放行。

## 8. 员工可感知的结果

| 场景 | 员工看到的 |
| --- | --- |
| 管理员登记了用户授权连接器，员工从未授权 | 用户中心显示未授权。使用 `all` 的 Agent 时，该连接器不进入本次对话，并在发送前说明。使用 `selected` 且点名了它时，不能发送，直到授权完成 |
| 授权成功后再次发送 | 本次工具来自这名员工的上游身份。另一名员工授权同一连接器，看不到对方的上游数据 |
| 解除授权或上游拒绝刷新 | 状态变为未授权或需要重新授权。新的 `selected` 执行被拒绝；新的 `all` 执行不再带上它。已经固定旧版本的执行在复核时停止 |
| 管理员停用或删除 | 新执行不再装配。删除后用户中心不再列出，原授权不可恢复 |
| 管理员登记的仍是 Bearer | 与现在相同，员工用户中心不把它显示成「待个人授权」 |

管理端不提供「查看某员工令牌」或「以某员工身份试连」。管理员自己的调用只代表管理员本人。

## 9. 验收

用业务结果判断，不依赖尚未存在的测试选择器。

1. 管理员能登记一个用户授权 MCP：不粘贴员工令牌，用自己的授权完成测试和添加；工具清单被封存；页面和接口响应中没有令牌或客户端密钥。
2. 两名员工分别授权后，各次执行注入的是各自的令牌。未授权员工在 `selected` 下发不出去，在 `all` 下该连接器不出现在本次可用工具中。两种情况都不会落到平台 Bearer 或另一人的令牌上。
3. 解除授权、刷新失败、停用、删除、能力摘要变化，都会让已固定的执行在复核时停止，并留下发起人与授权主体一致的调用审计。
4. 现有无认证和 Bearer 连接器的登记、轮换、共用身份和审计保持原样。
5. 员工不能登记 MCP。主导航仍是「新对话、Skill 广场、AI 同事、团队空间、自动任务」。
6. 自动任务使用所有者的授权。所有者未授权时，点名了该连接器的任务本次失败，且不借用他人授权。

实现时同步改架构说明里「MCP 凭据一律是连接器级共享身份」的表述，写明只有 `user_oauth` 按员工主体分权，并标明这是本规格落地后的约束。落地前，那些文档里的现行描述仍然有效。
