## 1. 要解决的问题

现在的提示只活在打开的页面里：Vant Toast / Notify 会随页面关掉消失；协作未读靠回到列表或页面重新可见时再拉接口；某次 Run 的 SSE 只在该页还活着时推事件。员工切走或划掉 PWA 之后，手机通知栏里看不到新消息，也看不到自己发起的任务已经结束。

本期要同时做到两件事：

1. **应用还开着**：在安全区下方出现一条顶部通知，点进去进对应对话。看起来接近原生 App 的应用内横幅，不是系统通知栏。
2. **应用已关掉或进程已不在**：由服务端 Web Push 唤醒 Service Worker，在系统通知栏留下一条通知。点通知打开对应对话。

两类业务都要覆盖：

| 类型 | 谁会收到 | 什么时候 |
| --- | --- | --- |
| 协作新消息 `collab_unread` | 该对话对象的其他成员 | 出现会增加其未读的新发言（同事讨论，或 Agent 回复） |
| 任务结果 `run_finished` | 发起这次 Run 的员工本人 | Run 进入成功、失败，或等待审批 |

同一个人、同一次助手回复只产生一条通知，规则见 §4。

## 2. 范围

### 2.1 本期做

1. 登录后的手机工作台可以登记本机 Push 订阅，退出登录时注销这一条订阅。
2. 登录进入工作台后，若本机通知权限仍是「未询问」，立刻弹出系统权限框。用户点允许后登记订阅；点拒绝后不再自动弹。「我的」仍可关掉本机订阅，或在权限已被拒绝时看到去系统设置的说明。
3. 前台用顶部通知；没有可见窗口时用系统通知栏。两条通道看同一套事件偏好。
4. 协作新消息、本人发起的 Run 终态（成功 / 失败 / 等待审批）都会按 §4 发送。
5. 点顶部通知或系统通知，打开现有对话地址；当前是协作模式时仍走 [26-10-26](./26-10-26%20协作模式.md) 的地址映射，不新做一套详情页。等待审批点进去后，在该对话里允许或拒绝，不提示去电脑端。
6. 静音群组不发这两种通知。未读数字、列表样式保持协作模式现有规则。
7. 后端保存订阅、按事件调用 Web Push，并在推送服务返回订阅失效时删掉该订阅。

### 2.2 本期不做

- 不给 PC 工作台做订阅或系统通知。后端只向已保存的订阅发送，没有订阅就不会推。
- 不改变 SSE、不改变「打开中的会话跟随 run events」、不改变列表在进入对话 Tab 与页面重新可见时的刷新。
- 不把定时同步、后台轮询当作「应用已关掉」的通知手段。页面被系统杀掉之后，只有 Web Push 算数。
- 不推：用户自己发出的讨论、用户自己取消的 Run、静音群组、员工私聊（手机端仍没有私聊）、定时任务、成员治理。允许或拒绝不做成通知栏按钮，也不再单独推一条「已通过 / 已拒绝」。
- 不在通知正文里放 Cookie、令牌、文件内容或完整 Markdown。
- 不改微信、企业微信内置浏览器里「加到主屏幕并在杀掉进程后收系统通知」的能力。这类容器里只保证应用还开着时的顶部通知。
- 不做通知中心历史列表，不做通知分组设置页（只有「我的」上的三个开关）。
- 不要求桌面图标角标。某台手机支持 `setAppBadge` 时可以在收到推送后顺手更新，不作为验收项。

## 3. 使用前提

系统通知栏（含关掉应用之后）同时满足下面四条才成立：

| 条件 | 说明 |
| --- | --- |
| HTTPS | 本机 `localhost` 开发例外。手机局域网 IP 上的 http 不能作为验收环境 |
| 已安装到主屏幕 | `display-mode: standalone`。iOS 16.4 及以上只给主屏幕图标里的 PWA 发 Push。Android 以安装后的 PWA 为验收对象 |
| 通知权限为允许 | 进入工作台时的系统权限框里点允许；拒绝后可在系统设置里重新允许，再打开应用会补登记订阅 |
| 服务端有一条有效订阅 | 登录账号与本机 `PushSubscription` 已绑定 |

缺任意一条时：应用打开期间仍可以出顶部通知（见 §6 的无推送退路）；系统通知栏不出现，也不要把这说成故障。

## 4. 何时发、发给谁

事件在服务端判定。服务端不判断手机屏幕是否亮着，每条符合条件的事件都发给该用户名下全部有效订阅。是否改成顶部条、是否进通知栏，由 Service Worker 按 §6 决定。

### 4.1 协作新消息

对话对象与未读口径沿用 `GET /me/conversation-targets`：`agent` 为与该 AI 同事的单聊，`group` 为本人所在的团队空间。预览仍是纯文本，最多 120 字，只取会进入未读的 user / assistant 内容。

| 新内容 | 接收人 |
| --- | --- |
| 其他成员的讨论消息 | 该群其余成员 |
| Agent 回复（assistant） | 该对话对象里、除这次 Run 发起人以外的成员 |
| 本人刚发出的讨论，或本人自己发起的这次 Run 的助手回复 | 不给本人发 `collab_unread` |

群组 `muted === true` 时，该群任何人都不收到 `collab_unread`。

### 4.2 任务结果

只通知发起这次 Run 的员工。状态从进行中变为下列之一时发一条 `run_finished`：

| 状态 | 标题 |
| --- | --- |
| 成功（`run.completed` / 任务 `succeeded`） | 任务已完成 |
| 失败 | 任务未完成 |
| `awaiting_approval` | 有待确认的操作 |

用户在手机上自己取消的 Run 不发。

助手回复已经按 §4.1 通知了其他成员，不再给那些成员发 `run_finished`。发起人只收 `run_finished`，不因同一条助手回复再收一条 `collab_unread`。

等待审批点进去后，对话页给出本次操作的原因、对象、范围，以及「允许本次」「拒绝」。只有这次 Run 的发起人能点。允许后从当前等待继续执行，不必重新发送问题。拒绝后本次 Run 结束，对话里写明「已拒绝本次操作」。其他人只看到等待说明，没有这两个按钮。不再使用「此操作需在电脑端确认」。

决议接口：`POST /runs/:runId/approval`，正文 `{ "decision": "approved" | "rejected" }`。仅发起人可调用，其他人 403。当前没有待决的审批时 409，按钮不再出现。`data` 为 `{ "runId": "<id>", "decision": "approved" | "rejected" }`。不打开管理端审批列表，通知栏上也不放允许/拒绝按钮。

### 4.3 合并

| 类型 | 通知 `tag` | 效果 |
| --- | --- | --- |
| `collab_unread` | `collab:{agent\|group}:{id}` | 同一对话对象只留最新一条 |
| `run_finished` | `run:{runId}` | 同一次 Run 只留最新状态 |

推送正文带 `eventId`。Service Worker 对同一个 `eventId` 只展示一次。

## 5. 文案与点击后去哪

标题、正文使用通知语言，不带 Markdown 标记。正文最多 120 字，更长则截断并加省略号。

| 类型 | 标题 | 正文 |
| --- | --- | --- |
| 单聊新消息 | AI 同事名称 | 预览文本。没有预览时用「发来一条新消息」 |
| 群聊新消息 | 群名称 | 「发送者：预览」。发送者用成员显示名；Agent 回复用该 Agent 名称 |
| 任务成功 | 任务已完成 | 会话标题。没有标题时用「可以回到对话查看结果」 |
| 任务失败 | 任务未完成 | 会话标题。没有标题时用「可以回到对话查看原因」 |
| 等待审批 | 有待确认的操作 | 会话标题。没有标题时用「打开对话后可以允许或拒绝」 |

点击后的地址用工作模式路径，交给现有模式守卫改写：

| 场景 | 地址 |
| --- | --- |
| 个人会话 | `/chat/{sessionId}` |
| 团队空间会话 | `/workspaces/{workspaceId}?session={sessionId}` |
| 任务结果 | 与该 Run 所属会话相同 |

无权或会话已删除：落到当前模式的对话首页，并沿用现有无权提示，不白屏。

通知图标用现有 `/icons/pwa/icon-192.png`。

## 6. 前台顶部与系统通知栏

Service Worker 收到 Push 后：

| 窗口情况 | 呈现 |
| --- | --- |
| 至少有一个本源窗口可见，且当前路由就是这条通知要打开的对话 | 不展示。用户正在看这条内容 |
| 至少有一个本源窗口可见，但当前路由不是目标对话 | 只出顶部通知，不进系统通知栏 |
| 没有可见窗口（含应用已划掉、进程已结束） | 只进系统通知栏 |

顶部通知：

- 贴在安全区下方，全宽圆角条，标题一行、正文一行，超出省略。
- 约 4 秒后收起。连续多条时只留最新一条，新的一条替换未消失的旧条。
- 点按走 §5 的地址。点按之外不挡住输入框的提交。
- 登录页、错误页不出现。

系统通知栏：

- 使用系统样式，不模拟状态栏。
- 点按打开或聚焦已安装的 PWA，再进入 §5 的地址。
- 同一 `tag` 的新通知替换旧通知。

### 6.1 还没有推送时的退路

用户拒绝系统权限，或关掉权限框而没有选择时，这一次进入不再弹第二遍。下次进入若权限仍是「未询问」，可以再弹。已经拒绝的，只能到系统设置里改，应用不再自动弹框。尚未安装到主屏幕时，浏览器若允许就照样弹权限框；不允许时给出现有安装说明。订阅失败时不反复弹框。

应用处于前台时仍要有顶部通知：

- 当前打开的 Run 仍看现有 SSE。终态符合 §4.2，且用户已经离开该对话页时，出顶部通知。
- 协作未读：对话列表保持现有的进入页面与重新可见时刷新；另外在已登录且页面可见时，每 60 秒拉一次 `GET /me/conversation-targets`。未读增加且不是静音、也不是正在看的那条对话时，出顶部通知。

这只覆盖页面还活着的时候。应用关掉之后没有这条退路。

## 7. 「我的」里的开关

放在安装入口上方，两种模式都显示。三项：

| 开关 | 缺省 | 作用 |
| --- | --- | --- |
| 系统通知 | 跟随本机权限 | 进入工作台时若权限未询问，先弹系统权限框。允许后开关为开，并登记订阅。拒绝后开关为关，文案为「请在系统设置中允许通知」。用户在这里关掉时注销本机订阅，已出现在通知栏里的旧通知不主动清空。再次打开时：权限仍是未询问或已允许则登记订阅；已拒绝则不再弹框，仍显示上述文案 |
| 协作新消息 | 开 | 关闭后不再投递 `collab_unread`（顶部与通知栏都停） |
| 任务完成提醒 | 开 | 关闭后不再投递 `run_finished`（成功、失败、等待审批一起停） |

偏好存在服务端，按账号，换手机仍然生效。`系统通知` 的浏览器权限与订阅是每台设备自己的。换一台手机后，进入工作台会再次弹出权限框。

iOS 上未安装到主屏幕时，系统往往不给出有效的通知权限。此时进入应用先走现有安装说明（含分享菜单步骤），安装完成并从主屏幕图标打开后，再弹出权限框。Android 上进入应用即可弹权限框，不要求先打开「我的」。

退出登录：先注销本机订阅，再走现有退出。取消退出确认时不注销。

## 8. 接口

前缀 `/api/workbench/v1`。成功与失败沿用 Workbench 现有信封（`code`、`data`、`msg`、`message`）。未登录 401。字段 camelCase。

### 8.1 公钥

`GET /me/push/config`

`data`：

```json
{ "vapidPublicKey": "<base64url>" }
```

没有配置密钥时 503，`message` 为「通知服务暂不可用」。手机端不弹权限框，开关保持关闭并显示同一句，不重试刷屏。

### 8.2 登记与注销

`PUT /me/push/subscriptions`

正文为浏览器 `PushSubscription.toJSON()` 的结果，至少包含 `endpoint`、`keys.p256dh`、`keys.auth`。同一用户、同一 `endpoint` 再次提交视为更新，返回 200。`data` 为 `{ "endpoint": "<同一 endpoint>", "updated": true }`。

缺字段或 endpoint 无法解析时 422。

`DELETE /me/push/subscriptions`

正文 `{ "endpoint": "<订阅 endpoint>" }`。只删除当前登录用户名下的这一条。本来就没有时仍返回 200，`data` 为 `{ "endpoint": "<同一 endpoint>", "deleted": true }`。不能删除别人的订阅。

### 8.3 偏好

`GET /me/notification-preferences`

从未保存过时 `data` 为 `{ "collabUnread": true, "runFinished": true }`。

`PATCH /me/notification-preferences`

正文可只带要改的字段，值为布尔。非法类型 422，原偏好不变。`data` 为保存后的完整对象 `{ "collabUnread": true, "runFinished": true }`。

`系统通知` 不进这个对象。它只表示本机权限与订阅是否有效。

### 8.4 推送载荷

服务端用 VAPID 发送。载荷是 JSON 文本，建议小于 3 KB：

```json
{
  "eventId": "稳定且唯一的事件 id",
  "type": "collab_unread",
  "tag": "collab:group:ws_123",
  "title": "华东项目组",
  "body": "林夏：合同第三节已改完",
  "url": "/workspaces/ws_123?session=sess_9",
  "sessionId": "sess_9",
  "targetType": "group",
  "targetId": "ws_123"
}
```

`type` 为 `run_finished` 时增加 `runId`、`runStatus`（`succeeded` | `failed` | `awaiting_approval`），`tag` 为 `run:{runId}`。`targetType` 在个人会话时为 `agent`。

推送服务返回订阅已失效（如 404 / 410）时删除该订阅，不影响同用户的其他设备。发送失败不回滚业务消息，不让对话接口因此失败。

用户关掉某一类偏好后，服务端不再为该类组包。静音群组在发送前再次判断，避免偏好接口与静音列表不一致。

## 10. 验收

1. 本机权限仍是「未询问」时，登录进入工作台就弹出系统权限框，不必先打开「我的」。点拒绝后，这次和以后进入都不再自动弹。应用开着时，协作新消息与本人 Run 终态仍能出顶部通知；未允许通知时，划掉应用后通知栏没有新条目。
2. 从主屏幕打开已安装的 PWA，在权限框点允许。划掉应用后：其他成员在群里发言，通知栏出现一条，标题为群名；同一群再来一条时替换前一条。点通知进入该群对话。iOS 须在主屏幕图标内验证，系统浏览器里的普通标签页不算通过。
3. 本人发起的 Run 在应用已关掉时成功、失败或进入等待审批，通知栏各出现对应标题的一条。本人在对话页里自己取消的 Run 不出现。点「有待确认的操作」进入该对话，发起人能点「允许本次」或「拒绝」，页面不出现「此操作需在电脑端确认」。允许后任务继续；拒绝后对话里写明「已拒绝本次操作」。其他人看不到这两个按钮。
4. 本人发起的 Run 成功后，本人只收到「任务已完成」，不额外收到「协作新消息」。同群其他成员只收到协作新消息，不收到任务结果。
5. 静音群组有新发言时，双方都不收到顶部通知和系统通知；列表里的未读数字仍按协作模式现有规则变化。
6. 应用开着且正在看这条对话时，不出现顶部条，也不进通知栏。应用开着但停在别的页时，只出顶部条，通知栏不重复一条。
7. 关掉「协作新消息」后，新的协作消息两种通道都没有；「任务完成提醒」仍有效。关掉「任务完成提醒」后三种任务状态都不再通知。重新打开后恢复。换一台已登录的手机，这两个偏好与上一台一致。
8. 退出登录后，该手机不再收到这个账号的推送。另一个仍登录的设备不受影响。
9. 拒绝通知权限后，开关为关，并有「请在系统设置中允许通知」。再次进入应用不弹权限框。前台顶部通知仍可用。
10. PC 工作台不出现订阅入口，行为与改前一致。微信内打开的页面在划掉后不要求出现系统通知。

## 11. PC 员工工作台增量（2026-10-29）

移动能力由 `dsh-work-mobile` 交付；**本仓库 `apps/workbench-web` 面向 PC 浏览器**，与移动共用 §8 接口与 §4 发送规则。

| 项 | PC 行为 |
| --- | --- |
| 订阅与 OS 通知 | 用户在 **用户中心** 打开「系统通知」并允许浏览器权限后登记 Push；标签页在后台或浏览器最小化时由 Service Worker 展示系统通知 |
| 权限弹框 | **不在**登录进入工作台时自动弹出（需用户手势）；移动/PWA 仍按 §2.1 自动询问 |
| 应用内顶部条 | 标签页在前台且当前不在目标对话时出现（§6 同逻辑）；宽屏条居中显示 |
| 无 Push 退路 | 标签页可见时仍靠 SSE / 60s 拉 `conversation-targets` 与 Run 终态检测出顶部条（§6.1） |
| 管理端 | 仍不做订阅 |

验收：PC Chrome/Edge 生产构建下，允许通知后切走标签页，协作消息与本人 Run 终态出现 OS 通知；前台仍在其它页时出现顶部条。
