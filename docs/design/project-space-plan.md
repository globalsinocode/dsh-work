# 项目空间方案

**状态：** 产品决策已确认（2026-10-17），待实施；分两个切片交付（第 7 节）。实施完成前，[功能规则第 3 节](../development/feature-rules.md#3-团队工作空间)仍描述现行行为，本文内容不得当作已支持能力。<br>
**更新日期：** 2026-10-17<br>
**范围：** 员工端团队空间的产品定位、命名、项目简报、项目任务、团队成果与项目档案。个人空间不变。

## 1. 为什么要改

团队空间现在是“共享讨论 + @Agent + 共享文件”，形态接近“群聊 + @机器人 + 网盘”：没有共同目标，Agent 拿不到项目上下文，没有分工，成果散落在讨论里。

新定位：**项目空间是人与 Agent 协同完成一个项目的地方。** 主线为：

```
项目简报 → 项目任务（员工或 Agent 承接）→ 团队成果 → 项目档案（档案员自动维护）
```

## 2. 已确认的决策

| # | 决策 |
| --- | --- |
| D1 | **命名：** 界面上“团队空间”改为“项目空间”。代码、表、接口继续使用 workspace（`kind = team`），不改名。 |
| D2 | **一个项目空间就是一个项目：** 空间内不再分子项目；截止时间与结项可选，长期运营型团队可以一直进行。结项沿用现有归档（3.6 语义不变）。 |
| D3 | **协作节奏：** 以异步项目任务为主，讨论中 @Agent 为辅。@Agent 仅用于临时问答（3.4 规则不变），回复不自动成为成果。 |
| D4 | **Agent 以独立 Principal 承接工作：** `executed_as` 为 Agent Principal，数据范围 = 发起员工权限 ∩ Agent 授权（代码已如此）。 |
| D5 | **被指派的 Agent 默认读取项目上下文：** 项目简报、项目档案、任务中指定的项目文件。不默认读取其他共享文件、讨论消息或成员私有内容。 |
| D6 | **恢复团队成果：** 项目任务完成后产出直接成为团队成果，全体成员可见；**不设审核环节**。 |
| D7 | **项目档案由默认“项目档案员”系统 Agent 自动维护**，人工修改优先且可回退（第 6 节）。 |
| D8 | **不做过度设计：** 首版只做下文列出的字段与状态；Agent 之间仍无委派，任务依赖由人编排。 |

## 3. 项目简报

- 空间的一个属性：目标、背景、范围与约束等自由文本，外加可选截止时间。
- 负责人与管理员可编辑，每次保存生成新版本（记录编辑人与时间）；成员和只读成员可读。
- 项目任务启动时固定当时的简报版本，与文件引用一样可追溯。

## 4. 项目任务

术语注意：平台已有执行层的 Task（`tasks` 表，对应 Run/Attempt）。本文的“项目任务”是业务层的工作项，实现时命名需区分（例如 `project_tasks`），不复用或改写执行层 Task。

**字段（首版）：** 标题、说明、指派人、承接者（一位员工成员或一个 Agent 成员）、引用的项目文件（固定版本）、可选截止时间。

**状态：**

- 员工承接：待办 → 进行中 → 已完成。
- Agent 承接：待办 → 进行中 → 已完成 / 执行失败；执行失败可重试（新 Attempt），也可改派。

**权限：** 成员及以上可创建、指派和编辑自己创建的任务；负责人与管理员可管理全部任务；只读成员只读。与现有“@Agent 发起执行”权限一致。

**Agent 任务的执行：**

- 每个 Agent 任务对应一个团队可见的任务会话，经既有 Run/Attempt → Runtime Adapter → DSH 执行，不启用无 Session 入口，不另建执行循环。
- 发起员工为指派人；数据范围 = 指派人当前权限 ∩ Agent 授权。执行前复核（A2）另加：指派人仍是现任非只读成员、Agent 成员仍可用。不满足时阻止启动，在途 Run 按 3.8 收敛。
- 输入：任务标题与说明 + 固定版本的简报 + 当前档案版本 + 指定文件。遵守现有文件数量与解析文本预算。
- 完成判定以持久化证据为准（`task-result/v1`），模型自述完成不算。

## 5. 团队成果

- 项目任务完成即登记为团队成果，在“成果”页签对全部成员可见，标注任务、承接者（员工或 Agent 及版本）与指派人。
- 员工承接的任务由承接者提交成果（上传文件或填写说明）后完成。
- 讨论中 @Agent 的回复可由成员手动“转为成果”，关联到一个已有或新建的项目任务。
- 读取仍按当前权限复核；归档后只读保留。

## 6. 项目档案与项目档案员

**项目档案：** 精选后的项目知识（已采纳结论、关键决策、术语、当前进展），不是文件集合。每次变更生成新版本，记录来源（档案员的哪次运行、基于哪些成果，或哪位成员手动编辑）。

**项目档案员：**

| 项 | 规则 |
| --- | --- |
| 形态 | 平台内置系统 Agent，每个项目空间默认挂载，不占负责人手动添加的 Agent 名额；负责人可停用，停用后档案改为人工维护。 |
| 触发 | 项目任务完成后触发；同一空间同时只有一个运行，期间完成的任务合并到下一次处理。 |
| 执行载体 | 每个空间一个“档案维护”会话，经 Run/Attempt → DSH，不启用无 Session 入口。 |
| 数据范围 | 以触发任务的指派人为发起员工：指派人权限 ∩ 档案员授权。只读本空间的简报、当前档案与新完成的成果，不授予企业数据工具。 |
| 写入 | 只经平台工具提交新档案版本，不直接改写；每次变更写入最近动态。 |
| 人工兜底 | 负责人与管理员可直接编辑或回退到任一版本。人工修改优先：档案员下次运行以最新人工版本为基础，不覆盖人工内容。 |
| 不做 | 不读取讨论消息、不读取任务未引用的共享文件、不主动给成员发消息。 |

**风险说明：** 成果不审核、档案自动更新、Agent 默认读取档案三者叠加，会让一次错误产出被当作项目事实传播。控制手段是档案版本化、变更进入动态、人工修改优先与一键回退；如实际使用中错误传播明显，再评估增加“档案变更确认”。

档案员按[通用 Agent 全生命周期模板](../development/agent-lifecycle-template.md)单独记录定义与扩展决策：MCP、持久化等待、记忆、无 Session 入口均不启用。

## 8. 不变的约束

- 所有 Agent 执行经 DSH；DSH 不可用时明确报告，不降级。
- Agent 之间无委派；档案员由平台在任务完成后触发，不是被其他 Agent 派发。
- 跨空间输入、执行前复核、读取复核当前权限、收权覆盖整条链路（3.8）均适用于项目任务与档案员。
- 空间角色不扩大员工的企业数据权限；Agent 能力不随加入空间扩大。
