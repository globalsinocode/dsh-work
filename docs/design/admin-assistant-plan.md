# 管理助手交互方案

> 2026-09 批次 4 增量：现有 Agent 草稿的展示文案采用一次最终确认；其余管理变更保留本文的委派/最终两次确认。字段白名单与服务器边界以 [C6 规则与证据](../development/review-c6-evidence.md) 为准。


**状态：** 交互方案已经管理员确认；通用 DSH 对话、任务提案、专用助手调度以及 Agent/Runtime 二次确认计划已进入实现。当前代码已接线，仍需在配置测试 PostgreSQL 与真实 DSH 的环境完成端到端验收后才能视为可发布。Skill 安装继续复用既有实现。见 [实现与验收](admin-skill-installation-implementation.md)。
**范围：** 统一管理端普通对话入口，识别管理员意图后调度 Skill、Agent 或平台运维专用助手。普通问答不执行变更；启动具体任务前必须由管理员确认。

## 0. 本轮交互决策

管理助手默认为普通对话，不要求管理员预先选择 Skill、Agent 或运维模式。每条输入先在当前管理身份、权限和数据范围内判断：

1. 查询、解释和诊断类请求由管理助手直接回复，不展示执行确认。
2. 识别到具体管理任务时，先展示任务摘要、将调用的专用助手、预计读取/写入及影响范围。
3. 管理员确认后才创建对应 Run/Attempt 并调用专用助手；取消时不启动任务。
4. 专用助手只进行受控检查和生成结构化执行计划。如计划包含平台写入，还要展示确切差异并再次确认；安装 Skill 现有“确认安装计划”作为该第二层确认。
5. 确认、取消、执行结果和失败作为持久化对话消息返回，不仅使用短暂通知。

| 意图 | 专用助手 / Runtime purpose | 当前状态 |
| --- | --- | --- |
| 普通对话与意图识别 | `admin-assistant` | DSH 后端已接线；只读查询使用受控状态工具 |
| 安装已有 Skill | `admin-skill-install` | 第一次确认后调度；安装计划仍需第二次确认 |
| 调整 Agent 草稿或状态 | `admin-agent-manage` | 第一次确认后调度；精确配置差异需第二次确认 |
| Runtime 或调度运维 | `admin-platform-operations` | 第一次确认后调度；精确配置差异需第二次确认 |

意图识别由 `admin-assistant` 的 DSH Agent Loop 完成，不在浏览器维护关键词路由。平台根据不可变 Runtime Manifest 暴露 `inspect_admin_state` 与 `propose_admin_task`；任务提案、专用助手操作计划分别绑定 SHA-256 摘要，并在两次确认及最终写入时重新鉴权。

## 1. 入口与页面分工

- 侧栏「概览」分组新增「管理助手」，独立路由 `/assistant`，复用管理端壳层和页面标题。
- 「新增 Skill」页签仅保留 ZIP 上传，删除其中独立的对话安装区域和模式切换。链接、`npx`、`curl` 输入统一进入管理助手。
- Skill 与工具、Agent 管理、Runtime 管理、系统健康页面提供「交给管理助手」；ZIP 页提供「前往管理助手」。通过 `context=skills|agents|operations` 带入业务领域，不自动发送或执行请求。
- 原列表、详情和确定性管理操作继续保留；不为各业务页面创建平行的对话助手。
- Skill 的包格式、来源适配与版本规则见 [Skill 安装方案](skill-installation-plan.md)。

## 2. 已确认的交互设计

全局左侧导航栏在「安全与运维」之后紧接同级的「对话记录」，复用其他一级目录的布局和展开/收起交互，不固定在底部、不单独滚动。仅列出已发送过消息的历史对话标题，不提供「新对话」入口，空白对话不进入历史；点击记录返回管理助手并恢复对应对话。管理助手内容区仅保留当前对话和输入区，不再设置独立历史侧栏。首次进入提供普通问答、Skill 管理、Agent 管理和平台运维四个示例入口，点击后只填写输入框，不自动发送或调用专用助手。

| 任务 | 对话行为 | 示例 |
| --- | --- | --- |
| 查询 | 展示结果、异常和前往业务页面的入口，不要求执行确认 | Skill 发布状态、Agent 配置状态、平台健康及连接超时 |
| Skill 安装 | 接收已有来源，展示包信息、依赖与权限，再确认安装 | 外部链接、`npx` 和 `curl` 输入；与 ZIP 复用包预览组件 |
| Agent 管理 | 准备配置变更并展示差异，确认后保存草稿；发布独立处理 | 采购分析助手的职责、Skill、可见角色和数据范围 |
| 平台运维 | 确认具体对象、前后状态与影响，再执行受控操作 | Runtime 排空：停止接收新任务，活动任务继续 |

- 调用提案与具体变更计划分为两张持久化卡片；前者确认专用助手调度，后者确认精确平台写入，不使用“演示执行”。
- 取消后不复用该卡片执行。近期对话可切换，消息、Run、任务提案、操作计划及结果均由服务端恢复。
- 对话历史在当前管理员身份变化时重置，不在浏览器持久化来源和命令文本。
- 输入支持 Ctrl/Command + Enter，中文输入组合期间不提交。页面和卡片支持键盘导航。
- 窄窗口复用全局移动导航展示对话记录，选择记录后关闭导航，保持消息区与发送入口可达；此页面不继承管理端旧列表的固定最小宽度。ZIP 页同样使用局部响应式规则；其他旧列表不在本轮调整范围。

## 3. 权限与能力边界

- 管理助手路由及侧栏沿用 `adminRead`；只读账号可体验查询，不显示变更确认按钮。提交变更或确认既有卡片时再次检查管理写权限。
- Skill 仅安装已有内容，不通过对话新建、编写或改写 Skill；无来源时引导提供链接/命令或使用 ZIP，不生成替代包。
- `npx`、`curl` 只作为既有 Skill 来源语法解析，不提供任意 Shell；来源安全检查和兼容性计划继续由平台安装工具负责。
- Agent 草稿、发布、Skill 版本和 Runtime 状态均须由平台持久化并审计。外部包、命令和助手文本不能替代管理员权限或变更确认。
- 真实对话必须复用现有 Run/Attempt → Runtime Adapter → DSH，平台实现受控工具；不直接调用模型、不新建第二套 Agent Loop。DSH 不可用时助手明确报告不可用，传统运维页面继续按权限提供确定性操作。

## 4. 当前实现与后端边界

前端实现位置为 [管理助手页面](../../apps/admin-web/src/views/AdminAssistantView.vue) 和 [前端对话状态](../../apps/admin-web/src/stores/admin-assistant.ts)；服务端入口为 `AdminAssistantService`。普通问答、意图理解和专用助手都复用 Run/Attempt → Runtime Adapter → DSH。平台工具只查询安全摘要、持久化提案或持久化计划，不在 DSH 工具调用时直接执行 Agent/Runtime 写入。

任务调用确认后创建独立、可审计的专用 Run。Agent 草稿更新、Agent 状态更新及 Runtime 配置更新复用既有领域服务；确认时校验计划摘要、Run 成功状态、管理员写权限及目标当前状态。操作计划保存 Agent 配置指纹或 Runtime 配置 revision，领域服务在持有目标行写锁后再次原子比较；状态已经变化时拒绝旧计划，不自动重试。Skill 安装沿用包计划摘要、原子保存、严格试运行与独立发布边界。

计划进入 `executing` 后如果服务退出，启动恢复会重新读取目标状态：与计划后状态完全一致时收敛为 `executed`；仍为计划前状态或出现第三种状态时收敛为 `failed` 并写入持久化对话消息，要求管理员重新核对。恢复只判定结果，不自动重放管理写入。

## 5. 实现验收

1. 首次进入可看到普通问答、Skill 管理、Agent 管理和平台运维四个示例；点击只填写输入框。
2. 普通问答创建 `admin-assistant` Run，可按权限读取平台安全摘要，不出现执行确认卡。
3. 识别到管理任务后，展示任务、将调用的专用助手、管理员原始请求和预计影响；确认前不创建专用 Run。
4. Skill 安装调用确认后进入既有真实 DSH 检查链路，生成安装计划后仍需点击「确认安装计划」；取消调用时不执行。
5. Agent 管理和平台运维在第一次确认后由专用助手生成结构化差异，第二次确认后才调用现有领域服务；只读管理员可普通对话和查看提案，不能确认专用助手或写入计划。
6. 既有 Skill 安装预览、计划摘要绑定、幂等重试、取消、严格试运行和发布边界不因本轮交互更新而弱化。

发布前还需在测试 PostgreSQL 中运行迁移及集成套件，并以真实 DSH 分别验收普通查询、三类提案、两层确认、取消、撤权、状态漂移和服务重启恢复。测试替身已覆盖行锁内 revision/指纹比较，以及重启时“未写入”和“已写入”两种收敛分支；这不替代真实 DSH 与目标环境验收。DSH 不可用时保持明确失败，不使用本地关键词回复或直接模型调用作为生产降级路线。
