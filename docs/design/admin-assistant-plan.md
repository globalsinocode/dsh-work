# 管理助手交互方案

**状态：** 前端交互已确认，Skill 对话安装已接入真实后端；Agent 管理及运维尚未接入。见 [实现与验收](admin-skill-installation-implementation.md)。
**范围：** 统一管理端对话入口，覆盖 Skill 管理、Agent 管理和平台运维。当前通过 DSH 和平台工具执行 Skill 安装，其余领域不返回模拟成功结果。

## 1. 入口与页面分工

- 侧栏「概览」分组新增「管理助手」，独立路由 `/assistant`，复用管理端壳层和页面标题。
- 「新增 Skill」页签仅保留 ZIP 上传，删除其中独立的对话安装区域和模式切换。链接、`npx`、`curl` 输入统一进入管理助手。
- Skill 与工具、Agent 管理、Runtime 管理、系统健康页面提供「交给管理助手」；ZIP 页提供「前往管理助手」。通过 `context=skills|agents|operations` 带入业务领域，不自动发送或执行请求。
- 原列表、详情和确定性管理操作继续保留；不为各业务页面创建平行的对话助手。
- Skill 的包格式、来源适配与版本规则见 [Skill 安装方案](skill-installation-plan.md)。

## 2. 已确认的交互设计（前端预览基线）

全局左侧导航栏在「安全与运维」之后紧接同级的「对话记录」，复用其他一级目录的布局和展开/收起交互，不固定在底部、不单独滚动。仅列出已发送过消息的历史对话标题，不提供「新对话」入口，空白对话不进入历史；点击记录返回管理助手并恢复对应对话。管理助手内容区仅保留当前对话和输入区，不再设置独立历史侧栏。首次进入提供三个领域的示例入口，点击后填写输入框，用户发送后进入对应流程。

| 任务 | 对话行为 | 当前预览样例 |
| --- | --- | --- |
| 查询 | 展示结果、异常和前往业务页面的入口，不要求执行确认 | Skill 发布状态、Agent 配置状态、平台健康及连接超时 |
| Skill 安装 | 接收已有来源，展示包信息、依赖与权限，再确认安装 | 外部链接、`npx` 和 `curl` 输入；与 ZIP 复用包预览组件 |
| Agent 管理 | 准备配置变更并展示差异，确认后保存草稿；发布独立处理 | 采购分析助手的职责、Skill、可见角色和数据范围 |
| 平台运维 | 确认具体对象、前后状态与影响，再执行受控操作 | Runtime 排空：停止接收新任务，活动任务继续 |

- 变更卡片显示「待确认」，提供「取消操作」「确认执行（演示）」；结果明确标记未修改平台数据。
- 取消后不复用该卡片执行。近期对话可切换，并保留各自输入和待确认卡片；当前仅保存在内存，刷新后清空。
- 对话历史在当前管理员身份变化时重置，不在浏览器持久化来源和命令文本。
- 输入支持 Ctrl/Command + Enter，中文输入组合期间不提交。页面和卡片支持键盘导航。
- 窄窗口复用全局移动导航展示对话记录，选择记录后关闭导航，保持消息区与发送入口可达；此页面不继承管理端旧列表的固定最小宽度。ZIP 页同样使用局部响应式规则；其他旧列表不在本轮调整范围。

## 3. 权限与能力边界

- 管理助手路由及侧栏沿用 `adminRead`；只读账号可体验查询，不显示变更确认按钮。提交变更或确认既有卡片时再次检查管理写权限。
- Skill 仅安装已有内容，不通过对话新建、编写或改写 Skill；无来源时引导提供链接/命令或使用 ZIP，不生成替代包。
- `npx`、`curl` 为待适配的来源输入，不提供任意 Shell。前端识别样式只是交互演示，不能作为后端命令安全检查或兼容性证明。
- Agent 草稿、发布、Skill 版本和 Runtime 状态均须由平台持久化并审计。外部包、命令和助手文本不能替代管理员权限或变更确认。
- 真实对话必须复用现有 Run/Attempt → Runtime Adapter → DSH，平台实现受控工具；不直接调用模型、不新建第二套 Agent Loop。DSH 不可用时助手明确报告不可用，传统运维页面继续按权限提供确定性操作。

## 4. 前端预览阶段边界（历史基线）

实现位置为 [管理助手页面](../../apps/admin-web/src/views/AdminAssistantView.vue) 和 [前端演示状态](../../apps/admin-web/src/stores/admin-assistant.ts)。演示使用固定样例回复、配置差异及状态，不连接安装或治理 API、不调用模型、不执行命令、不获取外部来源。示例内容不代表当前对象或平台状态；查看实际管理页面须通过明确链接跳转。

上述描述为已结束的前端预览阶段。本轮确认后已增加 Skill 安装 API、持久化、来源适配与 Runtime 工具接线；其他治理能力尚未开发。当前能力以实现文档为准。

## 5. 已确认的交互验收

1. 侧栏可进入管理助手，三个领域入口均可操作；业务页面转入正确领域，不自动发起任务。
2. 「新增 Skill」仅有 ZIP 上传，无独立对话模式；ZIP 和助手安装卡使用相同包内容预览。
3. 查询直接展示示例结果；变更先展示对象、差异/依赖和影响，能确认或取消，结果不冒充真实执行。
4. 「安全与运维」下方的同级「对话记录」可展开、收起，从其他业务页选择历史可返回对应对话；切换保留输入与待确认状态；只读用户及中途撤销写权限后不能确认变更。
5. 缺少来源、请求编写 Skill、组合命令都给出明确引导；不产生已安装记录。
6. 类型、UI 契约、lint、构建及交互测试通过；浏览器检查导航、窄窗口、查询、确认/取消、返回业务页与 ZIP 入口。

确认后的开发顺序：核实 DSH 受控工具能力 → 定义管理对话与运行契约 → 实现按权限查询 → 安装核心与 Skill 工具 → Agent 草稿及受控运维工具 → 持久化恢复、审计和真实链路验收。具体工具清单和变更风险规则在后端设计阶段细化，不将当前固定样例回复作为生产备用执行逻辑。
