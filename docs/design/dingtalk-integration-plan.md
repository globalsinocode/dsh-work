# 钉钉接入方案（移动协同与消息通知）

**状态：** 待评审，尚未实施。本文所述能力在实施并通过第 9 节验收前均不可用。<br>
**更新日期：** 2026-10-26<br>
**依据：** 现有站内通知（迁移 0026、0096）、协作模式壳层 `CollabShell` 窄屏布局、[移动端接入规范](../development/mobile-integration-guide.md)、[功能规则 3.7 与第 8 节](../development/feature-rules.md)、[Mac mini 部署手册](../release/mac-mini-deployment-runbook.md)；钉钉开放平台公开文档（接口名与配额以实施时官方文档为准，见第 8 节）。

## 1. 背景与目标

协作模式（B）已有窄屏布局（820px 以下底部标签栏 + “列表 → 聊天”两级），也有 H5 接入规范，但移动协同仍不可用，原因有两个：

- **收不到提醒。** 通知仅站内（功能规则 3.7），员工不打开网页就不知道有人 @ 了自己、任务完成或需要处理；
- **手机打不开。** 部署为内网 IP + 自签根证书，部署手册禁止公网转发，手机走蜂窝网络无法访问。

目标：员工在钉钉里及时收到与自己相关的提醒，点开后在钉钉内直接进入对应页面继续协作；平台的身份、权限、业务状态与 Agent 执行链路保持不变。

## 3. 边界

- **钉钉只是渠道，不是执行器。** 任何从钉钉发起的 Agent 交互都必须创建 Session/Run，经 Run/Attempt → Runtime Adapter → DSH 执行；钉钉适配层不调用模型、不实现工具循环（[AGENTS.md](../../AGENTS.md)）。
- **权限仍由平台裁决。** 推送前、点击后都按现行规则检查可见权限；钉钉侧的群、部门或角色不授予任何平台权限。
- **管理端不上公网。** 公网入口只暴露员工端的页面、`/api/workbench/v1` 与 `/auth/workbench`；管理端（4180）、服务端口与数据库保持内网。
- **不改桌面端登录。** 账号密码与 AI Hub 登录保持原样；钉钉免登只在钉钉客户端内生效（4.3）。
- **不做群机器人 Webhook 推送。** 群 Webhook 无法按人做权限检查，所有提醒发给具体员工本人。

## 4. 分阶段方案

### 4.1 阶段 1：钉钉工作通知

**触发事件（首批）：**

| 事件 | 接收人 | 现状 |
| --- | --- | --- |
| 项目任务指派给我 / 改派给我 | 被指派员工 | 已有 `project_task_events`（`reassigned` 等） |
| 我发起的项目任务完成 | 任务创建人 | 已有 `project_task_events.completed` |
| 我的定时任务执行完成或失败 | 任务所有者 | 已有执行记录；需改功能规则第 8 节“不新增外部通知” |
| 我发起的长时间 Run 完成或失败 | Run 发起人 | 由 Run 终态驱动，需新增投递触发点；仅在发起人离开页面后推送（见 8.4） |
| 对话或评论中 @ 我 | 被 @ 的员工 | **未实现**（项目空间方案 D13、D29 列为下一步），随 @ 功能一起交付 |

**消息内容：** 使用钉钉工作通知的卡片或链接消息，只放“谁、在哪个项目/对话、做了什么”和一个跳转链接，例如“张三在『Q4 投放复盘』给你指派了一个任务”。不放消息正文、Agent 回复、文件名以外的文件内容和成果摘要。名称在发送时按接收人当前可见性读取，不使用事件发生时的快照。

**投递链路：**

1. 业务事务内写入事件（沿用现有持久化事件，必要时补充事件类型），同一事务写入投递记录 `external_notification_deliveries`，状态 `pending`；
2. 单进程投递器（与定时任务一致，单一所有者）领取 `pending` 记录，**发送前复核**：接收人账号有效、仍有对象可见权限、未静音该空间或该类事件、绑定有效；任一不满足记为 `skipped` 并写原因；
3. 调用钉钉工作通知接口发送，成功记 `sent` 并保存钉钉任务 ID；可重试错误按退避重试，超过上限记 `failed`（死信），不再重试；
4. 投递失败不影响业务结果，也不回滚站内通知（沿用 3.7“通知失败不把已成功的业务变更报成失败”）。

去重键为 `(tenant_id, channel, recipient_user_id, source_event_id)`，重放与重启不会重复发送。同一接收人短时间内的同类事件可合并为一条（例如 5 分钟内 3 个任务被指派给你），合并窗口为可配置项。

**员工偏好：** 员工端个人设置增加“钉钉通知”开关与事件类型选择，默认开启首批事件；沿用按空间静音，静音的空间不推送。

**站内跳转：** 链接指向员工端公网地址的稳定路由（项目空间方案已规定链接与 A/B 模式无关），在钉钉内打开时走 4.3 免登；在系统浏览器打开时走现有登录。

### 4.2 账号匹配（手机号）

**现状：** `users` 表没有手机号字段；AI Hub 目录同步只带 `email`；独立账号的登录标识可以是手机号，但它是登录名，不是经过核对的联系方式。

**方案：**

- `users` 新增 `mobile`（E.164 规范化存储，唯一约束为 `(tenant_id, mobile)`，允许为空）。来源为管理端“员工与权限”由管理员维护或批量导入；AI Hub 目录若将来提供手机号，按目录同步覆盖并标记来源。**员工不能自助修改手机号。**
- 匹配：管理员触发或定时任务调用钉钉“根据手机号查询用户”接口，得到钉钉 `userid`，写入 `dingtalk_user_bindings`（`user_id`、`dingtalk_user_id`、`dingtalk_union_id`、`matched_mobile`、`status`、`matched_at`、`confirmed_at`），两侧各自唯一。
- 绑定分两级：
  - **已匹配：** 手机号查到唯一钉钉用户即可接收工作通知；
  - **已确认：** 员工在桌面端员工设置中点击“绑定钉钉”，服务端经工作通知向已匹配的钉钉用户发送一次性验证码（短时有效、限次尝试），员工在桌面端输入后确认。该过程同时证明平台身份（已登录桌面端）与钉钉身份（收到验证码），不依赖公网登录，独立账号与 AI Hub 账号都适用。只有已确认的绑定才允许免登（4.3）。
- 失效：平台手机号变更、账号停用、钉钉侧查不到该手机号（离职后接口不再返回）或返回的 `userid` 变化时，绑定置为失效，停止推送并要求重新确认；每次变更写审计。
- 冲突：同一手机号对应多个平台账号（唯一约束阻止写入）或钉钉返回异常时不绑定，在管理端列出待处理项。

**为什么要“已确认”：** 手机号录错时，已匹配只会让对方收到少量名称级提醒；若直接允许免登，录错就等于把整个账号交给他人。

### 4.3 阶段 2：钉钉工作台入口与免登

- **公网入口：** 员工端使用独立域名（例如 `m.<企业域名>`）+ 受信证书，经反向代理只转发员工端页面、`/api/workbench/`、`/auth/workbench/`；按[移动端接入规范](../development/mobile-integration-guide.md) §2 把该 origin 加入 `DSH_WORK_WORKBENCH_ORIGINS`。现有配置要求该列表中所有 origin 与 `DSH_WORK_WORKBENCH_PORT`（默认 4174）同端口（`server/src/modules/identity/config.ts`），公网入口若用 443 会启动失败。二选一：公网入口同样使用 4174 端口；或放宽为按 origin 分别校验端口（改动身份配置，需补测试）。公网暴露前补充登录限流核对、访问日志与告警，是否加 WAF 或网关白名单由部署方决定。
- **钉钉应用：** 在钉钉开放平台创建企业内部应用，配置 H5 微应用首页为公网入口的协作模式（B）首页，并申请通讯录手机号查询、工作通知、免登等最小权限。
- **免登：** 页面在钉钉容器内用 JSAPI 获取一次性授权码 → 新增 `POST /auth/workbench/dingtalk/login`，服务端用授权码换取钉钉 `userid` → 查已确认绑定 → 签发现有员工端 Session Cookie。绑定未确认时提示先在桌面端完成 4.2 的确认（独立账号员工也可在钉钉内直接用账号密码登录）；不存在绑定时提示联系管理员，不自动建账号。
- **身份语义：** 免登签发的是同一平台账号的会话，不新增账号类型；登录方式写入审计（`login_method = dingtalk`）。收权、停用、Session 撤销沿用现有机制。
- **移动端规范调整：** 现行规范写明“认证优先使用平台独立账号、不集成 AI Hub”。钉钉免登作为钉钉容器内的附加方式写入该规范，规范的其余约束不变。

### 4.4 阶段 3：钉钉机器人对话（待单独设计）

员工在钉钉单聊里给 AI 同事发消息，平台回复结果。接入采用钉钉 Stream 模式（服务端主动建立 WebSocket 连接，不需要公网回调地址）。本阶段只列约束，不在本方案内设计：

- 每条入站消息按已确认绑定识别员工，映射到该员工与目标 Agent 的对话，创建 Run，经 DSH 执行；回复通过消息卡片更新返回；
- 属于新的对话入口，按 [Agent 全生命周期模板](../development/agent-lifecycle-template.md)记录入口、身份、权限与披露策略；回复内容出站即不可收回，需另定可回传到钉钉的内容范围；
- 群聊 @ 机器人涉及群成员与平台权限不一致，首版不做。

## 5. 数据与接口草案

| 对象 | 说明 |
| --- | --- |
| `users.mobile` | 管理员维护的手机号，E.164，租户内唯一 |
| `dingtalk_user_bindings` | 平台账号与钉钉用户绑定，状态：已匹配 / 已确认 / 失效 |
| `external_notification_deliveries` | 投递记录：来源事件、接收人、渠道、状态（pending / sent / skipped / failed）、尝试次数、下次尝试时间、跳过或失败原因、钉钉任务 ID |
| `user_notification_preferences` | 员工渠道开关与事件类型选择 |
| `POST /auth/workbench/dingtalk/login` | 钉钉容器内免登 |
| 管理端“钉钉集成”页 | 应用凭据状态、匹配进度、待处理冲突、投递失败列表 |

钉钉应用凭据（AppKey/AppSecret）与其他密钥一样只进 `.env` 或受管 Secret Manager，不入库、不进 Git。端口按[内部端口与契约](../development/internal-ports.md)新增 `ExternalNotificationChannel`，钉钉为第一种实现；测试替身只用于测试。

## 8. 待评审确认的默认值与风险

1. **钉钉接口与配额：** 根据手机号查询用户只能查到在职员工；工作通知有每人每天条数与同内容去重限制。具体接口路径、权限点、限频与配额在 DT-S1 开始前按钉钉开放平台最新文档核对，并据此确定合并窗口和每人每日上限。
2. **服务器出站：** 投递器与 Stream 连接需要访问钉钉开放平台；若内网有出站白名单，需放行对应域名。
3. **公网暴露的安全基线：** 员工端上公网后登录接口暴露在外，需确认限流阈值、是否要求钉钉内访问以外的来源也能登录、是否加 IP 或网关控制。
4. **Run 完成提醒的条件：** 默认仅在 Run 运行超过一定时长（建议 2 分钟）且发起人当前没有打开该对话时推送，避免和页面内结果重复；判断依据需实现时确定。
5. **手机号来源：** 首次启用需要管理员批量导入手机号；导入错误的影响由 4.2 的两级绑定控制。
6. **任务与对话标题：** 标题可能含业务内容，默认不出现在外部消息中（只写“一个任务”）；如需显示，需单独确认并写入功能规则 3.7。

## 9. 验收

- **P0：** 冒烟服务提供测试身份与内存数据，钉钉渠道使用测试替身，验证员工通知设置页面与管理端集成页可用；
- **P1：** 专用 PostgreSQL + 钉钉渠道测试替身，覆盖投递去重、发送前复核（收权后不推送）、静音、失败不影响业务、绑定失效与重新确认、免登拒绝未确认绑定；
- **P2：** 真实钉钉企业内部应用、真实手机号匹配、真实工作通知送达与钉钉内免登跳转，按发布流程留证。测试替身与 P0/P1 绿灯不能代替 P2。
