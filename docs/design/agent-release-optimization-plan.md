## 1. 目标与约束

让管理员用更少的步骤、在更接近生产的条件下验证 Agent，并在发布前看清“改了什么、验证了什么”；发布证据只记录已核实的事实。

必须遵守：

1. 试运行与生产执行唯一经过 Run/Attempt → Runtime Adapter → DSH，不新增第二套 Agent Loop，不在前端或业务后端直连模型。
2. 已发布版本、Attempt Manifest、试运行证据不可覆盖；修改受影响内容使旧证据失效。
3. 按 2026-09-20“不考虑历史兼容”决策清理旧状态与旧入口，不保留双读或兼容分支；不清空数据库，不删除已有版本、执行和成果。
4. 身份、文件来源和执行授权检查不因本计划放宽（见[功能规则第 1 节](../development/feature-rules.md#1-跨功能约束)）。
5. 每阶段按 AGENTS.md 的 Spec → Code → Verify → Test → Green 推进；P0/P1/P2 证据分层记录，不互相替代。

## 2. 现行流程与已完成的修复

当前流程：三步弹窗创建草稿（`0.1.0`，自动创建独立执行身份）→ 发布工作台设置员工可见角色 → 五类案例逐项运行，每项经 DSH 执行后人工判定 → 一次确认发布，事务内复核修订、指纹、绑定、授权、MCP 范围与数据集合。

应保留的能力：草稿与发布版本分离；指纹加修订使旧证据失效；锁顺序统一；机器断言不能被人工覆盖；审核页展示完整回答；`setStatus` 不能绕过工作台；数据平面在试运行中返回 `trial_only`。

`96e797d` 已完成的修复（隔离 PostgreSQL 发布治理集成 27/27、Runtime/策略/授权单测 258/258、管理端单测 138/138；未运行浏览器 E2E 与 P2）：

| 问题 | 实际处理 |
| --- | --- |
| 管理员判定两处口径不一（F-04） | 授权、Agent、发布三处共用 `requirePlatformAdminActor`：本地授予、角色启用、在有效期内、租户有效 |
| 回滚会重新启用已停用 Agent 并停用草稿（F-03） | 事务内锁定 Agent 并比较活动版本；不改 `agents.status`，不停用草稿，拒绝回滚到当前版本 |
| 发布范围有两个写入方（F-05） | `PATCH /agents/draft` 必须回传 `expectedRevision`，服务端沿用当前发布范围，过期修订返回 409 |
| 未填意见时代写“业务效果已确认”（F-06） | 留空不写 `business_accepted`；输入框改为“业务确认意见（选填）”并说明后果 |
| Runtime 兼容检查夸大事实（F-07） | 文案改为“授权范围兼容；DSH 执行能力与模型能力要求在试运行派发时校验” |
| 改写过的生成案例仍标为生成（F-08） | 内容与生成时完全一致才保留 `generated`，改写即清除 |
| 只改可见角色也要重跑全部案例（F-09） | 可见角色移出定义指纹，平台数据上限仍计入 |
| 试运行的审批、写入、工具集、超时与生产不同（F-01/F-02 的一部分） | 使用 Agent 自身审批模式、`workspace_only`、与生产相同的工具集（含委派、记忆）和超时，等待时长为 Attempt 超时加 60 秒；需审批的动作直接拒绝，不建审批等待；MCP 调用返回 `trial_only`；委派拒绝；数据与记忆沿用 `trial_only` |
| 新版本丢失改写过的案例 | 新版本候选按类型沿用上一次发布时改写过的案例 |
| 服务重启后试运行卡在执行中 | 启动时把 checking/queued/executing 的试运行标为“服务重启中断”，asserting 保留 |

存量影响：可见角色移出指纹后，进行中的候选在下次读取时推进一次修订，已通过但未发布的试运行需重跑一次。

## 3. 仍存在的问题

### 3.1 试运行仍不代表线上行为

| 编号 | 问题 | 依据 | 影响 |
| --- | --- | --- | --- |
| G-01 | 试运行与员工执行各有一份 Manifest 组装，靠注释维持一致 | `run/orchestration/release-trial-entry.ts` 与 `attempt-dispatcher.ts` | 新增字段很容易只改一处，差异会重新出现 |
| G-02 | 试运行的知识上下文固定为空，没有记忆上下文 | 同上，试运行 `knowledge_context: []` | 依赖知识库或经验的 Agent 在试运行中行为与线上不同 |
| G-03 | 案例只有文本输入，不能挂载文件；工作空间为空 | 同上，`file_mounts: []`、`workspace_id: ''` | 处理文件、修改成果的 Agent 无法验证 |
| G-04 | 试运行只用 Agent 自身授权，不与员工披露上限求交 | `resolveAgentPrincipalTrialScope` | “越权请求”案例测不到员工侧边界 |
| G-05 | MCP 调用在试运行中一律返回 `trial_only`，只读调用同样不执行 | DSH 策略对 `agent-release-trial` 的处理 | 依赖 MCP 的 Agent，“正常任务”案例实际上没有运行核心能力，却可以判为通过 |

G-05 的根因是 MCP 能力没有读写分类：平台工具和 DSH 内置工具已经声明 `effect: read/write`，MCP 能力只登记名称、说明和输入 Schema。MCP 协议的 `readOnlyHint` 由服务方自报，不能作为隔离依据。

### 3.2 流程与体验

- 一轮通过需 22 次点击、5 次串行等待；任一项失败须从第一项重来。
- 试运行在 HTTP 请求内同步执行（`startTrial` 等待 `executeTrialSteps` 完成），单个案例最长占用请求“Attempt 超时 + 60 秒”。
- 封存候选后草稿不能再改：草稿指纹一变，后续案例全部失败并要求从第一项重来。
- 授权分散在三处：编辑弹窗、管理页抽屉（执行身份）、工作台（发布范围），缺授权时需离开工作台处理。
- 页面暴露 rev、封存修订、Principal、绑定修订、DSH Lock 等内部术语。
- `submitted`/`changes_requested` 已无进入路径，ZIP 相关字段与检查仍在代码中。

## 4. 目标设计

1. **试运行与生产共用一个 Manifest 构造函数。** 试运行只通过“试运行环境配置”覆盖三项：执行身份（选定测试角色作为员工披露上限）、外部效果隔离、工作空间与输入文件来源（测试空间和案例附件）。知识、记忆、工具集、审批、写入策略和限额全部与生产一致。环境配置及其摘要写入 Attempt 和证据。
2. **外部效果按能力的读写分类隔离。** 平台写工具、可写数据集合、委派在试运行中返回 `trial_only` 或拒绝（已实现）。MCP 能力在 Connector 审核时由管理员逐项标注只读或写入，标注纳入能力摘要；只读能力在试运行中真实执行，写入能力返回 `trial_only`。未标注的能力按写入处理。
3. **验证期间冻结候选副本。** 开始验证时把草稿定义复制为一条不可变的候选版本，试运行和发布都引用这条副本；之后编辑草稿不影响进行中的验证，只提示“草稿与待发布内容不同”。不新增快照、评测套件或发布指针实体；案例继续随候选保存，并按类型沿用上一次发布时的改写。
4. **试运行后台执行。** HTTP 只受理并返回，案例作为后台 Run 执行，前端沿用进度轮询；同一候选内其余案例可并行（可配置先跑“正常任务”），全部完成后统一判定；只重跑失败项时保留全部尝试并显示次数。
5. **发布属性与定义分离。** 可见范围在发布确认步骤设置，不进入定义指纹；`dataScopes` 上限仍计入。
6. **写入型 Agent 加严门禁。** 有写入能力（平台写工具、可写集合、标注为写入的 MCP 能力）的 Agent 增加专项写入案例与外部效果隔离证据，是否要求配置人与审核人分离见 D-2。基础文本 Agent 维持五类案例加一人审核。

统一 Agent 详情页（左侧“配置 → 试一试 → 验证 → 发布”、右侧发布就绪度面板、草稿临时对话转案例）作为独立的界面项目，见 AR-08。可点击原型 [agent-release-flow.html](prototypes/agent-release-flow.html) 按修订前的设计绘制，其中“定义快照与发布指针”已不采用，“第二审核人”待 D-2 决定；用于确认交互，不作为实现依据。

### AR-02 试运行与生产对齐

### AR-04 可见范围移到发布确认步骤

### AR-05 后台试运行与并行案例

- 受理即返回，案例作为后台 Run 执行，进度沿用现有轮询；启动收敛补充“底层 Run 已终态则补记结果”。
- 同一候选内可并行运行其余案例，并发受 D-5 的试运行容量规则约束；取消对全部在途案例生效。
- **验证：** 集成覆盖重启收敛、并行容量、取消与交互任务不被挤占；P0 进度展示回归。

### AR-06 验证期间冻结候选副本

- 开始验证时复制草稿定义为不可变候选版本；试运行、证据和发布都引用该副本；发布使该副本成为活动版本。
- 编辑草稿不再使进行中的验证失败；草稿与候选不同时在工作台提示，并允许“以当前草稿重新开始验证”。
- 删除依赖草稿指纹追踪的候选修订推进、rebind/refresh 与 GET 页面触发的同步。
- **验证：** 发布治理集成覆盖验证中编辑草稿、并发发布、回滚到旧版本；P1 浏览器旅程。

### AR-07 MCP 能力读写标注与写入型 Agent 门禁

- Connector 审核界面逐项标注 MCP 能力为只读或写入，未标注视为写入；标注纳入能力摘要，能力变化后需重新标注。
- DSH 策略在试运行中只放行标注为只读的 MCP 能力（替换现行的一律 `trial_only`）。
- 按能力自动判定写入型 Agent；写入型增加专项写入案例与外部效果隔离证据，按 D-2 决定是否要求审核人与配置人不同。
- 在 AR-07 完成前，发布确认页对使用 MCP 的 Agent 标明“MCP 能力未在试运行中执行”。
- **验证：** Connector 治理集成覆盖标注、摘要变化与重新标注；Runtime 策略单测覆盖只读放行、写入隔离与未标注拒绝；P2 在本地可丢弃 MCP 上复核。

### AR-08 统一 Agent 详情页

合并为单一 Agent 详情页与发布就绪度面板，提供“试一试”临时对话及“对话转为案例”。管理端导航变化同步 `e2e/TEST-CATALOG.md` 与相关 spec；验证运行全量 `pnpm test:e2e`。开工前单独评审范围。
