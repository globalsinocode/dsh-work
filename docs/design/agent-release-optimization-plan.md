## 1. 目标与约束

让管理员用更少的步骤、在更接近生产的条件下验证 Agent，并在发布前看清“改了什么、验证了什么”；同时让发布证据如实反映已核实的事实。

必须遵守：

1. 试运行与生产执行继续唯一经过 Run/Attempt → Runtime Adapter → DSH，不新增第二套 Agent Loop，不在前端或业务后端直连模型。
2. 已发布版本、Attempt Manifest、试运行证据不可覆盖；修改受影响内容使旧证据失效。
3. 按 2026-09-20“不考虑历史兼容”决策清理旧状态与旧入口，不保留双读或兼容分支；不授权清空数据库或删除已有版本、执行和成果。
4. 身份、文件来源和执行授权检查不因本计划放宽；安全修复批次的共同门槛同样适用。
5. 每阶段按 AGENTS.md 的 Spec → Code → Verify → Test → Green 推进；P0/P1/P2 证据分层记录，不互相替代。

## 2. 现状与已确认问题

当前流程：三步弹窗创建草稿（`0.1.0`，独立执行身份自动创建）→ 发布工作台设置员工可见角色 → 五类案例逐项运行，每项经 DSH 执行后人工确认 → 一次确认发布，事务内复核修订、指纹、绑定、授权、MCP 范围与数据集合。

已具备且应保留的能力：草稿与发布版本分离；指纹 + 修订使旧证据失效；锁顺序统一；机器断言不可被人工覆盖；审核页展示完整回答；`setStatus` 不能绕过工作台；数据平面在试运行中返回 `trial_only`。

### 2.3 流程与体验（预演确认）

- 一轮通过需 22 次点击、5 次串行等待；任一项失败须从第一项重来。
- 授权分散在三处：编辑弹窗、管理页抽屉（执行身份）、工作台（发布范围），缺授权时需离开工作台处理。
- 页面暴露 rev、封存修订、Principal、绑定修订、DSH Lock 等内部术语；发布确认页看不出本次变化。
- 试运行在 HTTP 请求内同步执行，进程中断后试运行停在 `executing`，无启动收敛，只能手动取消。
- 新版本的候选重新生成默认案例，上一版本改写过的案例不保留。
- `submitted` 状态已无进入路径，ZIP 相关字段与检查仍在代码中。
- 另：`scripts/testing/admin-mcp-connector-browser.ts` 把临时目录字符串传入发布服务的编排参数，该夹具中试运行无法执行。

## 3. 目标设计

### 3.1 对象与流程

```text
可编辑草稿 ──开始验证时冻结──▶ 定义快照（内容 hash，不可变）
                                   │
                 评测套件（独立资产，版本化）+ 试运行环境配置（hash）
                                   │
                                   ▼
                     评测运行（后台任务，经 DSH 执行，汇总后人工判定）
                                   │ 门禁：hash 完全一致的通过记录
                                   ▼
             发布指针：Agent 当前版本 → 快照；可见范围/灰度/启停为独立属性
```

1. **冻结快照取代可变草稿的指纹追踪**：草稿随意编辑；开始验证时冻结定义、精确依赖与绑定修订；发布即指针指向快照。后续编辑草稿不作废任何证据，仅提示“草稿与待发布快照不同”。可删除 submission 修订推进、rebind/refresh、GET 页面触发的同步及 `submitted`/`changes_requested`/`withdrawn`。
2. **评测套件独立成资产**：归属 Agent、版本化、跨版本复用，形成回归；修改案例输入即清除 `generated` 标记，门禁可要求业务相关案例已改写。
3. **后台批量执行**：评测运行作为无 Session Task（复用 PF-01），按 Runtime 容量并行，完成后统一判定；可选“先跑正常任务再并行其余”控制成本；允许只重跑失败项但保留全部尝试并显示次数。
4. **试运行与生产共用 Manifest 构造**：仅通过环境配置覆盖试运行身份（选定测试角色作为披露上限）与外部效果隔离（MCP 与平台写工具默认 `trial_only` 或指向测试 Connector）；写入策略、审批、超时、工具集与生产一致。
5. **发布属性与定义分离**：可见范围、灰度和启停在发布指针上，不进入快照 hash；`dataScopes` 上限仍在快照中。回滚只移动指针，保持启停状态与草稿。
6. **按风险分级的门禁**：基础文本 Agent 维持五类评测 + 一人审核；有写入能力（平台写工具、可写集合、带写工具的 MCP）的增加专项写入案例、外部效果隔离证据和配置人与审核人分离。

### 3.2 管理端交互

合并为单一 Agent 详情页：左侧生命周期导航「配置 → 试一试 → 验证 → 发布」，右侧常驻“发布就绪度”面板，每个阻塞项附修复入口；主按钮随状态给出下一步；技术标识统一收进“技术详情”。新建后可先基于草稿进行临时对话（同一 DSH 链路，不作为证据），并可把对话转为评测案例。

可点击原型：[agent-release-flow.html](prototypes/agent-release-flow.html)（浏览器直接打开；示例数据、不连接后端，默认采用第 5 节建议选项）。提供两个场景：A 新建基础文本 Agent；B 已发布 Agent 创建含写入型 MCP 的新版本（就地补授权、改写生成案例、冻结后修改草稿、第二审核人、回滚保持状态）。原型用于确认流程，不是实现代码，也不是验收证据。

- 工作台内直接编辑执行身份授权（复用 `updateAgentPrincipal`），保存后自动复查；平台数据范围去掉自由输入，仅列平台登记范围。
- 草稿变化后由系统自动同步候选，去掉“候选同步完成前不能操作”提示。
- 编辑器：“权限与运行限制”改为“高级：受控委派”并新增运行限制展示；示例问题移到第 1 步并说明其为第一条案例的默认输入。
- 删除 `submitted`/`changes_requested` 状态处理、退回修改入口、ZIP 字段与检查（`source`、`packageRefs`、`filesCheck`、`packageWarnings`）及“旧版评测证据”提示；需迁移收紧状态约束（不回填历史）。
- 发布页“撤回候选”改为“放弃本次发布准备”并说明保留内容；列表操作列合并为“状态 + 下一步”。
- **验证：** 更新 AG-REL-01、AG-SOUL-01 旅程；组件单测；P0 spec；P1 `test:e2e:agent-principal`。

### AR-04 发布属性与定义分离

- 可见角色移出定义指纹，作为发布属性单独审计；变更可见范围不作废试运行证据；`dataScopes` 仍计入指纹。
- 可见范围设置移到发布确认步骤，试运行前不再要求选择角色（`audience` 检查从试运行前移到发布事务）。
- 为后续灰度预留：发布属性可按角色分批扩大，旧会话不静默切换版本。
- **验证：** 集成：改可见范围不重跑、改数据上限仍须重跑；发布事务复核角色有效性；P0 旅程调整。

### AR-05 后台试运行与启动收敛

- 试运行改为后台 Task，HTTP 只受理并返回；前端沿用现有进度轮询。
- 启动时收敛遗留 `checking/queued/executing` 试运行：底层 Run 已终态则补记结果，否则标记中断并允许重新开始。
- 允许同一修订内并行运行其余案例（可配置先跑正常任务），统一判定；如允许只重跑失败项，记录全部尝试并在审核页展示次数。
- **验证：** 集成覆盖重启收敛、并行容量与取消；Runtime 容量与交互任务保留不受影响；P0 进度展示回归。

### AR-06 冻结快照与独立评测套件

- 新增定义快照（内容 hash）、评测套件版本与评测运行实体；发布指针引用快照；移除 submission 修订与草稿指纹追踪逻辑。
- 评测套件跨版本复用，修改即清除 `generated` 标记；门禁可配置要求业务相关案例非生成（D-3）。
- 回滚移动发布指针；版本导出改为从快照导出。
- **验证：** 新契约同步生产者/消费者与 OpenAPI；发布治理集成重写；P1 浏览器旅程；不做历史兼容。

### AR-07 风险分级门禁与统一详情页

- 按能力自动判定风险等级，写入型 Agent 增加专项写入案例、隔离证据与审核人分离（D-2）。
- 合并为 Agent 详情页 + 发布就绪度面板；“试一试”临时对话及“对话转为案例”。
- 更新员工端壳层无关；管理端导航变化同步 `e2e/TEST-CATALOG.md` 与相关 spec。
- **验证：** 全量 `pnpm test:e2e`；P1 隔离旅程；P2 按发布流程在真实 DSH/OIDC 留证。
