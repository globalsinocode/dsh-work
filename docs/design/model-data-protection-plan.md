## 1. 背景与目标

员工使用 Agent 时，公司的隐私与机密信息会随请求发给外部模型厂商：员工输入、上传与工作区文件、知识库检索结果、MCP 与工具返回、Python 执行输出、群组与项目空间的历史消息。后几类由 DSH 在 Agent Loop 中直接拼进上下文，平台在 Run 入口或 Adapter 事件处都看不到。

目标：**发往外部模型厂商的请求中不出现密钥、个人信息与企业机密词的原值**，且不影响员工正常使用。

- 识别出的值在请求中替换为占位符，厂商回复（含流式与工具调用参数）中的占位符还原为原值，DSH 与员工看到的始终是原值；
- 员工本条消息中含密钥时，消息不发送给模型，员工可修改后重新发送；
- 每个请求的处理结果可审计，审计中不出现原值；
- 策略按 Provider 信任级别区分。

## 2. 已确认决策（2026-11-05、2026-11-06）

| 编号 | 决策 |
| --- | --- |
| D1 | 模型网关从模型路由方案第 7 节**提前立项**，作为数据防护的前提。网关只做认证、转发、计量与数据防护，不承担任何 Agent 执行逻辑 |
| D2 | WeKnora 改用**内网部署的嵌入模型**，知识库文档不出内网，不经网关脱敏（另立事项，见 6.3） |
| D3 | 保密词表第一期由**管理员手工维护**（CSV 导入、检测试用、单独授权查看与编辑），不做自动同步 |
| D4 | Provider 信任级别只分两级：**内部部署 / 外部厂商**，不区分境内与境外 |
| D5 | 外部厂商：**密钥拦截**（拦截范围见 D10），个人信息与保密词表**遮盖**；内部部署：不处理 |
| D6 | 图片与扫描件：外部厂商**放行并记录**，第一期不拦截、不做 OCR；内部部署放行 |
| D7 | 员工端：**遮盖不提示**；拦截时说明被拦截的**类别**，不显示具体值 |
| D8 | 审计只记录类别、次数、处理方式，**不保存原值，也不保存原值的哈希或上下文** |
| D9 | **任何路由都不允许绕过网关**；DeepSeek 统一以 `openai-completions` 经 pi-ai 接入（模型路由方案 R4） |
| D10 | **拦截只作用于员工本条消息正文**：命中密钥则不创建运行，消息标记为“未发送给模型”，此后不进入会话历史。上传文件、历史消息、工具结果、执行中读取的文件里出现的密钥一律**遮盖**，不拦截 |
| D11 | **第一期简化**（2026-11-06）：不做策略版本，网关按请求时的当前词表处理；不做管理员自定义规则；不保留跨请求的已识别值集合；租户密钥不分版本 |
| D12 | **联网搜索经网关并遮盖**（2026-11-06）：`web_search` 插件的 `baseURL` 指向网关、`apiKeyEnv` 指向 Attempt 令牌；网关为 DeepSeek 的 Anthropic 兼容搜索接口（`/anthropic/v1/messages`）做透传，搜索请求按与模型请求相同的策略遮盖与审计。只为这一个接口提供透传，不等于开放 `anthropic-messages` 路由类型。**补充（2026-11-07）：** 搜索使用默认路由 Provider 的平台密钥，只在默认路由的 Provider 是 DeepSeek 官方（`base_url` 为 `https://api.deepseek.com`）时可用，网关只放行插件的搜索模型 `deepseek-v4-flash`；默认路由不是 DeepSeek 官方时本轮不装配 `web_search`，Manifest 以 `unavailable_tools` 记录，运行说明告知模型不可用 |

D10 的理由：平台每一轮都会把会话历史随 Manifest 重新发给模型（[attempt-dispatcher.ts](../../server/src/modules/run/orchestration/attempt-dispatcher.ts) 的 `conversation_history`、Adapter 的 `renderUserPrompt`），审批后恢复还会携带已完成的工具结果。若在网关按请求拦截，一条含密钥的历史消息会让此后每一轮都失败，而历史与工具结果中的内容员工无法移除。

## 3. 边界

- **不是内容合规审核。** 本方案不判断输入或输出是否违规，也不拦截模型展示给员工的内容。
- **执行职责不变。** 模型调用仍由 DSH 发起；网关是请求转发路径上的平台组件，不运行模型循环、不改写对话结构、不做协议互转（[AGENTS.md](../../AGENTS.md)、[总览 3.5](../development/overview.md#35-agent-执行引擎统一)）。输入预检（5.6.1）是 Run 创建前的同步判定，不调用模型。
- **识别不调用模型。** 第一期只用内置规则与保密词表，不在平台侧调用 LLM 做识别；本地 NER 模型与自定义规则留待评估（第 8 节）。
- **不做 Attempt 内路由切换。** 网关只转发到本 Attempt 路由快照中的模型，延续模型路由方案第 2 节与 4.7 的失败语义。
- **内部部署模型不处理。** 数据不出企业网络，脱敏只会损失回答质量（D5）。
- **图片不识别。** 文本规则无法覆盖图片与扫描件，第一期只记录（D6）。
- **已发出的原值无法收回。** 遮盖只对之后的请求生效；词表更新前已经发出的内容不在本方案能力范围内。

### 4.1 DLP-S0 探针结论（2026-11-06）

在本机 DSH `0.1.2-rc.1`（`76fda72979`）上以 `--profile acp --patch <探针 patch>` 启动，patch 声明 pi-ai 路由 `dshw-probe`（`api: openai-completions`、`compat.thinkingFormat: deepseek`、显式 `retryPolicy`），`baseURL` 指向探针网关，`apiKeyEnv` 指向进程环境中的令牌变量，`settings.path` 指向独立文件。探针网关分两种：记录请求并返回固定流式回复的假网关；记录请求后原样转发到 DeepSeek 官方的透传网关（凭据由 DSH 按引用解析，探针不读取密钥值）。探针脚本保存在会话 scratchpad，未进入仓库。

| # | 问题 | 结论 |
| --- | --- | --- |
| 1 | pi-ai 能否指向网关 | **能。** 本轮全部模型请求都发到 `baseURL`，令牌以 `Authorization: Bearer` 发送；`session/new` 的 `currentValue` 为 `["dshw-probe", <模型>]` |
| 2 | 用 `openai-completions` 接 DeepSeek（R4） | **可行。** `deepseek-v4-pro` 经透传网关完成一轮“思考 → 调用 `read` 工具 → 回答”：默认开启思考（返回推理内容与 `reasoning_tokens`），工具调用参数按流式片段拼接正确，下一次请求原样带回上一轮的 `reasoning_content` 与 `tool_calls`，DeepSeek 返回 200。DeepSeek 模型须设置 `compat.thinkingFormat: deepseek`（pi-ai 支持路由级默认与模型级覆盖，平台按模型设置，见模型路由方案 4.3） |
| 3 | 思考内容经网关 | DSH 在下一次请求中把上一轮的 `reasoning_content` **逐字原样回传**，网关可以按 5.4 对思考内容双向透传、不做改动。探针网关没有做遮盖，占位符在思考内容中的往返由 DLP-S2 的 P1 用例验证。Anthropic 思考块签名未验证（该协议首批不开放） |
| 4 | 4xx 与 429 的重试 | 探针设置 `retryPolicy: { mode: normal, maxRetries: 2 }`，重试码沿用默认集合（空回复、限流、服务端错误、超时、传输错误）：403、400 **只请求 1 次、不重试**；429、500 各请求 3 次（1 次 + 2 次重试）。408 未验证。平台生成路由时应显式设置 `retryableCodes`（模型路由方案 4.3），不依赖默认值 |
| 5 | 拒绝如何到达 Adapter | ACP 返回 JSON-RPC 错误 `-32603`，消息为 `turn failed: <状态码>: <响应体 JSON>`，网关响应体中的 `code` 原样保留。Adapter 仍以网关记录为准分类、不解析 DSH 错误文本，记录缺失时按 Runtime 不可用处理（5.2、模型路由方案 4.7）；错误文本中保留 `code` 只便于排障 |
| 6 | DSH 以外的出口 | dsh-work 服务端、前端与脚本没有直接调用模型 API 的代码。DSH 侧唯一绕过网关的出口是 `web_search`：它本身就是一次模型调用（见第 4 节），搜索词以原文发给 DeepSeek，凭据在 `DSH_HOME`。MR-S2 上线后 `DSH_HOME` 不再保存厂商密钥，`web_search` 将不可用。可选做法：**(a) 经网关**：把插件 `baseURL` 指向网关、`apiKeyEnv` 指向 Attempt 令牌，网关为这一个 Anthropic 兼容的搜索接口做透传与遮盖（搜索词同样按策略处理），不等于开放 `anthropic-messages` 路由类型；**(b) 停用联网搜索**。保留单独的搜索凭据、让搜索词绕过网关违反 D9 与 D5，**不作为选项**。已决定按 (a) 实施（D12）。其余：子 Agent 默认模型（`agent-default-model: deepseek-official`）因平台不放行子 Agent 工具而不可达；`session-title-llm` 在 ACP 配置中已停用；上下文压缩沿用会话当前路由，不是绕过；启动检查与两条探测路径只到 `session/new`，不发出模型请求 |
| 7 | 缓存用量字段 | DeepSeek 同时返回 `prompt_tokens_details.cached_tokens` 与 `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens`，两者一致（第二次请求命中 8448 / 8600） |

## 5. 方案

### 5.1 执行链路

```text
员工提交消息 ── 输入预检（本轮将使用的路由为 external 时）
        │       消息正文含密钥 → 不创建 Run，消息标记“未发送给模型”
        ▼
Attempt Dispatcher ── 路由快照（含 trust_level）── Manifest
        │
Runtime Adapter ── 签发 Attempt 短期令牌 ── 生成 patch：baseURL=网关，apiKeyEnv=令牌变量
        ▼
DSH Worker ──请求──> 模型网关
  1. 校验令牌与模型：租户、Run、Attempt、路由与模型必须一致，过期或越权即拒绝
  2. 按快照中的 trust_level 与当前词表处理：
       internal → 原样转发
       external → 密钥、个人信息、保密词表命中值全部替换为占位符
  3. 用平台保存的厂商密钥转发；记录用量与数据防护审计
厂商回复（流式） ──> 网关还原占位符（思考内容除外，见 5.4） ──> DSH
```

### 5.2 模型网关（最小范围）

- **形态：** 第一期作为现有 Node.js 模块化单体中的独立模块与独立监听端口，只对本机或执行网络开放；是否拆为独立进程按容量与故障域证据另行评审（[总览第 11 节](../development/overview.md#11-生产演进原则)）。
- **令牌：** Adapter 为每个 Attempt 签发短期令牌，绑定租户、Run、Attempt、路由与模型，Attempt 终态即失效。DSH 只持有该令牌，不再持有厂商密钥。
- **厂商密钥：** 复用平台加密凭据（`postgres-encrypted` 后端，见模型路由方案 4.5；与 MCP Bearer Token 同一机制，[总览第 9 节](../development/overview.md#9-身份安全与数据边界)），明文只在网关转发时解析，不进入 Manifest、patch、日志或 API 响应。
- **只转发、不改造：** 网关保持厂商协议原样，只替换文本内容中的敏感值；不做协议互转、不做回退。
- **拒绝的传递与重试：** 网关拒绝以 HTTP 403 返回，响应体为厂商兼容的错误结构，`code` 取 5.6.2 的错误码，并带响应头 `x-dshw-origin: gateway`，与厂商透传的 403 区分（模型路由方案 4.7）。平台为 pi-ai 路由显式设置的 `retryPolicy`（模型路由方案 4.3）不重试这类 4xx（DLP-S0 已确认 403、400 只请求一次，4.1）。Attempt 失败时，Adapter 以网关对该 Attempt 的请求记录为准映射错误码，不依赖 DSH 错误文本（模型路由方案 4.7）。
- **计量：** 网关按请求记录 token 用量（含缓存读写，模型路由方案 4.6）；`effective_model` 以网关实际转发的模型为准。

### 5.3 识别范围

| 类别 | 占位符前缀 | 内容 | 识别方式 |
| --- | --- | --- | --- |
| 密钥（`secret`） | `SECRET` | 常见厂商 API Key 前缀、私钥块、JWT、Bearer Token、连接串与配置中的密码，以及“密码为 / 密钥是 / token:”等中英文字段表述 | 内置的前缀与结构规则、字段名上下文 |
| 个人信息（`personal`） | `PERSONAL` | 手机号、身份证号（校验位）、银行卡号（Luhn 校验）、邮箱 | 内置规则加校验，减少误报 |
| 保密词表（`term`） | `TERM` | 项目代号、客户名、产品内部名、内部域名与 IP 段等 | 管理员维护的词表（D3），可选区分大小写与整词匹配 |

第一期不提供管理员自定义正则或前缀规则（D11）；词表覆盖不到的格式化机密（如内部工号格式）以后按需增加。

误报控制（借鉴 magpie 的经验）：

- UUID、长十六进制串、内容摘要、缓存键等标识符**整体不参与匹配**，避免把其中的片段误判为手机号或卡号；
- 匹配有边界要求：值两侧不能紧贴字母或数字；
- 白名单：管理员可放行特定值（整值匹配，不区分大小写）。

### 5.4 遮盖与还原

**占位符**

- 格式为 `{{<占位符前缀>_<10 位短码>}}`，例如配置中“密码为 Abc#2026x”的值遮盖为 `{{SECRET_k3v9x2mq7d}}`，客户名遮盖为 `{{TERM_p8w2c6ze4n}}`。
- 短码取租户数据防护密钥对原值做 HMAC-SHA256 的结果，按 base32 截取 10 位（50 比特）：同一值在任何请求中都得到同一占位符，与请求、轮次无关，对话历史逐轮一致，厂商侧提示词缓存不失效。
- **碰撞：** 同一请求内若两个不同值得到相同短码，网关拒绝转发（`DATA_POLICY_UNAVAILABLE`）并告警。50 比特下该情形预期不会出现，出现即视为缺陷处理。
- **租户密钥：** 由环境主密钥按租户派生（HKDF，信息字段含租户 id），不单独存储，不分版本（D11）。轮换环境主密钥即轮换全部租户密钥，影响仅是提示词缓存失效一次。

**识别与替换**

- **请求内全文遮盖：** 先在请求的全部文本（系统提示、各轮消息、工具调用参数与结果、工具定义的说明文字）上收集命中值，再统一替换。一个值只要在任一位置被识别（包括依赖上下文识别的，如上例中“密码为”之后的值），它在该请求的所有出现位置都遮盖，不论周围文字是否还能触发规则。
- **每个请求独立识别：** 网关不在请求之间保留已识别值（D11）。DSH 每轮重发完整上下文，只要触发识别的文字还在上下文中，值就会被识别；上下文被压缩后可能漏报，残余风险见第 8 节。
- **词表变化：** 网关按请求时的当前词表处理（D11），词表更新后立即对之后的请求生效，包括进行中的 Attempt。一个值在后续请求中首次被识别时，此前已原样发出的历史在之后的请求中会变为占位符：这会使该段的提示词缓存失效，但不会造成泄露，可以接受。
- **JSON 与转义：** 网关解析请求 JSON，在解码后的字符串值上识别与替换，再重新编码，因此转义形式（如 `\"`、`\n`、`\uXXXX`）不会导致漏报。工具调用参数本身是 JSON 字符串时，在解码后的参数文本上处理。

**还原**

- 厂商回复中的占位符还原为原值后再交给 DSH，覆盖流式文本与工具调用参数。占位符只由字母、数字、下划线和花括号组成，在 JSON 字符串中无需转义，可在流式片段中直接匹配；还原写回 JSON 字符串时，对原值按 JSON 规则转义。
- 流式还原保留尾部一段（不超过最长占位符长度）再放行，避免占位符被拆在两个片段之间。
- **思考内容原样透传：** 厂商返回的思考内容（推理文本、Anthropic thinking 块及其签名）**不还原**，DSH 下一次请求带回时网关也**不再遮盖**，双向保持厂商生成时的原文。思考内容由厂商生成，原样回传不会泄露原值；这样签名始终与文本一致。
- **未知占位符：** 回复中出现本请求映射之外的占位符形式时原样保留，不猜测。
- **原文本身含占位符形式的文本**时先转义，保证还原不会误替换。
- **告知模型：** 外部厂商的运行在系统提示里加一段固定说明：占位符代表真实值，照常使用，不向用户提及（实测不说明时模型会对员工说“看到的不是真实值”，违背 D7）。
- **不持久化映射：** “占位符 → 原值”映射只在单个请求及其回复期间保存在内存中。

### 5.5 Provider 信任级别与策略

`model_providers` 增加 `trust_level`：`internal`（内部部署）/ `external`（外部厂商），新建 Provider 必须选择，默认不填不允许保存。存量 Provider 迁移为 `external`，由管理员确认后改为 `internal`。

策略（D5、D6、D10）：

| 类别 | `internal` | `external`：输入预检（本条消息正文） | `external`：网关（全部请求） |
| --- | --- | --- | --- |
| 密钥 | 放行 | **拦截** | 遮盖 |
| 个人信息 | 放行 | 放行 | 遮盖 |
| 保密词表 | 放行 | 放行 | 遮盖 |
| 图片与扫描件 | 放行 | 放行 | 放行并记录 |

- 策略矩阵为固定规则，不做版本（D11）；可变的只有保密词表与白名单，保存后即对之后的请求生效。
- Dispatcher 解析路由时把 `trust_level` 写入路由快照（模型路由方案 4.2）；PF-04 恢复沿用来源 Attempt 的快照，重试随路由重新解析。

### 5.6 拦截与失败语义

#### 5.6.1 输入预检

- **位置：** 员工可直接输入内容的入口在创建 Run 之前调用，包括新对话与会话续聊、项目空间任务、群组中 @AI 同事、钉钉消息；定时任务在保存提示词时预检，每次触发时再预检一次。系统入口（会话摘要、项目归档、发布试运行）处理的是已经过预检的内容，不再重复预检。
- **范围：** 只检查本条消息正文（D10）。本轮上传的文件不预检，执行中读取时由网关遮盖。
- **条件：** 只在本轮将使用的路由 `trust_level` 为 `external` 时进行；`internal` 路由不预检。
- **命中：** 不创建 Run，接口以 `DATA_POLICY_BLOCKED` 拒绝；消息保留在会话中供员工查看，标记为“未发送给模型”，之后构建会话历史时排除该消息。员工修改后重新发送即可。
- **引擎异常：** 预检失败即关闭，不创建 Run，以 `DATA_POLICY_UNAVAILABLE` 拒绝。

#### 5.6.2 网关

| 情形 | 结果 |
| --- | --- |
| 外部厂商请求中命中任一类别 | 遮盖后转发，不拦截（D10） |
| 令牌无效、过期，或令牌、请求模型与路由不符 | 403 拒绝；Attempt 以 `MODEL_ROUTE_UNAVAILABLE` 结束 |
| 识别引擎异常、短码碰撞 | **拒绝转发**（失败即关闭），403；Attempt 以 `DATA_POLICY_UNAVAILABLE` 结束；不得降级为不脱敏直发 |
| 网关不可用 | Attempt 失败，沿用 Runtime 不可用的错误分类；不得回退为 DSH 直连厂商 |

`DATA_POLICY_UNAVAILABLE` 不自动重试；拒绝如何传到 Adapter 见 5.2。

### 5.7 员工端提示（D7）

- 遮盖对员工无感，对话中不显示提示。
- 输入预检拦截时，消息下方显示固定说明：“这条消息包含 **<类别>**，按公司数据防护策略未发送给模型。请删除后重新发送。”类别取 5.3 的名称（如“密钥”），不显示具体值或位置。被拦截的消息带“未发送给模型”标记。
- `DATA_POLICY_UNAVAILABLE` 时显示“数据防护暂时不可用，本轮未发送给模型”，不显示内部原因。

### 5.8 词表管理（管理端）

- 新增“数据防护”管理页：保密词表、白名单、Provider 信任级别概览、命中统计；先出可点击原型，确认后再开发。
- 词表本身是机密，查看与编辑需要单独的权限，不默认授予所有管理员。
- 词表支持 CSV 导入，条数与单条长度设上限；提供“检测试用”：输入一段文本，显示会被如何处理（只在管理端本地展示，不写入审计）。
- 保存即生效，对之后的请求使用新词表（D11）；变更记入管理操作审计（谁在何时增删了多少条，不记录词条内容）。

### 5.9 审计（D8）

- **网关：** 每个请求记录租户、用户、Run、Attempt、Provider 与模型、`trust_level`、各类别命中次数、处理方式（遮盖 / 放行）、是否含图片。
- **输入预检：** 每次拦截记录租户、用户、入口、会话、命中类别与次数。
- **不保存原值、原值哈希或原值周围的文本。** 保留期沿用平台现有审计日志。管理端运行详情可查看该 Run 的数据防护摘要。

## 8. 风险

| 风险 | 处理 |
| --- | --- |
| 遮盖降低回答质量（如分析客户名单时只能看到占位符） | 内部部署模型不处理；管理员可调整词表与白名单 |
| 误报导致正常内容被遮盖或输入被拦截 | 校验位、边界与标识符排除；白名单；检测试用 |
| 漏报：词表外的机密、无固定格式的机密、图片中的文字 | 第一期接受并在管理端说明；后续评估自定义规则、本地 NER 与内网 OCR |
| 依赖上下文识别的值，在上下文被压缩后漏报（D11 去掉了跨请求集合） | 请求内全文遮盖；员工本条消息中的密钥由输入预检拦截；残余风险第一期接受，在 P2 观察实际漏报 |
| 上传文件中的密钥只遮盖、不拦截（D10） | 网关遮盖保证不以原值发出；员工端不提示 |
| 词表变化或首次识别使已发出的历史变为占位符，提示词缓存失效 | 接受；P2 依据网关记录的缓存读写 token（模型路由方案 4.6）观察缓存命中变化 |
| 思考内容中出现原值或占位符 | 思考内容双向原样透传；它由厂商生成，不会把厂商未见过的原值带出 |
| 网关成为单点与性能瓶颈 | 识别为线性多模式匹配；网关不可用时 Attempt 明确失败，不回退直连 |
| 流式还原的切分与延迟 | 只保留不超过最长占位符长度的尾部 |
| 厂商把占位符改写（大小写、拆开） | 只还原精确形式；在 P2 中观察真实厂商的改写率 |
| DSH 升级后适配器地址、协议或错误格式变化 | 纳入 DSH 升级准入检查：网关地址、令牌变量、流式格式、4xx 错误码传递 |
