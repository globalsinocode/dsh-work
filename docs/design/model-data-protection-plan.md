# 发往模型的数据防护方案

**状态：** 决策已确认，尚未实施。本文所述能力在实施并通过第 9 节验收前均不可用。<br>
**更新日期：** 2026-11-06（按 PR 评审修订：新增 D10，密钥只拦截本轮新输入、其余位置遮盖；已识别值集合改为 Run 范围；思考内容原样透传；补充前置条件、拒绝传递、JSON 转义、短码碰撞与租户密钥、验证项）<br>
**依据：** 当前 Model 模块、Runtime Adapter 与 [模型路由方案](model-routing-plan.md)；参考开源项目 [yetone/magpie](https://github.com/yetone/magpie)（MIT）的网关脱敏设计（`internal/redact`、`internal/gateway/masked.go`），只借鉴设计，不复制代码。<br>
**关联：** [模型路由方案](model-routing-plan.md) 第 7 节（本方案将其提前立项）、[执行隔离方案](execution-isolation-plan.md) 第 10 节、[WeKnora 接入方案](weknora-knowledge-plan.md)。

## 1. 背景与目标

员工使用 Agent 时，公司的隐私与机密信息会随请求发给外部模型厂商：员工输入、上传与工作区文件、知识库检索结果、MCP 与工具返回、Python 执行输出、群组与项目空间的历史消息。后几类由 DSH 在 Agent Loop 中直接拼进上下文，平台在 Run 入口或 Adapter 事件处都看不到。

目标：**发往外部模型厂商的请求中不出现密钥、个人信息与企业机密词的原值**，且不影响员工正常使用。

- 识别出的值在请求中替换为占位符，厂商回复（含流式与工具调用参数）中的占位符还原为原值，DSH 与员工看到的始终是原值；
- 员工本轮新输入中含密钥时，消息不发送给模型，员工可修改后重新发送；
- 每个请求的处理结果可审计，审计中不出现原值；
- 策略按 Provider 信任级别区分，策略版本随 Attempt 固定。

## 2. 已确认决策（2026-11-05、2026-11-06）

| 编号 | 决策 |
| --- | --- |
| D1 | 模型网关从模型路由方案第 7 节**提前立项**，作为数据防护的前提。网关只做认证、转发、计量与数据防护，不承担任何 Agent 执行逻辑 |
| D2 | WeKnora 改用**内网部署的嵌入模型**，知识库文档不出内网，不经网关脱敏（另立事项，见 6.3） |
| D3 | 企业词表第一期由**管理员手工维护**（CSV 导入、检测试用、单独授权查看与编辑），不做自动同步 |
| D4 | Provider 信任级别只分两级：**内部部署 / 外部厂商**，不区分境内与境外 |
| D5 | 外部厂商：**密钥拦截**（拦截范围见 D10），个人信息与企业词表**遮盖**；内部部署：不处理 |
| D6 | 图片与扫描件：外部厂商**放行并记录**，第一期不拦截、不做 OCR；内部部署放行 |
| D7 | 员工端：**遮盖不提示**；拦截时说明被拦截的**类别**，不显示具体值 |
| D8 | 审计只记录类别、次数、处理方式、策略版本，**不保存原值，也不保存原值的哈希或上下文** |
| D9 | DSH 内置的 `deepseek-official` 路由若不能指向网关，改为以 `openai-completions` 经 pi-ai 接入 DeepSeek；**任何路由都不允许绕过网关** |
| D10 | **拦截只作用于员工本轮新输入**（本条消息与本轮上传的文件）：命中密钥则不创建运行，消息标记为“未发送给模型”，此后不进入会话历史。历史消息、工具结果、执行中读取的文件里出现的密钥一律**遮盖**，不拦截（2026-11-06） |

D10 的理由：平台每一轮都会把会话历史随 Manifest 重新发给模型（[attempt-dispatcher.ts](../../server/src/modules/run/orchestration/attempt-dispatcher.ts) 的 `conversation_history`、Adapter 的 `renderUserPrompt`），审批后恢复还会携带已完成的工具结果。若在网关按请求拦截，一条含密钥的历史消息会让此后每一轮都失败，而历史与工具结果中的内容员工无法移除。

## 3. 边界

- **不是内容合规审核。** 本方案不判断输入或输出是否违规，也不拦截模型展示给员工的内容。
- **执行职责不变。** 模型调用仍由 DSH 发起；网关是请求转发路径上的平台组件，不运行模型循环、不改写对话结构、不做协议互转（[AGENTS.md](../../AGENTS.md)、[总览 3.5](../development/overview.md#35-agent-执行引擎统一)）。输入预检（5.6.1）是 Run 创建前的同步判定，不调用模型。
- **识别不调用模型。** 第一期只用规则与词表，不在平台侧调用 LLM 做识别；本地 NER 模型留待评估（第 8 节）。
- **不做 Attempt 内路由切换。** 网关只转发到本 Attempt 路由快照中的模型，延续模型路由方案 2 与 4.7 的失败语义。
- **内部部署模型不处理。** 数据不出企业网络，脱敏只会损失回答质量（D5）。
- **图片不识别。** 文本规则无法覆盖图片与扫描件，第一期只记录（D6）。
- **已发出的原值无法收回。** 遮盖只对之后的请求生效；规则或词表更新前已经发出的内容不在本方案能力范围内。

## 4. 现状与缺口

| 发往模型的路径 | 现状 | 本方案处理 |
| --- | --- | --- |
| DSH → `deepseek-official`（`dsh-llm-deepseek` 适配器） | DSH 直连厂商，凭据在 `DSH_HOME` | 改指向网关；不能改则按 D9 改走 pi-ai |
| DSH → pi-ai 路由（模型路由方案 4.3） | 方案未实施 | `baseURL` 指向网关，`apiKeyEnv` 为 Attempt 短期令牌 |
| WeKnora → 在线嵌入模型 | 文档全文发往在线服务 | 改内网嵌入模型（D2） |
| 其他直接调用模型的组件 | 未盘点 | DLP-S0 盘点；发现即纳入网关或改内网 |

## 5. 方案

### 5.1 执行链路

```text
员工提交消息 ── 输入预检（本轮将使用的路由为 external 时）
        │       本条消息与本轮上传文件含密钥 → 不创建 Run，消息标记“未发送给模型”
        ▼
Attempt Dispatcher ── 路由快照（含 trust_level、策略版本）── Manifest
        │
Runtime Adapter ── 签发 Attempt 短期令牌 ── 生成 patch：baseURL=网关，apiKeyEnv=令牌变量
        ▼
DSH Worker ──请求──> 模型网关
  1. 校验令牌：租户、Run、Attempt、路由与模型必须一致，过期或越权即拒绝
  2. 按快照中的策略版本处理：
       internal → 原样转发
       external → 密钥、个人信息、企业词表、自定义规则命中值全部替换为占位符
  3. 用平台保存的厂商密钥转发；记录用量与数据防护审计
厂商回复（流式） ──> 网关还原占位符（思考内容除外，见 5.4） ──> DSH
```

### 5.2 模型网关（最小范围）

- **形态：** 第一期作为现有 Node.js 模块化单体中的独立模块与独立监听端口，只对本机或执行网络开放；是否拆为独立进程按容量与故障域证据另行评审（[总览第 11 节](../development/overview.md#11-生产演进原则)）。
- **令牌：** Adapter 为每个 Attempt 签发短期令牌，绑定租户、Run、Attempt、路由与模型，Attempt 终态即失效。DSH 只持有该令牌，不再持有厂商密钥。
- **厂商密钥：** 由平台使用环境主密钥加密保存（沿用 MCP Bearer Token 的做法，[总览第 9 节](../development/overview.md#9-身份安全与数据边界)），明文只在网关转发时解析，不进入 Manifest、patch、日志或 API 响应。`dsh-managed` 凭据后端随之退役。
- **只转发、不改造：** 网关保持厂商协议原样，只替换文本内容中的敏感值；不做协议互转、不做回退。
- **拒绝的传递与重试：** 网关拒绝以 HTTP 403 返回，响应体为厂商兼容的错误结构，`code` 取 5.6.2 的错误码。平台为 pi-ai 路由显式设置的 `retryPolicy`（模型路由方案 4.3）不重试 4xx，避免对同一拒绝反复请求；`dsh-llm-deepseek` 的重试行为由 DLP-S0 确认。Adapter 从 DSH 的首轮错误或会话日志中识别该错误码并映射为 Attempt 错误码；DSH 错误信息中能否保留 `code` 由 DLP-S0 确认，不能保留时网关另按 Attempt 记录拒绝事件，Adapter 结束时查询该事件。
- **计量：** 网关按请求记录 token 用量，与 DSH 会话日志的用量核对；`effective_model` 以网关实际转发的模型为准。

### 5.3 识别范围

| 类别 | 占位符前缀 | 内容 | 识别方式 |
| --- | --- | --- | --- |
| 密钥（`secret`） | `SECRET` | 常见厂商 API Key 前缀、私钥块、JWT、Bearer Token、连接串与配置中的密码，以及“密码为 / 密钥是 / token:”等中英文字段表述 | 前缀与结构规则、字段名上下文 |
| 个人信息（`personal`） | `PERSONAL` | 手机号、身份证号（校验位）、银行卡号（Luhn 校验）、邮箱 | 规则加校验，减少误报 |
| 企业词表（`term`） | `TERM` | 项目代号、客户名、产品内部名、内部域名与 IP 段等 | 管理员维护的词表（D3），可选区分大小写与整词匹配 |
| 自定义规则（`custom`） | `CUSTOM` | 管理员补充的前缀规则或正则规则 | 见 5.8 的校验约束 |

误报控制（借鉴 magpie 的经验）：

- UUID、长十六进制串、内容摘要、缓存键等标识符**整体不参与匹配**，避免把其中的片段误判为手机号或卡号；
- 匹配有边界要求：值两侧不能紧贴字母或数字；
- 白名单：管理员可放行特定值（整值匹配，不区分大小写）。

### 5.4 遮盖与还原

**占位符**

- 格式为 `{{<占位符前缀>_<10 位短码>}}`，例如配置中“密码为 Abc#2026x”的值遮盖为 `{{SECRET_k3v9x2mq7d}}`，客户名遮盖为 `{{TERM_p8w2c6ze4n}}`。
- 短码取租户数据防护密钥对原值做 HMAC-SHA256 的结果，按 base32 截取 10 位（50 比特）：同一值在任何请求中都得到同一占位符，与请求、轮次无关，对话历史逐轮一致，厂商侧提示词缓存不失效。
- **碰撞：** 同一请求内若两个不同值得到相同短码，网关拒绝转发（`DATA_POLICY_UNAVAILABLE`）并告警，不尝试加长或改号，以免同一值在不同请求中占位符不一致。50 比特下该情形预期不会出现，出现即视为缺陷处理。
- **租户密钥：** 由环境主密钥按租户派生（HKDF，信息字段含租户 id 与密钥版本），不单独存储明文。轮换时生成新版本，只对之后新建的 Run 生效；进行中的 Run 沿用旧版本。轮换的影响仅是提示词缓存失效。

**识别与替换**

- **请求内全文遮盖：** 先在请求的全部文本（系统提示、各轮消息、工具调用参数与结果）上收集命中值，再统一替换。一个值只要在任一位置被识别（包括依赖上下文识别的，如上例中“密码为”之后的值），它在该请求的所有出现位置都遮盖，不论周围文字是否还能触发规则。
- **Run 内已识别值集合：** 网关在内存中为每个 Run 保留已识别值集合，覆盖该 Run 的所有 Attempt（包括重试与 PF-04 恢复新建的 Attempt）；后续请求先按集合匹配，再跑规则。这样，最初触发识别的上下文被 DSH 压缩掉后，值本身仍会被遮盖。集合只在内存中，Run 终态即清除，不落盘、不进审计（与 D8 一致）；网关进程重启会丢失集合，残余风险见第 8 节。
- **历史内容可能变化：** 集合只增不减，一个值在后续请求中首次被识别时，此前已原样发出的历史在之后的请求中会变为占位符。这会使该段的提示词缓存失效，但不会造成泄露，可以接受；网关不会把已遮盖的值改回原值发送。模型自己写出的、恰好命中规则的值（如示例手机号）在下一次请求中同样会被遮盖，影响同上。
- **JSON 与转义：** 网关解析请求 JSON，在解码后的字符串值上识别与替换，再重新编码，因此转义形式（如 `\"`、`\n`、`\uXXXX`）不会导致漏报。工具调用参数本身是 JSON 字符串时，在解码后的参数文本上处理。

**还原**

- 厂商回复中的占位符还原为原值后再交给 DSH，覆盖流式文本与工具调用参数。占位符只由字母、数字、下划线和花括号组成，在 JSON 字符串中无需转义，可在流式片段中直接匹配；还原写回 JSON 字符串时，对原值按 JSON 规则转义。
- 流式还原保留尾部一段（不超过最长占位符长度）再放行，避免占位符被拆在两个片段之间。
- **思考内容原样透传：** 厂商返回的思考内容（推理文本、Anthropic thinking 块及其签名）**不还原**，DSH 下一次请求带回时网关也**不再遮盖**，双向保持厂商生成时的原文。思考内容由厂商生成，原样回传不会泄露原值；这样签名始终与文本一致。
- **未知占位符：** 回复中出现本请求映射之外的占位符形式时原样保留，不猜测。
- **原文本身含占位符形式的文本**时先转义，保证还原不会误替换。
- **不持久化映射：** “占位符 → 原值”映射只在单个请求及其回复期间保存在内存中，下一次请求由 DSH 重发的上下文与 Run 内集合重建。

### 5.5 Provider 信任级别与策略

`model_providers` 增加 `trust_level`：`internal`（内部部署）/ `external`（外部厂商），新建 Provider 必须选择，默认不填不允许保存。存量 Provider 迁移为 `external`，由管理员确认后改为 `internal`。

默认策略（D5、D6、D10）：

| 类别 | `internal` | `external`：输入预检（本轮新输入） | `external`：网关（全部请求） |
| --- | --- | --- | --- |
| 密钥 | 放行 | **拦截** | 遮盖 |
| 个人信息 | 放行 | 放行 | 遮盖 |
| 企业词表 | 放行 | 放行 | 遮盖 |
| 自定义规则 | 放行 | 按规则配置（拦截或放行，默认放行） | 遮盖 |
| 图片与扫描件 | 放行 | 放行 | 放行并记录 |

- 策略以版本发布，已发布版本不可修改；词表与规则的变更发布为新版本。
- Dispatcher 解析路由时把 `trust_level` 与当前策略版本一起写入路由快照（模型路由方案 4.2 的 `model_route` 增加 `trust_level`、`data_policy_version` 两个字段），同一 Run 的重试与恢复沿用同一版本。

### 5.6 拦截与失败语义

#### 5.6.1 输入预检

- **位置：** 员工可直接输入内容的入口在创建 Run 之前调用，包括新对话与会话续聊、项目空间任务、群组中 @AI 同事、钉钉消息；定时任务在保存提示词时预检，每次触发时再按当时策略预检一次。系统入口（会话摘要、项目归档、发布试运行）处理的是已经过预检的内容，不再重复预检。
- **范围：** 本条消息正文，以及本轮新上传、平台能解析出文本的文件（复用上传时的文本解析）；不能解析出文本的文件不在预检范围，执行中读取时由网关遮盖。
- **条件：** 只在本轮将使用的路由 `trust_level` 为 `external` 时进行；`internal` 路由不预检。
- **命中：** 不创建 Run，接口以 `DATA_POLICY_BLOCKED` 拒绝；消息保留在会话中供员工查看，标记为“未发送给模型”，之后构建会话历史时排除该消息，本轮上传的文件不挂载。员工修改后重新发送即可。
- **引擎异常：** 预检失败即关闭，不创建 Run，以 `DATA_POLICY_UNAVAILABLE` 拒绝。

#### 5.6.2 网关

| 情形 | 结果 |
| --- | --- |
| 外部厂商请求中命中任一类别 | 遮盖后转发，不拦截（D10） |
| 令牌无效、过期或与路由不符 | 403 拒绝；Attempt 以 `MODEL_ROUTE_UNAVAILABLE` 结束 |
| 识别引擎异常、短码碰撞 | **拒绝转发**（失败即关闭），403；Attempt 以 `DATA_POLICY_UNAVAILABLE` 结束；不得降级为不脱敏直发 |
| 网关不可用 | Attempt 失败，沿用 Runtime 不可用的错误分类；不得回退为 DSH 直连厂商 |

`DATA_POLICY_UNAVAILABLE` 不自动重试；拒绝如何传到 Adapter 见 5.2。

### 5.7 员工端提示（D7）

- 遮盖对员工无感，对话中不显示提示。
- 输入预检拦截时，消息下方显示固定说明：“这条消息包含 **<类别>**，按公司数据防护策略未发送给模型。请删除后重新发送。”类别取 5.3 的名称（如“密钥”），不显示具体值或位置。被拦截的消息带“未发送给模型”标记。
- `DATA_POLICY_UNAVAILABLE` 时显示“数据防护暂时不可用，本轮未发送给模型”，不显示内部原因。

### 5.8 词表与规则管理（管理端）

- 新增“数据防护”管理页：词表、自定义规则、白名单、Provider 信任级别概览、命中统计；先出可点击原型，确认后再开发。
- 词表与规则本身是机密，查看与编辑需要单独的权限，不默认授予所有管理员。
- 词表支持 CSV 导入；提供“检测试用”：输入一段文本，显示会被如何处理（只在管理端本地展示，不写入审计）。
- 规则校验：条数与长度设上限；正则须能编译、不能匹配空串；使用 RE2 语义或受限写法，防止回溯型正则拖垮网关。
- 发布：保存为草稿，发布后生成新策略版本，只对之后新建的 Run 生效。

### 5.9 审计（D8）

- **网关：** 每个请求记录租户、用户、Run、Attempt、Provider 与模型、`trust_level`、策略版本、各类别命中次数、处理方式（遮盖 / 放行）、经 Run 内集合首次遮盖的历史出现次数、是否含图片。
- **输入预检：** 每次拦截记录租户、用户、入口、会话、命中类别与次数、策略版本。
- **不保存原值、原值哈希或原值周围的文本。** 保留期沿用平台现有审计日志。管理端运行详情可查看该 Run 的数据防护摘要。

## 8. 风险

| 风险 | 处理 |
| --- | --- |
| 遮盖降低回答质量（如分析客户名单时只能看到占位符） | 内部部署模型不处理；管理员可调整词表与白名单 |
| 误报导致正常内容被遮盖或输入被拦截 | 校验位、边界与标识符排除；白名单；检测试用 |
| 漏报：词表外的机密、图片中的文字 | 第一期接受并在管理端说明；后续评估本地 NER 与内网 OCR |
| 依赖上下文识别的值，在上下文被压缩、跨 Run（下一轮对话）或网关重启后漏报 | 请求内全文遮盖；Run 内已识别值集合覆盖重试与恢复；跨 Run 与重启窗口的残余风险第一期接受，在 P2 观察实际漏报 |
| 后续首次识别使已发出的历史变为占位符，提示词缓存失效 | 接受；审计记录首次遮盖的历史出现次数，P2 观察缓存命中变化 |
| 思考内容中出现原值或占位符 | 思考内容双向原样透传；它由厂商生成，不会把厂商未见过的原值带出 |
| 网关成为单点与性能瓶颈 | 识别为线性多模式匹配；网关不可用时 Attempt 明确失败，不回退直连 |
| 流式还原的切分与延迟 | 只保留不超过最长占位符长度的尾部 |
| 厂商把占位符改写（大小写、拆开） | 只还原精确形式；在 P2 中观察真实厂商的改写率 |
| DSH 升级后适配器地址、协议或错误格式变化 | 纳入 DSH 升级准入检查：网关地址、令牌变量、流式格式、4xx 错误码传递 |
