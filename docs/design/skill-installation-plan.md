# Skill 安装产品方案与实施计划

**状态：** 前端交互已确认；管理助手已接入结构化计划、同源依赖原子安装、严格试运行和渐进式激活，详见 [实际实现与验收](admin-skill-installation-implementation.md)。ZIP 实装、升级及旧入口整体退出仍待后续批次。
**方案范围：** 管理端 Skill 安装、版本与发布；统一助手的 Agent 管理与运维交互见 [管理助手方案](admin-assistant-plan.md)。
**架构约束：** [Agent 执行引擎统一](../development/overview.md#35-agent-执行引擎统一)、[内部端口与契约](../development/internal-ports.md)。

## 1. 已确认的产品决策

1. 删除当前手工填写名称、说明、执行指令和工具的 Skill 创建模式，不保留隐藏入口或生产回退入口。
2. 「新增 Skill」页签仅提供 ZIP 上传；外部链接或安装命令统一交给独立「管理助手」页面。删除 Skill 页内单独的对话安装方式，两条安装路径共用获取后的解析、校验、安装记录、版本和发布流程。
3. 名称、说明、指令和资源从包中读取；管理员确认来源、依赖映射、权限和安装目标，不重新抄写包内容。
4. 对话安装仅接受外部链接或受支持的安装命令（如 `npx`、`curl`）来引入已有 Skill，不通过对话新建、生成或改写 Skill。缺少有效来源时引导用户提供来源，不生成替代包。
5. 安装与发布分离：获取或入库成功不等于通过真实运行验证，也不等于员工已经可用。
6. 新版本通过新包引入；删除原来的指令编辑表单，保留版本查看、依赖配置、验证、发布、停用和回滚。
7. 对话安装和试运行统一经过 Run/Attempt、Runtime Adapter 和 DSH；平台工具负责下载、解包、校验、保存和发布，不引入第二套 Agent Loop。

## 2. 前端确认前的改造起点（历史基线）

当前页面位于 `/capabilities`，新增「新增 Skill」独立页签，与「Skill 中心」「工具目录」「连接器状态」并列，仅有管理写权限的用户可见。前端已移除原手工创建和指令编辑弹窗，安装新版本也进入新页签。原 [Skill 服务](../../server/src/modules/skill/postgres-skill-service.ts) 仍管理文本指令、工具引用、不可变发布版本和配置校验记录；旧 API 的退出属于用户确认后的完整功能开发，本轮不修改后端。

[ZIP 安装交互预览](../../apps/admin-web/src/components/SkillInstallationPanel.vue) 支持文件选择、移除和格式提示，以及示例内容预览、权限确认和演示结果。原独立对话安装区域已移除；外部链接、`npx`、`curl` 输入迁入 [统一管理助手](admin-assistant-plan.md)。两条路径复用 [包内容预览](../../apps/admin-web/src/components/SkillPackagePreview.vue)。界面明确标记示例，不读取或上传包、不下载来源、不执行命令、不调用模型、不写入 Skill；不是生产安装或 Agent 执行的替代链路。ZIP 预览入口为 `/capabilities?tab=install`，助手入口为 `/assistant?context=skills`。

现有 [Runtime Manifest](../../server/src/modules/runtime/runtime-types.ts) 传递 Skill 指令，[DSH 适配器](../../server/src/modules/runtime/dsh-acp-runtime-adapter.ts) 将指令加入系统提示词。目前不能据此认定已经支持完整 Skill 目录、脚本、模板、依赖安装或管理端安装工具调用。

保留已有身份授权、版本锁定、审计及员工执行链路。扩展安装能力时分别验证资源保存、运行时挂载、工具调用与结果回传，不能只完成前端上传或数据库入库。

## 3. 统一用户流程

### 3.1 ZIP 上传

选择 ZIP → 上传并解析 → 安装预览 → 确认安装 → 保存待验证版本 → 试运行 → 发布。

- 上传前说明接受的包结构及大小限制；解析失败展示具体文件、原因和修正方法。
- 包校验通过前不生成已安装版本。解析中、依赖待处理、待确认和安装失败都有独立状态。
- 重复提交同一次安装不创建重复版本；同名不能直接判定为同一 Skill 或覆盖原有记录。

### 3.2 管理助手中的 Skill 安装

管理员在统一管理助手粘贴外部链接或安装命令 → DSH 管理助手识别已有 Skill 来源 → 平台工具解析来源并获取制品 → 展示统一安装预览 → 管理员确认 → 使用同一安装与验证流程。

| 输入形式 | 处理方式与支持边界 |
| --- | --- |
| 外部链接 | 识别受支持的仓库、Skill 目录或包下载链接，解析到明确 Skill 和固定提交/制品；页面本身不是 Skill 时要求明确来源 |
| `npx` 安装命令 | 仅支持已适配的安装器和参数；解析包名、版本、来源及所选 Skill，通过平台来源适配器获取现成制品。是否需要运行安装器由批次 1 验证；确需执行时只运行固定版本的受支持安装器，并限制目录、网络、凭据与副作用 |
| `curl` 下载命令 | 从受支持的参数中提取下载来源，使用平台下载工具获取并检查制品；不直接执行粘贴的命令文本 |
| 其他命令 | 按明确的来源适配器逐项增加支持；未适配的命令给出原因，并引导提供直接链接或改用 ZIP 上传 |

支持安装命令作为输入不等于提供通用终端。命令由确定性解析器检查结构与参数，模型不能自行放宽规则；管道执行脚本（如 `curl ... | sh`）、命令串联、命令替换、任意写入目标和无法识别的安装器均不直接执行。需要脚本才能获取 Skill 的来源，必须先实现并验证专用适配器。批次 1 给出实际支持的安装器及命令示例，不笼统承诺所有 `npx` 或 `curl` 命令兼容。

助手可以解释已有包、协助选择包内 Skill、匹配本地依赖和定位安装失败；不能为了使安装通过而编造缺失文件、改写执行指令或自行生成脚本。源包不完整时要求更换或修正来源。

- 对话展示可理解的阶段、结果和可执行操作；安装事实以平台记录为准，不根据助手文字判断成功。
- 助手只能在批准的工具与来源范围内工作；包内指令属于待检查内容，不能获得管理权限或替代用户确认。
- 对话刷新、断线后能恢复安装记录与运行状态；取消和重试复用现有运行语义。
- DSH 不可用时明确提示「安装助手不可用」。ZIP 的确定性解析和保存可继续；真实试运行及依赖该结果的发布仍须等待执行能力恢复。

### 3.3 ZIP 与管理助手共用的安装预览

| 内容 | 用户需要理解的事实 |
| --- | --- |
| 能力概览 | 名称、说明、适用场景及包内提供的输入输出要求；缺失信息明确标记，不由助手伪造 |
| 来源与版本 | 上传来源或解析后的外部来源、安装器及固定版本（如适用）、固定提交/制品标识、包摘要、上游版本（如有）和平台版本；不回显或记录命令中的凭据正文 |
| 内容 | 入口说明、脚本、模板、参考资料和其他文件清单；标明支持情况 |
| 依赖与权限 | 所需工具和资源访问、已匹配的平台能力、缺失项、实际申请的权限 |
| 安装目标 | 新 Skill 或指定 Skill 的新版本；升级展示变更与影响的引用范围 |
| 操作 | 取消、处理依赖、确认安装；安全校验通过才可确认；Python 专项落地后依赖不足可明确保存草稿，但不得运行或发布 |

未知或不支持的内容不能静默丢弃后宣称完整可用。必需依赖未解决时不能发布。工具依赖允许为空；包声明的依赖不自动变成平台授权。

## 4. 状态、版本和交互约束

安装记录、版本验证结果和 Skill 可用状态分别管理，避免一个「草稿」标签遮蔽仍在使用的发布版本。

- 安装记录至少表达：获取/解析中、依赖待处理、待确认、安装中、已安装、失败、已取消。
- 待验证版本可重新试运行、放弃；试运行结果区分未运行、运行中、成功、失败与取消。技术执行成功还需管理员检查结果，不能等同于业务效果已经达标。
- 发布要求当前包及依赖/权限配置通过校验、对应配置的真实试运行成功并由管理员确认结果；配置变化使旧验证证据失效。
- Skill 启用/停用与待发布版本管理独立。存在新版本时仍可停用活动 Skill，或放弃新版本。
- 发布更新活动版本；Agent 和已有对话的精确版本引用不自动升级。选择旧版时必须取旧版元数据和依赖，不能混入新草稿内容。
- 回滚切换活动版本，不改写历史制品；放弃未发布版本不要求先回滚。
- 页面复用管理端应用壳层、Token、Element Plus 表格和现有状态组件。列表保持可用宽度，写入口按权限隐藏；上传/安装/验证失败提供重试或修正入口。

## 5. 完整方案的包与执行支持规则

Python 脚本支持采用独立的 [受控执行方案](skill-python-execution-plan.md)。当前已实现 `.py` 保存、兼容性门禁、`python_execute` 平台工具、摘要锁定镜像、无网络临时容器和严格试运行证据；依赖镜像的构建、签名、漏洞治理仍属于部署运维。该专项不代表 ZIP、升级或旧入口退出已经完成。

以下为实施前需要完成验证的设计项，不是已经验证的兼容承诺：

| 设计项 | 批次 1 的必要产出 |
| --- | --- |
| 包入口与结构 | 核对目标 DSH 的实际 Skill 格式；以 `SKILL.md` 为候选入口，明确元数据规则、单层包装目录、多 Skill 包、额外文件的处理方式及有效样包 |
| 来源支持 | 明确首批支持的外部链接、`npx` 安装器及参数、`curl` 下载参数，提供可运行样例与拒绝样例；验证固定版本、制品获取、下载限制和安装器隔离；私有源和凭据接入若未实现，必须明确拒绝而非交给模型尝试 |
| 静态资源 | 验证参考资料、模板的受控存储与只读挂载、相对路径解析、隔离和版本摘要；不沿用仅有指令文本的成功判据 |
| 脚本与依赖 | 列出实际支持与禁止的类型；在现有执行边界内验证，不能为安装包开放任意 Shell、任意联网或自动执行安装脚本 |
| 工具映射 | 外部工具声明如何匹配本地固定版本、如何显示缺失项；验证纯指令包无工具依赖也能使用 |
| 安装助手 | 在现有 Run/Attempt 链路内完成一次真实平台工具调用及结果回传，验证管理身份、取消和重试 |

所有来源均执行同一套包检查：压缩/解压后大小、文件数、路径穿越、绝对路径、链接文件、路径冲突和损坏文件等。下载同时校验目标和重定向，限制可达来源。具体限额由样包和受控存储验证后记录，不把未经验证的数字作为兼容承诺。

平台保存不可变包内容、摘要和来源快照，更新使用新版本。包文件生命周期与业务记录提交需可恢复，避免失败重试造成重复版本、孤立文件或半完成安装。

## 6. 已有 Skill 与旧入口退出

- 已发布文本 Skill 和 Agent 引用继续可读、可执行；兼容读取不等于保留手工创建能力。
- 为现有文本版本提供确定性的包表示或导出方式，保持原指令、工具依赖和原版本身份可追溯；转换方案及回滚须用迁移样本验证。
- 既有草稿允许查看、导出和放弃，后续变更通过包导入；不得无提示删除管理员已保存的内容。
- 前端预览阶段已移除 `SkillEditorDialog` 及旧创建/编辑表单接线；完整功能切换时还须替换旧文本创建/更新 API，不能将仅删除前端入口视为整体退出完成。
- 同步更新原型模式、前端类型、Store、API 契约、种子、测试和文档。当前现状文档在代码落地时切换描述，不提前宣称安装已支持。

## 8. 验收与验证

1. 同一有效包通过两种入口得到一致的内容摘要、能力解释和依赖结果；重试不重复创建版本。
2. 纯指令包无需无关工具；资源包在真实 DSH 运行中读取准确版本的文件；不支持的包给出明确原因并阻止发布。
3. 页面刷新、断线、取消、超时、工具失败和权限变更均收敛到可恢复状态；发布和工具调用重新鉴权。
4. 有新版本时活动版本仍可停用；新版本可以放弃；旧 Agent 和对话继续固定原版本；停用行为遵循既有授权边界。
5. 包和配置改变后必须重新验证；配置检查、真实试运行结果、管理员确认和发布记录分别可追溯。
6. 无权限用户不显示写入口，直接调用 API 同样拒绝；包内容和助手输出不能直接批准安装或扩大授权。
7. 旧创建/编辑入口及对应文本写入路径删除；迁移后历史 Skill 可读、可运行，草稿可处理。
8. 外部链接、受支持的 `npx` 和 `curl` 输入可追溯到已有 Skill 的固定制品；不支持的命令不执行并给出替代入口。缺少来源或用户要求编写新 Skill 时，不创建包或版本；包缺文件时不由助手补写。

开发验证遵循 [开发与测试](../development/development.md)：按改动执行类型、UI、API、Runtime、授权及生命周期测试；数据库使用专用可丢弃测试库。新增安装测试接入项目门禁，浏览器检查覆盖上述交互，真实 DSH 验证单独记录。最终分别报告本地检查、真实运行、提交、CI 和部署事实。
