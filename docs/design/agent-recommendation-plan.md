# dsh-work 助手推荐 AI 同事方案

**状态：** 已实施（代码级，P1 浏览器旅程 REC-01 与集成测试 REC-02 已覆盖）。现行规则以[功能规则 2.4](../development/feature-rules.md#24-推荐-ai-同事)为准；真实 DSH 下的推荐质量（验收目录 `REC-P2`）未验收前，不宣称推荐准确。<br>
**更新日期：** 2026-10-29<br>
**原型：** [AI 同事推荐原型](https://claude.ai/artifact/FBX4AM2CnHascsnHUaNR57)（2026-10-29 确认；首页不放示例问题）。

## 1. 背景与目标

员工不知道某件事该找哪个 AI 同事时，只能去“AI 同事”目录逐个看说明。目标：

- 员工可以直接问 dsh-work 助手“这件事该找谁”，助手给出推荐；
- 有职责相符的 AI 同事时，助手**优先推荐**该同事，只用一两句话说明原因，不自己展开解答（R4）；没有相符同事或是通用问题时直接回答；
- 推荐以卡片呈现，点“去聊天”直接进入该 AI 同事的新对话，问题已预填、未发送。

非目标：不在团队空间推荐（那里的 Agent 必须是空间成员）；不自动把对话转交给另一个 Agent；不带入原对话的历史或附件。

## 2. 已确认决策（2026-10-29）

| 编号 | 决策 | 结论 |
| --- | --- | --- |
| R1 | 谁能推荐 | Agent 版本开关“可推荐其他 AI 同事”（`agent_recommendation_enabled`），与联网搜索、项目任务管理同一机制，默认关闭；迁移为 dsh-work 助手发布开启该开关的新版本 |
| R2 | 跳转后带什么 | 新会话输入框预填原问题，**不自动发送**；原对话历史与附件不带入 |
| R3 | 适用范围 | 只在个人对话的员工交互运行中装配（A 新对话、B 单聊）；团队空间、定时与主动任务、管理运行不装配 |
| R4 | 有合适同事时先答还是先推荐（2026-10-30 调整） | **优先推荐**：有职责相符的同事时只推荐并简短说明原因，不自己展开解答；员工看了推荐仍明确要求由助手回答时再回答。替代原“先尽量回答，再推荐” |

## 3. 边界

- **执行职责不变。** 推荐判断由模型在 DSH 单次 Attempt 内完成；平台只提供目录与校验，经 Platform Tool Bridge 执行，不在平台侧另写匹配逻辑或直接调用模型（[总览 3.5](../development/overview.md#35-agent-执行引擎统一)）。
- **不扩大可见范围。** 只列出、只记录发起员工本人当前可用的 AI 同事；可见性与运行授权的执行前复核同一口径：按员工在平台中的当前角色（`authorizeWorkbench`，无会话角色时读 `user_roles`），再按 Agent 已发布、执行身份启用、可见角色求交（`listWorkbenchAgents`）。不使用 Manifest 中已与当前 Agent 授权求交的 `role_ids`。
- **卡片是结构化交互。** 这是[生命周期模板 4.5](../development/agent-lifecycle-template.md#45-其他扩展)“结构化交互”扩展的首次使用：卡片字段固定，名称与说明取 Agent 当前启用版本，只有推荐理由来自模型且按纯文本渲染、限长；不执行任何模型生成的脚本或链接。

## 4. 方案

### 4.1 平台工具

| 工具 | 效果 | 输入 | 输出 |
| --- | --- | --- | --- |
| `list_colleague_agents` | 只读 | 无 | 发起员工当前可用的 AI 同事（不含本 Agent），每项 `agentId`、名称、说明、至多 3 个示例问题；至多 50 个 |
| `recommend_agents` | 写入，不重试 | `recommendations`：1～3 项 `{ agentId, reason }`，`reason` 1～120 字 | 已记录的推荐 |

- 注册表装配方式为 `agent-opt-in`（版本开关），派发时再按运行场景过滤：只有无 purpose、个人空间的员工交互运行装配；Skill 不能声明这两个工具。
- `recommend_agents` 校验每个 `agentId` 都在 `list_colleague_agents` 的同一口径中、互不重复、不是本 Agent；任一不满足整次拒绝并告知模型。同一 Attempt 再次调用时替换上一组推荐。
- 工具运行时的系统提示加入“推荐 AI 同事”说明：用户提出业务问题或问该找谁时先列目录；有职责相符的同事时优先推荐 1～3 位，回复只用一两句话说明原因，不展开解答（R4）；没有相符同事或是通用问题（写作、润色、翻译、常识、一般性解释）时直接回答；同一会话不重复推荐同一位同事；推荐理由只依据目录返回的同事说明与示例问题，不得声称说明之外的能力（REC-P2 发现）。

### 4.2 推荐记录与展示

- 新表 `agent_recommendations`：`run_id`、`attempt_id`、`session_id`、`recommended_by_user_id`（发起员工）、`source_agent_version_id`、`agent_id`、`reason`、`position`、`created_at`。
- 会话详情按 Run 返回推荐（个人会话的多轮消息各自挂在该 Run 最后一条回复下，与成果卡同一规则），只取各 Run **当前 Attempt** 的记录，重试不会重复出现旧卡片。
- 读取时重新计算 `available`：该同事当前是否仍对该员工可用；名称与说明取当前启用版本，同事已删除时只显示“该 AI 同事暂不可用”。

### 4.3 跳转与预填

- “去聊天”按当前模式直接生成目标路由（A：`/workbench?agent=<id>`；B：`/c/chats/agent/<id>`），不经模式重定向。
- 问题经浏览器历史状态（router `state`）传递，不进入 URL；新对话页读取一次后清除，刷新不会重复预填。只预填该 Run 的用户问题，不预填附件。
- 进入后若该同事已不可用（解析 Agent 失败），在卡片处提示“该 AI 同事暂不可用”，不跳转。

### 4.4 管理端

Agent 草稿“能力”步骤增加开关“可推荐其他 AI 同事”，说明“只在员工个人对话中生效，只推荐员工本人可用的 AI 同事”。开关随版本固定，改动形成新草稿并作废旧验证结果（与联网搜索一致）。

## 5. 验收

见验收目录 `REC-01`（P0：卡片展示与跳转预填）、`REC-02`（P1：装配范围、可见性、记录与重试）、`REC-P2`（真实 DSH 推荐质量）。

## 6. 风险与后续

- **发布试运行不装配推荐工具**（与项目任务工具一致），验证结果不覆盖推荐行为，已在[功能规则第 9 节](../development/feature-rules.md#9-agent-验证与发布)列为与生产的差异。
- **既有风险（非本方案引入）：** 会话仓库在未传 Agent 版本时回退到写死的 `agent-version-dsh-work-assistant-1`，会绕过新版本；员工端主路径先解析当前版本，暂不处理。
- 推荐质量依赖各 Agent 的说明与示例问题写得清楚；后续可在管理端提示“说明过短，可能不会被推荐”。
