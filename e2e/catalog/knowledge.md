# 企业知识库

设计见[企业知识库接入 WeKnora 方案](../../docs/design/weknora-knowledge-plan.md)。本分册覆盖一期 WK-S2（员工端“知识库”与对话中添加知识库）；WK-S1 的检索链路用例在 `server/src/infrastructure/postgres/weknora-knowledge.integration.test.ts`。所有 P0、P1 用例使用按 WeKnora v0.9.0 接口实现的测试替身，不能证明真实 WeKnora 的解析与检索效果。证据层级与写法见[验收目录索引](../TEST-CATALOG.md)。

### KB-P0-01 员工浏览知识库并按权限看到不同操作

**优先级：** P0 · **角色：** 员工（冒烟测试身份，可在“仅查看 / 文档管理 / 知识库管理”三种权限下运行） · **运行层级：** P0 冒烟服务、内存数据<br>
**前置数据：** 员工属于两个部门；三个可见知识库，其中一个归属员工所在部门，另外两个归属其他部门或由管理员授给全公司；归属员工部门的知识库有已完成、解析中和解析失败的文档<br>
**spec：** `e2e/knowledge.spec.ts`

1. A 工作模式主导航在“项目空间”之后出现“知识库”，B 协作模式在“群组”之后出现“知识库”；进入后页头为“知识库”，列出可见知识库，每张卡片显示文档数、解析中数量、可见部门数、归属部门与更新时间；归属员工部门的知识库标“可管理”。
2. “全部 / 可管理”筛选与搜索按名称或归属部门过滤列表。
3. 打开知识库进入详情：面包屑为“知识库 / 名称”，“文档”列表显示标题、文件名、上传人、更新时间与解析状态；右侧“知识库信息”显示归属部门、我的权限与可见部门（区分员工授予与管理员授予）。
4. 仅查看：没有新建、上传、编辑、删除与“管理可见部门”入口，只能预览和下载。文档管理：归属自己部门的知识库可以上传、编辑标题、重新解析失败的文档、删除文档，其他知识库只能查看。知识库管理：另有新建知识库、修改名称和说明、管理可见部门与删除知识库。
5. 新建知识库时归属部门只能在自己所属的部门中选择，默认主部门并包含下级；确认前显示“将对哪些部门可见”。上传前显示“上传的文档将对以下部门可见”。删除知识库须输入名称确认。

**验收：** 按钮、输入框与对话框有可访问名称；窄屏下列表、详情与右侧信息可操作；加载、空列表、知识库中没有文档与服务不可用都有明确提示。

### KB-P0-02 对话中添加与移除知识库

**优先级：** P0 · **角色：** 员工（冒烟测试身份） · **运行层级：** P0 冒烟服务、内存数据<br>
**前置数据：** 员工有可见知识库；个人空间新对话<br>
**spec：** `e2e/knowledge.spec.ts`

1. 个人空间对话输入框旁有“添加知识库”，打开后只列出员工当前可见的知识库，可多选。
2. 选中的知识库显示为输入框上方的标签，可以逐个移除；在知识库列表或详情点“用这个知识库提问”，进入新对话且已带上该知识库。
3. 团队空间的新对话不显示“添加知识库”。

**验收：** 标签与移除按钮有可访问名称；不具备知识库查看权限的员工看不到入口。

### KB-01 可见范围与操作权限

**优先级：** P1 · **角色：** 仅查看、文档管理、知识库管理三种员工；没有部门的员工 · **运行层级：** 专用可丢弃 PostgreSQL、受控测试身份、真实 HTTP 接口、WeKnora 测试 HTTP 服务<br>
**前置数据：** 两级部门树；归属不同部门、授权方式不同（含下级、不含下级、管理员授给根部门）的知识库<br>
**spec：** `server/src/http/knowledge-api.integration.test.ts`

1. 列表只返回授给员工所属部门、或上级部门勾选“包含下级”授给的知识库；调岗后下一次请求即变化；没有部门的员工列表为空，也不能新建。
2. 对不可见知识库的详情、文档列表、预览、下载与任何管理请求都被拒绝，不泄露其名称。
3. 仅查看不能上传、编辑、删除文档；文档管理不能新建或删除知识库、不能调整授权；可见但归属其他部门的知识库（包括管理员授给全员的）只能查看，归属部门是员工的上级或下级部门时同样被拒绝。
4. 请求的文档不属于该知识库时被拒绝（先向 WeKnora 查询文档所属知识库）。
5. 不提供从网址导入的接口。

**验收：** 每个被拒绝的请求都返回明确的错误，不调用 WeKnora 的写接口。

### KB-02 新建、修改与删除知识库

**优先级：** P1 · **角色：** 知识库管理员工 · **运行层级：** 专用可丢弃 PostgreSQL、受控测试身份、WeKnora 测试 HTTP 服务<br>
**前置数据：** 员工属于两个部门，其中一个为主部门；已配置统一嵌入模型<br>
**spec：** `server/src/http/knowledge-api.integration.test.ts`

1. 新建时归属部门默认主部门，可以改选员工所属的其他部门，不能选不属于自己的部门或根部门；新建后授给归属部门（默认包含下级），WeKnora 收到的建库请求带统一嵌入模型。
2. 未配置嵌入模型时拒绝新建并提示联系管理员。
3. 修改名称和说明同步到 WeKnora；名称不能为空。
4. 删除后知识库立即不在列表中、不再被检索，已添加它的会话跳过它；WeKnora 后台清理失败不影响平台侧删除结果。

**验收：** 新建、修改、删除都写审计，记录操作人、知识库与可见部门。

### KB-03 可见部门调整

**优先级：** P1 · **角色：** 知识库管理员工 · **运行层级：** 专用可丢弃 PostgreSQL、受控测试身份<br>
**前置数据：** 归属员工部门的知识库，已有员工授予与管理员授予的授权各一条<br>
**spec：** `server/src/http/knowledge-api.integration.test.ts`

1. 员工可以把知识库授给自己直接所属的其他部门，可选是否包含下级；不能授给自己不在的部门，也不能授给根部门（即使本人属于根部门）。
2. 员工可以撤销员工授予的授权，不能撤销管理员授予的授权，不能撤销到没有任何授权。
3. 同一部门只有一条有效授权，重复授予幂等。

**验收：** 每次授权变更写审计；变更在下一次请求立即生效。

### KB-04 文档管理

**优先级：** P1 · **角色：** 文档管理员工 · **运行层级：** 专用可丢弃 PostgreSQL、受控测试身份、WeKnora 测试 HTTP 服务<br>
**前置数据：** 归属员工部门的知识库，含已完成与解析失败的文档<br>
**spec：** `server/src/http/knowledge-api.integration.test.ts`

1. 文档列表按页返回标题、文件名、上传人、更新时间与解析状态，支持关键词与解析状态筛选；上传人取自平台审计。
2. 上传文件转发给 WeKnora；重复文件提示“该文档已存在”；超过大小上限被拒绝。
3. 修改标题、重新解析失败的文档、删除文档都转发给 WeKnora；删除后文档不在列表中。
4. 预览、下载经平台转发，按查看者当前权限校验，下载写审计。

**验收：** 上传、修改、删除与下载都写审计，记录操作人、知识库、文件名。

### KB-05 会话所选知识库

**优先级：** P1 · **角色：** 员工 · **运行层级：** 专用可丢弃 PostgreSQL、受控测试身份<br>
**前置数据：** 个人空间会话、团队空间会话；可见与不可见的知识库<br>
**spec：** `server/src/http/knowledge-api.integration.test.ts`

1. 员工可以为自己的个人空间会话添加和移除知识库，之后再读取会话（如刷新页面）得到同样的选择；只能添加当前可见的知识库。
2. 不能修改他人的会话，团队空间会话（一期）被拒绝。
3. 读取会话所选知识库时，已删除或已不可见的知识库标为不可用，不返回其文档信息。
4. 添加、移除只影响之后的执行；执行时按 WK-S1 的规则检索。

**验收：** 添加与移除写审计。

### KB-06 知识库服务不可用

**优先级：** P1 · **角色：** 员工 · **运行层级：** 专用可丢弃 PostgreSQL、WeKnora 测试 HTTP 服务（返回 5xx、超时）<br>
**前置数据：** 可见知识库<br>
**spec：** `server/src/http/knowledge-api.integration.test.ts`

1. WeKnora 不可用时，列表、详情和文档操作返回“知识库服务暂不可用，请稍后重试”，不返回缓存数据，也不在平台侧排队重试写操作。
2. 未配置 WeKnora 连接时，员工端不显示“知识库”入口与“添加知识库”。

**验收：** 错误不包含 API Key、请求或响应正文。

### KB-ADM-P0 管理端企业知识库页

**优先级：** P0 · **角色：** 平台管理员（冒烟测试身份） · **运行层级：** P0 冒烟服务、内存数据<br>
**前置数据：** 已配置的连接；若干知识库，其中有无可见部门、归属部门已删除、嵌入模型与当前配置不同的知识库<br>
**spec：** `e2e/knowledge-admin.spec.ts`

1. 管理端侧栏有独立的“知识库”分组，其中是“企业知识库”；页面显示连接状态、知识库与文档数、需要处理的知识库数、最近 24 小时检索与不可用次数。
2. “全部知识库”列出所有经平台创建的知识库，显示归属部门（已删除的标出）、可见部门（区分员工授予与管理员授予）、文档数、嵌入模型（与当前配置不同的标“需重建”）；“需要处理”筛选只留下无可见部门、归属部门已删除或需重建的知识库。
3. 可见部门：可以授给任意部门（含全公司），可选是否包含下级，可以撤销任何授权，撤到没有授权时提示员工都看不到。修改归属部门、新建知识库（指定归属部门，默认授给它并包含下级）、删除知识库（输入名称确认）。
4. “连接配置”：API Key 只显示末四位与到期时间，点“更换”才能输入；修改嵌入模型时提示现有知识库将标为需重建；停用时提示员工端入口隐藏；“测试连接”显示结果。

**验收：** 表单与对话框有可访问名称；窄屏下可操作；WeKnora 不可用时页头提示，知识库与授权仍可查看和调整。

### KB-ADM-01 连接配置与凭据

**优先级：** P1 · **角色：** 平台管理员、只读管理员 · **运行层级：** 专用可丢弃 PostgreSQL、受控测试身份、WeKnora 测试 HTTP 服务<br>
**前置数据：** 已配置凭据主密钥<br>
**spec：** `server/src/http/knowledge-admin-api.integration.test.ts`

1. 保存地址、API Key、到期时间、统一嵌入模型与启用状态；API Key 加密保存，读取接口只返回末四位与到期时间，不返回明文。
2. 不更换 API Key 时保存其他字段，原有 Key 保持不变；地址必须是 http 或 https。
3. 测试连接用填写的或已保存的 Key 调用 WeKnora，返回成功或失败原因分类，不含 Key 与响应正文。
4. 保存后检索与员工端立即使用新配置；停用后员工端入口隐藏、对话不检索。
5. 只读管理员可以读取、不能保存；每次保存写审计（不含 Key）。

**验收：** 未配置主密钥时保存 API Key 被拒绝并说明原因。

### KB-ADM-02 全部知识库与跨部门授权

**优先级：** P1 · **角色：** 平台管理员 · **运行层级：** 专用可丢弃 PostgreSQL、受控测试身份、WeKnora 测试 HTTP 服务<br>
**前置数据：** 部门树（含已删除的部门）；员工建的与管理员建的知识库<br>
**spec：** `server/src/http/knowledge-admin-api.integration.test.ts`

1. 列表包含所有经平台创建、未删除的知识库，标出无可见部门、归属部门已删除与需重建。
2. 管理员可以把任意知识库授给任意有效部门（含根部门），撤销任何授权（包括员工授予的），撤到没有授权；授权后员工端可见范围立即变化。
3. 修改归属部门只能选有效的非根部门；新建知识库可以指定任意有效的非根部门为归属部门，WeKnora 收到统一嵌入模型。
4. 删除后员工端立即不可见、不再检索。
5. 每次变更写审计；只读管理员不能变更。

### KB-ADM-03 验证页提示不覆盖企业知识

**优先级：** P0 · **角色：** 平台管理员 · **运行层级：** P0 冒烟服务<br>
**前置数据：** 企业知识库已启用；一个处于验证与发布步骤的 Agent<br>
**spec：** `e2e/knowledge-admin.spec.ts`

1. Agent 的“验证与发布”步骤显示“验证不覆盖企业知识”：验证运行不检索企业知识库，需在员工端实际对话中确认；只提示，不阻断验证。

### KB-P2 真实 WeKnora 验收

**优先级：** P2 · **角色：** 知识库管理员工、仅查看员工 · **运行层级：** 受控环境中固定版本的真实 WeKnora、内网嵌入与重排序模型、真实 DSH<br>
**前置数据：** 经批准的测试文档<br>
**spec：** 按发布流程人工执行（WK-S4）

1. 新建知识库 → 上传 → 解析完成 → 对话中添加并提问，回答引用该文档 → 调整授权后另一员工不可见 → 删除。
2. WeKnora 停机时对话照常回答并注明不可用；员工端页面提示不可用。
3. 运行 `server/src/modules/knowledge/weknora-contract.test.ts` 契约测试，校准最低相关度。

**验收：** 证据按发布流程留存，不写入本条目。
