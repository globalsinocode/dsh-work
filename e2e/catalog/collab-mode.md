# 员工端双模式（S5）

A 工作模式与 B 协作模式：模式切换、协作壳层、对话列表、单聊、群聊、群组与成员选择。证据层级与写法见[验收目录索引](../TEST-CATALOG.md)。

方案：[项目空间方案第 12 节](../../docs/design/project-space-plan.md#12-员工端双模式a-工作模式与-b-协作模式s5提议)。A 工作模式即现有员工工作台，现有旅程全部保持通过；B 协作模式的群组就是项目空间，只换界面，不改业务规则、权限与执行链路。本节按切片补充，S5a 只覆盖模式基础，B 的对话、AI 同事、群组页在 S5a 为占位页。

### MODE-E2E-01 默认进入工作模式与 logo 模式菜单（S5a）

**优先级：** P0
**角色：** 员工（冒烟测试身份，从未切换过模式）
**运行层级：** P0 冒烟服务、内存数据（每个用例前重置，偏好回到缺省）
**前置数据：** 冒烟夹具；浏览器无本地模式缓存
**spec：** `e2e/collab-mode.spec.ts`

1. 打开 `/workbench`：显示工作模式壳层，主导航依次为“新对话、Skill 广场、AI 同事、项目空间、定时任务”。
2. 点击左上角 logo（可访问名称“切换模式”）：打开模式菜单，列出“工作模式”“协作模式”，“工作模式”处于选中状态，并提示按账号记住选择。
3. 按 Esc 或点击菜单外：菜单关闭，页面与地址不变。

**验收：** 从未切换过的用户进入工作模式；A 的界面除“自动任务”改名“定时任务”与 logo 可打开模式菜单外不变。

### MODE-E2E-02 切换到协作模式并按账号记忆（S5a）

**优先级：** P0（记忆跨设备的持久化部分为 P1，见 MODE-API-01）
**角色：** 员工（冒烟测试身份）
**运行层级：** P0 冒烟服务、内存数据
**前置数据：** 冒烟夹具
**spec：** `e2e/collab-mode.spec.ts`

1. 在工作模式的 `/workbench` 打开模式菜单，选择“协作模式”：切换为协作模式壳层，地址变为 `/c/chats`，菜单中“协作模式”处于选中状态。
2. 刷新页面：首屏直接是协作模式壳层，地址仍为 `/c/chats`。
3. 新开一个无本地缓存的浏览器上下文（模拟另一台设备）登录同一账号并打开 `/workbench`：以服务端偏好为准进入协作模式 `/c/chats`。
4. 在协作模式中打开模式菜单选择“工作模式”：回到工作模式壳层，地址映射回 `/workbench`；再刷新仍为工作模式。
5. 偏好保存失败时：界面保持原模式并提示切换失败，不出现半切换状态。

**验收：** 模式按账号保存在服务端，本地缓存只用于首屏；切换只换界面与地址，不改数据。

### MODE-E2E-03 协作模式壳层导航（S5a）

**优先级：** P0
**角色：** 员工（冒烟测试身份，已切换到协作模式）
**运行层级：** P0 冒烟服务、内存数据
**前置数据：** 冒烟夹具；偏好为协作模式
**spec：** `e2e/collab-mode.spec.ts`

1. 协作模式主导航只有四个入口：对话、AI 同事、群组、定时任务；宽屏左侧图标栏只显示图标，入口名称在悬停提示与可访问名称中；当前入口处于选中状态。配色与工作模式侧栏一致（中性暖灰）。
2. 依次进入：对话 `/c/chats`、AI 同事 `/c/agents`、群组 `/c/groups`（S5a 为占位页，显示页面名称与“即将上线”说明）；定时任务 `/automations` 直接是工作模式的同一页面（标题“我的定时任务”）。
3. 打开头像菜单：包含“用户中心、Skill 广场、我的文件、历史对话”，分别打开 `/settings`、`/skills`、`/files`、`/history`，页面与工作模式相同、仍处于协作模式壳层。
4. 窄屏（宽度 ≤ 820px）：四个入口显示为底部标签栏，logo 模式菜单与头像菜单仍可用，页面无横向溢出。

**验收：** B 的主导航为四个入口；共用页面只有一套，放在协作模式壳层中。

### MODE-E2E-04 两种模式间的路由映射（含旧链接与通知落地）（S5a）

**优先级：** P0
**角色：** 员工（冒烟测试身份）
**运行层级：** P0 冒烟服务、内存数据
**前置数据：** 冒烟夹具中的项目空间 `ws-supply`
**spec：** `e2e/collab-mode.spec.ts`；映射规则的单元测试在 `apps/workbench-web/src/router/mode-routes.test.ts`

1. 协作模式下直接打开工作模式地址（旧书签、复制的链接、站内通知）：`/workbench` → `/c/chats`；`/workspaces` → `/c/groups`；`/agents` → `/c/agents`；`/workspaces/ws-supply` → `/c/chats/group/ws-supply`；`/workspaces/ws-supply?tab=files` → `/c/chats/group/ws-supply?tab=files`；`/workspaces/ws-supply/tasks/:taskId` → `/c/chats/group/ws-supply?tab=tasks&task=:taskId`；`/conversations/:id` → `/c/chats?conversation=:id`（S5c 定位到所属 Agent 的单聊）；`/workbench?agent=:agentId` → `/c/chats/agent/:agentId`。
2. 工作模式下打开协作模式地址：反向映射回工作模式对应地址；没有对应页的 `/c/...` 进入 `/workbench`。
3. 共用页（`/automations`、`/settings`、`/skills`、`/files`、`/history`）在两种模式下地址不变。
4. 在协作模式切回工作模式（及反向）时，当前页按同一规则映射，不丢失所在空间、页签与任务。

**验收：** 链接与模式无关：同一链接在两种模式下都落到对应页面，不出现 404 或空白页。

### MODE-API-01 用户偏好接口（S5a）

**优先级：** P1
**角色：** 员工 A、员工 B（受控测试身份）
**运行层级：** 专用可丢弃 PostgreSQL（服务端集成测试，经 HTTP 路由）
**前置数据：** 迁移后的空库
**spec：** `server/src/http/user-preferences-api.integration.test.ts`（`pnpm test:s5:preferences:integration`）

1. 从未保存过偏好的员工 `GET /api/workbench/v1/me/preferences`：返回 `uiMode = work`。
2. `PUT` `{ "uiMode": "collab" }` 后再 `GET`：返回 `collab` 与更新时间；重复 `PUT` 同值幂等。
3. `PUT` 非法值（缺失、`dark`、非字符串、多余字段）返回 422，偏好不变。
4. 员工 A 的偏好不影响员工 B；未登录请求被拒绝。

**验收：** 偏好按账号保存在服务端；缺省为工作模式；接口与 OpenAPI 一致。

### MODE-E2E-05 组件拆分后工作模式不变（S5b）

**优先级：** P0（回归）+ P1
**角色：** 员工、项目空间负责人 / 成员 / 只读成员（各层级既有测试身份）
**运行层级：** P0 冒烟服务（逐像素对比）、P1 专用可丢弃 PostgreSQL + 合成 Runtime
**前置数据：** P0 冒烟夹具（执行中、成功含成果、等待审批、失败四类执行，`ws-supply` 项目空间）；P1 `project-space`、`personal` 夹具
**spec：** 既有 `e2e/*.spec.ts`（P0）、`e2e/project-space.integration.spec.ts` 与 `e2e/personal-integration/*.spec.ts`（P1）；组件与组合式函数单测在 `apps/workbench-web/src/components/conversation/` 与 `src/composables/`

S5b 把消息列表、执行结果卡片、执行状态与输入区从 `ConversationView` 拆为 `components/conversation/*`，把停止 / 重试 / 引用成果抽为 `useRunActions`，把空间加载、成员与角色、可 @ 的 Agent、文件、成果与写入口判断从 `WorkspaceDetailView` 抽为 `useProjectSpace`，供 B 的对话页与群组页复用。

1. 依次打开四类执行的对话详情与 `ws-supply` 的任务、对话、共享文件、成果、档案页签（桌面与 390px 宽）：与拆分前逐像素一致（反锯齿差异除外）。
2. 对话详情中下载成果、继续修改、复制、停止、重新执行与续写；共享讨论中发言与 @ Agent 执行；任务对话中评论、交给 Agent、标记完成：行为与拆分前一致。
3. 只读成员与归档空间：讨论与任务对话不显示输入区，执行详情不显示继续修改与重新执行。

**验收：** 工作模式界面与交互不变；既有单测、P0 冒烟与 P1 旅程全部保持通过（环境性既有失败另行记录）。

### MODE-E2E-06 协作模式对话列表（S5c）

**优先级：** P0
**角色：** 员工（冒烟测试身份，协作模式）
**运行层级：** P0 冒烟服务、内存数据
**前置数据：** 冒烟夹具中本人的个人对话（同一 AI 同事的多段会话）与本人所在的项目空间
**spec：** `e2e/collab-mode.spec.ts`

1. 进入“对话”：左栏为统一对话列表，单聊按 AI 同事聚合为一行（同一 AI 同事的多次对话不重复出现），群组为一行；按最近活动排序，每行显示头像（群组为成员头像拼图）、名称、最后一条消息预览与时间。
2. 在搜索框输入 AI 同事或群组名称：列表只保留匹配项；无匹配时显示空态。
3. 点“＋”→“发起对话”：选择一位 AI 同事后进入与其单聊；尚无对话时该 AI 同事出现在列表顶部。“新建群组”在 S5d 接入。
4. 窄屏：先显示列表，进入单聊后可返回列表。

**验收：** 对话对象而不是单次会话构成列表；列表内容只来自本人可读的会话与群组。

### MODE-E2E-07 单聊连续显示与续写（S5c）

**优先级：** P0（展示）+ P1（续写与自动开启会话）
**角色：** 员工（P0 冒烟测试身份；P1 受控测试身份，专用可丢弃 PostgreSQL + 合成 Runtime）
**运行层级：** P0 冒烟服务（`e2e/collab-mode.spec.ts`，展示与版本变化提示）；P1 `e2e/personal-integration/collab-chat.spec.ts`（`pnpm test:e2e:personal`，续写与自动开启会话；版本变化由仅在可丢弃夹具注册的测试钩子 `POST /api/workbench/v1/test/collab/agents/:agentId/stale-latest-session` 构造）
**前置数据：** P1：同一 AI 同事的两段历史会话，其中较早一段使用旧 Agent 版本

1. 打开与某 AI 同事的单聊：头部显示 AI 同事名称与岗位说明；聊天区按时间连续显示该 AI 同事的多段会话，段首以“话题 · 时间”分隔；Agent 回复的成果以卡片展示，可下载。
2. 较早的会话可通过“加载更早的对话”按需展开。
3. 发送消息：续写最近一段会话（不出现新的分隔），回复出现在同一段末尾；执行中可停止。
4. 最近一段会话的 Agent 版本与 AI 同事当前版本不同（或从未与该 AI 同事对话）时，发送消息自动开启新的会话，聊天区出现新的“话题 · 时间”分隔；不提供手动“新话题”。
5. AI 同事当前不可用时：历史可读，输入区替换为不可用说明。

**验收：** 一个对话对象连续显示多段会话；发送只续写最近一段或由平台自动开启新会话，均经既有 createSession / startRun 与 Run/Attempt → DSH 链路，不新增执行入口。

### MODE-E2E-08 链接与入口落到单聊（S5c）

**优先级：** P0
**角色：** 员工（冒烟测试身份，协作模式）
**运行层级：** P0 冒烟服务
**前置数据：** 冒烟夹具中本人的一次个人对话与一次项目空间对话
**spec：** `e2e/collab-mode.spec.ts`

1. 打开工作模式的对话链接 `/conversations/:id`（复制的链接、旧书签、站内通知）：映射到 `/c/chats?conversation=:id`，再定位到该会话所属 AI 同事的单聊并滚动到该段。
2. 项目空间里的对话链接定位到对应群组。
3. 链接指向不存在或无权访问的对话：提示对话不存在或无权访问，停留在对话列表。
4. 从协作模式切回工作模式时，单聊中定位的会话映射回 `/conversations/:sessionId`。

**验收：** 旧链接在协作模式中落到对应对象，不出现空白页或越权内容。

### MODE-API-02 对话对象接口（S5c）

**优先级：** P1
**角色：** 员工 A、员工 B（受控测试身份）
**运行层级：** 专用可丢弃 PostgreSQL（服务端集成测试，经 HTTP 路由）
**前置数据：** A 与两个 AI 同事各有个人会话（其中一段为旧版本）；A 是一个活动项目空间和一个已归档项目空间的成员；B 有自己的个人会话
**spec：** `server/src/http/conversation-targets-api.integration.test.ts`（`pnpm test:s5:conversation-targets:integration`）

1. `GET /me/conversation-targets`：A 的个人会话按 AI 同事聚合，每个 AI 同事一行；A 所在的活动项目空间各一行；按最近活动排序；含最后一条消息预览与时间；不含 B 的会话、已移除的会话、A 不是成员的空间；`query` 按名称过滤；分页游标不重复不遗漏。
2. 被移出项目空间后，该群组不再返回。
3. `GET /me/conversation-targets/agent/:agentId/sessions`：返回 A 与该 AI 同事的会话分段（新到旧、分页）；只有最近一段且其 Agent 版本等于当前版本时给出可续写的会话；旧版本或 AI 同事不可用时不可续写；与该 AI 同事无会话且不可用时 404。
4. `GET /me/conversation-targets/resolve?conversation=`：Run ID 与 Session ID 都能解析；个人会话解析为所属 AI 同事，项目空间会话解析为群组；他人会话与不存在的 ID 返回 404。

**验收：** 列表与分段只含本人可读内容；续写判断由服务端给出；接口与 OpenAPI 一致。

### MODE-E2E-09 群聊时间线与 @Agent（S5d）

**优先级：** P0（展示）+ P1（发言、@Agent 执行、只读与归档）
**角色：** 项目空间成员；只读成员；负责人（P1 受控测试身份）
**运行层级：** P0 冒烟服务（`e2e/collab-mode.spec.ts`）；P1 专用可丢弃 PostgreSQL + 合成 Runtime（`e2e/project-space.integration.spec.ts`）
**前置数据：** 含 Agent 成员、讨论话题、Agent 任务（含一次执行）与已完成任务的项目空间；一个已归档项目空间

1. 在对话页打开群组：头部显示群组名称与成员数（不显示成员头像），右侧为“⋯”群信息按钮（可访问名称“群信息”），其下为“对话 / 任务 / 文件 / 成果 / 档案”页签，默认“对话”。
2. 时间线按时间连续显示该群组的讨论话题（段首“话题 · 时间”）、成员发言、Agent 回复（标注发起人）与系统记录（创建群组、成员与 Agent 加入或移出、归档）；任务以卡片出现（任务创建、Agent 任务每次执行完成——定时执行“无变化”折叠、标记完成），显示状态、负责人、执行规则与结果摘要。任务对话本身不进入群聊时间线。
3. 发送不 @ 的消息：作为讨论消息出现，不触发执行。@ Agent 发送：问题下方出现该 Agent 的条目，标注发起人与“执行中”，显示正在进行的步骤；完成后由 Agent 回复取代该条目，问题与回复之间不再单独显示执行记录；只有一个 Agent 成员时输入框预选它，可改为不 @。发送续写最近一段讨论；群组还没有讨论时自动开启第一段。
4. 点 Agent 回复或执行中条目下的“查看执行详情”：在群组内打开执行详情（与工作模式同一页面），可返回对话。执行失败、被停止或等待确认且没有回复时，条目标出状态并用一句话说明，同样可查看执行详情；执行中条目对非只读成员提供“停止”。
5. 只读成员与归档群组：时间线可读，不显示输入区；群组没有 Agent 成员时提示先添加 Agent。

**验收：** 群组即项目空间，发言、@Agent 与权限规则与工作模式一致；任务卡片来自任务事件与执行记录，不写入消息表。

### MODE-E2E-10 群组页签、任务详情与群信息（S5d）

**优先级：** P0（导航与复用）+ P1（任务对话续接、文件新版本、档案编辑）
**角色：** 项目空间负责人与成员
**运行层级：** P0 冒烟服务；P1 `e2e/project-space.integration.spec.ts`
**前置数据：** `ws-supply` 项目空间（P0）；含 Agent 任务的项目空间（P1）

1. 点任务卡片：切到“任务”页签并打开该任务的详情（任务对话 + 任务信息，与工作模式同一组件，布局见 MODE-E2E-16），点“任务”页签返回任务列表；任务对话中评论、交给 Agent、标记完成与工作模式一致。
2. “任务 / 文件 / 成果 / 档案”页签占满内容区，内容、操作与权限与工作模式对应页签一致（上传文件与新版本、成果预览与下载、档案编辑与回退）；页签切换不离开当前群组，地址可分享（`/c/chats/group/:id?tab=`，任务详情 `/c/chats/group/:id/tasks/:taskId`）。
3. “群信息”展开右侧信息栏：项目简报、成员与 Agent、最近动态，以及管理成员、设置、用量、归档入口；可收起；窄屏为抽屉。
4. 在工作模式与协作模式之间切换：所在页签、任务详情与执行详情按 12.5 映射，不丢失位置。

**验收：** 群组页签与工作模式项目空间页签复用同一组件，没有第二份实现。

### MODE-E2E-16 群组任务详情：任务对话与任务信息并列（D37）

**优先级：** P0（布局、信息栏切换与收起、操作菜单）+ P1（Agent 任务的执行成果、执行步骤与继续修改）
**角色：** 项目空间负责人或成员（非只读）；只读成员

### MODE-API-03 对话对象已读位置（S5e）

**优先级：** P1
**角色：** 员工 A、员工 B（受控测试身份）
**运行层级：** 专用可丢弃 PostgreSQL（服务端集成测试，经 HTTP 路由）
**前置数据：** A 与 B 同在一个活动群组；A 与一个 AI 同事有单聊；另有一个 A 不是成员的群组
**spec：** `server/src/http/conversation-targets-api.integration.test.ts`

1. `GET /me/conversation-targets` 每项含 `unreadCount` 与 `muted`：只计已读位置之后、他人发送的 user 消息与 assistant 回复，本人发送的不计；群组的起点不早于本人加入时间；最多计到 100。
2. `POST /me/conversation-targets/:type/:id/read`（`upTo` 可选，默认当前时间，晚于当前时间按当前时间）：已读位置只前进不后退；之后到达的消息仍为未读。
3. 对 A 不是成员的群组、不存在的 AI 同事标记已读返回 404；`type` 非 `agent | group`、`upTo` 不是时间返回 400；B 的已读位置不影响 A。
4. 静音的群组 `muted` 为 true，未读数照常返回。

**验收：** 已读位置按“账号 + 对话对象”保存，与 `workspace_notification_states` 分开；接口不泄露无权群组是否存在。

**优先级：** P0（@ 候选含同事、发送后提醒显示与打开即已读）+ P1（他人 @ 产生提醒、失权后不显示、同时 @Agent 与同事）

**前置数据：** A 与 B 同在一个含 Agent 成员的活动群组（P0 为 `ws-supply`）；测试身份已有一条未读 @ 提醒（P0 冒烟数据预置）

1. 协作模式群聊输入框输入“@”：候选同时列出 Agent 成员（标“Agent”）与群内同事（标“同事”，不含本人）；输入文字可筛选。
2. 选中同事后发送：消息作为讨论消息出现，不触发执行；提示文案说明“@同事只提醒，@Agent 才执行”。同一条消息同时 @Agent 与同事时，交给该 Agent 执行，并提醒该同事。只有一个 Agent 时，只 @ 同事的消息作为讨论发送，不交给预选的 Agent；没有 @ 任何人时仍交给预选的 Agent。工作模式空间内新对话同样如此。
3. 被 @ 的员工打开协作模式：对话列表中该群组显示“[有人@我]”（静音的群组同样显示），主导航“对话”显示提醒圆点；群聊中 @ 本人的消息标注“@了你”。打开该群组后“[有人@我]”与导航圆点消失，刷新后仍为已读。

### MODE-API-04 @ 提醒登记与读取（D38）

**优先级：** P1
**角色：** 员工 A、员工 B、非成员 C（受控测试身份）
**运行层级：** 专用可丢弃 PostgreSQL（服务端集成测试，经 HTTP 路由）
**前置数据：** A 与 B 同在一个含 Agent 成员的活动群组；C 不是成员
**spec：** `server/src/http/message-mentions-api.integration.test.ts`

1. `POST /sessions/:id/messages` 与 `POST /sessions/:id/runs` 接受 `mentionedUserIds`（字符串数组，最多 50 个）：只为现任成员登记提醒，发送者本人与非成员被忽略；同一幂等键重放不重复登记；格式不对返回 400。
2. `GET /me/mentions` 返回本人未读提醒按空间与讨论的汇总（空间、讨论、条数）；群组时间线与讨论详情的消息带 `mentionedUserIds`；`GET /me/conversation-targets` 的群组带 `mentioned`。
3. `POST /me/mentions/read`（`workspaceId` 必填，`sessionId` 可选）只把本人的提醒标为已读；`POST /me/conversation-targets/group/:id/read` 同时把该群组本人的提醒标为已读（不晚于 `upTo`）。
4. B 被移出后，`GET /me/mentions` 与对话对象均不再返回该群组的提醒；对非成员空间标记已读返回 404。

**验收：** 提醒只按“消息 + 接收人”保存，接收人由服务端校验；读取时重查成员身份，不泄露无权空间。
