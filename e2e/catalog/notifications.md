# 站内通知

设计见 [站内通知方案](../../docs/design/notification-center-plan.md)，原型见方案页首链接。标注“待建”的 spec 文件随对应实施切片创建。

## 通知记录与接口（NC-S1）

### NC-01 与本人相关的四类事件各产生一条通知，读取时按当前权限解析

**优先级：** P1 · **角色：** 项目负责人、两位成员、一位非成员 · **运行层级：** 专用可丢弃 PostgreSQL、受控测试身份、真实 HTTP 接口（不调用模型）<br>
**前置数据：** 一个团队项目空间，负责人与成员甲在内；成员乙、非成员各一<br>
**spec：** `server/src/http/user-notifications-api.integration.test.ts`

1. 负责人把成员乙加入项目：成员乙收到一条“被加入项目”通知；负责人本人不收到。
2. 负责人在共享讨论中 @ 成员甲和非成员：只有成员甲收到“@ 我”通知；幂等重放同一条消息不产生第二条。
3. 负责人创建一个员工任务指派给成员甲：成员甲收到“任务指派给我”；把任务改派给成员乙：成员乙收到一条，成员甲不再新增；自己指派给自己不产生通知。
4. 成员乙把任务标记完成：任务创建人（负责人）收到“我创建的任务完成”；创建人自己完成时不产生通知。
5. 每条通知带触发人、所属项目、对象名称与跳转所需的 ID；名称在读取时解析，改名后读到新名称。
6. 成员乙被移出项目后，此前的通知仍在列表中，但不再返回项目和任务名称，标为“不可见”；任务被删除后，该任务的通知同样不可见。

**验收：** 通知与业务变更同一事务写入、可幂等重放；只有本人能读到自己的通知；失权后旧通知不泄露名称。

### NC-02 未读、已读与静音

**优先级：** P1 · **角色：** 项目成员 · **运行层级：** 专用可丢弃 PostgreSQL、受控测试身份、真实 HTTP 接口<br>
**前置数据：** 成员已有若干条未读通知，含 @ 我与任务类通知<br>
**spec：** `server/src/http/user-notifications-api.integration.test.ts`

1. 未读数等于未读且可见的通知条数；按“未读”筛选只返回未读通知，按时间倒序，可用游标翻页。
2. 标记单条已读后未读数减一；对他人的通知或不存在的通知标记已读返回“不存在”。
3. “全部标为已读”后未读数为 0。
4. 成员把该项目静音：该项目的任务类通知照常列在“全部”中，但不计入未读、不出现在“未读”页签；@ 我仍计入未读。
5. 在群组中打开对话（标记该群已读）后，该群的 @ 我通知同时变为已读；反之在通知中心读 @ 通知（单条或全部）后，群组“[有人@我]”标记同时消失。

**验收：** 未读口径与静音规则和方案 NC4、NC5 一致；已读只改本人记录，不改变业务数据。

### NC-04 定时执行暂停或停止、定时任务没成功、Skill 审核结论（NC-S3）

**优先级：** P1 · **角色：** 项目负责人（定时规则设置人）、定时任务所有者、Skill 提交人、平台管理员 · **运行层级：** 专用可丢弃 PostgreSQL、受控测试身份、真实 HTTP 接口（不调用模型）<br>
**前置数据：** 一个团队项目与其中一个按天执行的 Agent 任务；一个已启用的定时任务；员工经对话提交、待审核的 Skill 两个<br>
**spec：** `server/src/http/user-notifications-api.integration.test.ts`

1. Agent 任务连续多次执行失败、定时执行被自动暂停：规则设置人收到一条通知，写明“已暂停”与原因；Agent 被移出、项目归档或过了截止日期而停止时同样收到，写明“已停止”与原因。任务被他人标记完成而停止时不另发（创建人已有“任务完成”通知）。
2. 定时任务的一次执行失败、被跳过（例如上一次还没结束）或因停机错过：所有者各收到一条，写明是哪种情况；成功不通知；所有者本人“立即运行”被当场拒绝时不通知（页面已提示）；同一结果已有未读通知时合并为一条（更新为最新一次），读过后再发生另起一条；服务重启后丢失的执行记为失败并通知。点通知打开这次执行的对话，没有对话时打开定时任务页。
3. 管理员通过或拒绝员工提交的 Skill：提交人收到一条，写明已发布或未通过；通知不包含拒绝原因（原因在草稿卡片上）。点通知打开提交时的对话。
4. 定时任务被停用、或提交记录不再属于本人时，旧通知不再返回名称与跳转目标。
5. 每类事件重放不重复，只有接收人本人能读到。

**验收：** 写入与业务变更同一事务；通知只含名称级信息与代码值（状态、原因），名称读取时解析。

### NC-05 只保留最近 90 天的通知（NC-S4）

**优先级：** P1 · **角色：** 员工 · **运行层级：** 专用可丢弃 PostgreSQL、受控测试身份<br>
**前置数据：** 两位员工各有超过 90 天与 90 天内的通知若干<br>
**spec：** `server/src/http/user-notifications-api.integration.test.ts`

1. 清扫删除所有员工超过 90 天的通知，90 天内的保留，与已读未读无关；返回删除条数。
2. 再次清扫不再删除任何记录（幂等），多个实例同时清扫也不出错。
3. 清扫前，超过 90 天的通知已不在列表与未读数中（读取侧口径不变）。

**验收：** 清扫只删通知记录，不影响 @ 提醒、项目动态等业务数据；服务启动时与之后每天执行一次。

## 员工端入口（NC-S2）

### NC-03 两种模式在导航栏左下角打开通知面板，点一条直达对应页面

**优先级：** P0 · **角色：** 员工 · **运行层级：** P0 冒烟服务（测试身份、内存通知数据）<br>
**前置数据：** 测试身份有若干条通知：一条未读的“@ 我”（项目“供应链经营分析”）、一条未读的“被加入项目”、一条已读的任务通知、一条已不可见的通知<br>
**spec：** `e2e/personal-workbench.spec.ts`、`e2e/collab-mode.spec.ts`、`apps/workbench-web/src/components/NotificationCenter.test.ts`

1. A 工作模式：侧栏底部头像上方有“通知”按钮，可访问名称带未读条数，角标显示未读数；主导航入口不变（五个，企业知识库启用时为六个）。
2. 点“通知”打开面板，标题“通知”，有“全部”“未读”两个页签与“全部标为已读”；条目按时间倒序，写明谁在哪个项目做了什么，未读条目有标记。
3. 切到“未读”只显示未读条目；点“全部标为已读”后角标消失，“未读”页签显示“暂时没有未读通知”。
4. 点“被加入项目”通知：面板关闭，进入该项目（A 为项目空间页，B 为群组）；已不可见的通知点了不跳转，就地提示“该内容已不可见”。
5. B 协作模式：图标栏底部头像上方有同一个“通知”按钮，主导航仍是四个入口；点“@ 我”或“被加入项目”通知进入对应群组，点任务通知进入群组内的任务详情。在群组中打开对话后，铃铛上该群的 @ 随即变为已读；在通知中心读了 @ 后，对话列表的“[有人@我]”与导航圆点随之更新。
6. 窄屏：B 的通知按钮在顶栏头像旁；A 的通知按钮随侧栏收进菜单，菜单按钮显示未读圆点，全部已读后圆点消失；面板全屏显示，可关闭；点通知跳转后侧栏收起。

**验收：** 入口位置与方案 NC2 一致，不改变主导航；面板是模态对话框（焦点不离开面板），条目的可访问名称含时间与所属项目；未读数、页签与已读和 NC-02 同一口径；P0 不证明真实权限与持久化（见 NC-01、NC-02）。
