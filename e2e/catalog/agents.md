# Agent

Agent 定义与能力、详情与发布、岗位权限、轻量自动任务、经验迭代与主动记忆。证据层级与写法见[验收目录索引](../TEST-CATALOG.md)。

### AG-SOUL-P0 无依赖 Agent 创建页面冒烟

**优先级：** P0 · **角色：** 平台管理员（冒烟测试身份） · **运行层级：** P0 浏览器冒烟<br>
**前置数据：** 隔离冒烟服务，不连接 PostgreSQL；使用唯一 Agent 名称<br>
**spec：** `e2e/admin-agent-soul.spec.ts`

1. 打开 Agent 管理，点击「创建 Agent」；创建窗口只要求名称、说明和 `SOUL.md`，不出现员工可见角色、平台数据范围、Skill 或 MCP 选择。
2. 创建后直接进入该 Agent 的草稿编辑流程第 1 步「职责与人格」（`/agents/:agentId/draft?step=profile`），页头显示“编辑草稿”与“草稿与服务端一致”，左侧步骤为职责与人格、能力、角色与权限、验证与发布；进入「能力」步骤后 Skill 为空、MCP 为默认“不使用 MCP”，不展示逐 Agent 的 DSH 基础工具列表。

**验收：** 页面能在不选择任何工具的情况下创建基础 Agent，Soul 有清晰的名称和边界提示；只证明页面交互，不证明 PostgreSQL、发布或真实 DSH。

### AG-CAP-P0 Agent 定义与 MCP 范围配置（草稿编辑流程自动保存）

**优先级：** P0 · **角色：** 平台管理员（冒烟测试身份） · **运行层级：** P0 浏览器冒烟<br>
**前置数据：** 隔离冒烟服务；一个可用的企业知识 MCP Connector；唯一 Agent 名称<br>
**spec：** `e2e/admin-agent-capabilities.spec.ts`

1. 创建 Agent 后在草稿编辑流程「职责与人格」步骤填写 `AGENTS.md` 工作规程与员工端示例问题；修改后页头显示“保存中”，随后显示“已保存”，不需要点击保存按钮。不合法的内容（如名称过短、`AGENTS.md` 不足 20 字）在字段旁提示且不保存。
2. 在「能力」步骤检查默认“不使用 MCP”，切换为“仅选定”：空集合提示必须选择连接器且不保存；选择连接器后查看只读工具详情及登记的上游权限说明，随后自动保存。
3. 「退出编辑」回到只读详情页，「概览」显示刚保存的工作规程与 MCP 范围（标为未发布草稿）；从列表「继续编辑」重新进入草稿流程，工作规程、示例问题和 MCP 模式按保存结果回显。
4. 切换为“不使用 MCP”后再切回“仅选定”，旧选择已清空，空集合不保存。
5. 运行限制（超时、工具调用上限、输出上限）默认折叠，展开后可修改并自动保存。

**验收：** 草稿只在内容合法时自动保存，保存状态、校验错误与冲突（另一处已修改，提示重新载入）均可见；离开页面前未保存的修改会先保存。不展示逐 Agent 的基础/扩展工具开关或全部工具预览。本层只证明页面交互，不证明数据库、发布或实际调用限制。

### AG-DETAIL-01 Agent 详情（只读查看与运维）与草稿编辑流程分离

**优先级：** P0（页面冒烟）/ P1（隔离 PostgreSQL 旅程） · **角色：** 平台管理员；安全审计员只读 · **运行层级：** P0 冒烟服务 + P1 浏览器测试服务（`scripts/testing/admin-mcp-connector-browser.ts`）<br>
**前置数据：** 一个已发布 Agent（含版本历史）、一个仅有草稿的 Agent；P1 另需可丢弃 PostgreSQL 与受控 Runtime<br>
**spec：** `e2e/admin-agent-soul.spec.ts`、`e2e/admin-agent-capabilities.spec.ts`、`e2e/agent-release-review.spec.ts`（P0）；`e2e/agent-principal.integration.spec.ts`、`e2e/agent-capabilities.integration.spec.ts`、`e2e/agent-routines.integration.spec.ts`（P1）

详情页只用于查看与运维，修改版本内容必须进入独立的草稿编辑流程；两处不混用，也不会在查看时静默生成草稿。

1. 在 Agent 列表点击某行或「查看」进入 `/agents/:agentId` 详情页。页头显示名称、可用性、当前版本与待发布版本，提供启用/停用；管理员另有主操作：无待发布版本时为「编辑配置」，有草稿或已冻结版本时为「继续编辑 vX」。列表行同样提供「编辑配置 / 继续编辑」，点击待发布版本标签直接进入验证与发布步骤。
2. 详情页分区：概览、岗位权限、主动任务、经验、版本历史、运行记录；分区可通过地址（`?section=`）直接打开，刷新后停留在同一分区。旧分区地址 `?section=profile|capabilities` 落到「概览」，`?section=release` 与旧 `/agents/:agentId/release/*` 落到草稿编辑流程的「验证与发布」步骤。
3. 「概览」只读显示当前版本的说明、欢迎语、示例问题、`SOUL.md`、`AGENTS.md`、Skill、MCP 范围与运行限制；从未发布时显示草稿内容并标明“尚未发布”。有待发布版本时提示并提供继续编辑入口。详情页不显示草稿保存状态。
4. 「岗位权限」显示权限总览与可见角色、岗位角色、数据范围，以及“允许加入项目空间”开关与已加入空间；修改立即生效，不需要验证。
5. 「版本历史」列出各版本（发布时间、发布人、当前标记），可回滚到任一曾发布的版本；回滚只移动当前版本指针。
6. 「运行记录」列出以该 Agent 身份运行的最近 Run：来源（对话、主动任务、自动任务、验证）、版本、发起人、状态与起止时间；无记录时显示空状态。
7. 草稿编辑流程 `/agents/:agentId/draft?step=`：左侧步骤依次为「职责与人格」「能力」「角色与权限」「验证与发布」，「角色与权限」只在从未发布的 Agent 上出现（已发布 Agent 在详情页「岗位权限」修改）。页头显示“编辑草稿 vX · 基于 vY”和自动保存状态，提供「退出编辑」（先保存再回详情页）。底部「上一步 / 下一步」与步骤导航切换时先保存草稿，步骤写入地址。「角色与权限」步骤中可见角色与岗位角色为必填、数据范围选填，全部由管理员手动选择，不预填、不自动授予（岗位角色选项标出“含管理权限”，服务端验证前检查与发布复核同样要求岗位角色）。必填未完成时「下一步」停留在本步并标出字段；从其他步骤直接进入「验证与发布」时提示先完成「角色与权限」并跳转到该步骤。步骤不显示权限总览、执行身份开关与单独的「保存岗位权限」按钮，离开该步骤（下一步、上一步、步骤导航、退出）时保存，保存失败则停留在本步；返回上一步或退出不检查必填。详情页「岗位权限」与验证与发布中的岗位权限抽屉仍需显式保存并确认，因为修改立即生效。
8. 「验证与发布」步骤只包含岗位权限摘要、验证前检查、验证案例（含自定义测试问题）、验证结果与确认发布；缺少可见角色时「调整」在当前页打开岗位权限抽屉，保存后摘要与检查刷新，不离开流程。发布成功后回到详情页「版本历史」并提示发布完成。
9. 安全审计员可查看详情页全部分区；草稿流程以只读方式打开（「查看待发布 vX」），输入框只读、没有保存、验证、发布、回滚或启停操作。

**验收：** 查看与编辑分离：详情页不能直接修改版本内容；创建后按步骤完成定义、能力、角色与权限（岗位角色必填）并验证发布；草稿自动保存且不覆盖并发修改；每个分区的加载失败只影响该分区并可重试。P0 只证明页面交互；P1 证明权限与运行记录来自隔离 PostgreSQL。

### AG-DETAIL-02 详情页经验分区（S5）

**优先级：** P0 · **角色：** 平台管理员；安全审计员只读 · **运行层级：** P0 浏览器冒烟（路由夹具提供经验申请）<br>
**前置数据：** 一个 Agent 及其一条待审核、一条已发布的经验申请<br>
**spec：** `e2e/agent-experience.spec.ts`；全局汇总页仍由 `e2e/mvp-smoke.spec.ts` 覆盖

1. 在详情页打开「经验」分区，按“待审核 / 已发布 / 已拒绝 / 全部”查看该 Agent 的经验申请，只显示该 Agent 的申请；每条显示标题、来源版本、来源 Run 与申请时间。
2. 查看申请详情：来源 Run/Attempt、内容摘要与完整经验内容。
3. 填写审核说明（选填）后批准并发布，或拒绝；拒绝必须填写原因。处理后待审核数减少，已发布列表出现该经验。
4. 全局“经验迭代”页保留为所有 Agent 的汇总视图，每行可跳到对应 Agent 详情页的经验分区。
5. 安全审计员可查看但没有批准或拒绝操作。

**验收：** 按 Agent 审核经验无需离开详情页；批准只创建不可变经验版本，不修改 Soul、Skill、Tool 或权限；拒绝原因随申请保存。本层只证明页面交互，不证明真实 DSH 经验提出与检索。

### AG-CAP-P1 Agent 能力装配与发布执行

**优先级：** P1 · **角色：** 平台管理员、可运行 Agent 的员工 · **运行层级：** P1 集成用户旅程<br>
**前置数据：** 专用可丢弃 PostgreSQL、受控 Runtime/Worker、两个同租户合成 MCP Connector；已准入的文件工具、可发布 Agent 及运行身份<br>
**spec：** `e2e/agent-capabilities.integration.spec.ts` 覆盖管理端创建、持久化、版本历史、运行快照与选定连接器失效；验证 Attempt 的实际 Manifest、跨租户校验及策略边界由对应服务端集成测试覆盖

1. 通过界面配置分别创建有、无 `AGENTS.md` 的 Agent；工作规程只来自配置，不读取宿主目录或输入附件中的同名文件。
2. 无需手选 DSH 文件工具即可试运行；配置创建选择依赖文件工具的 Skill 时，平台自动解析并固定依赖，移除该 Skill 后隐式工具不残留，原先直接声明的工具保留；检查实际 Attempt 的精确工具与绑定快照、成果和授权范围。未授权文件和未批准集合不能因默认装配而被访问。
3. 修改 Soul、`AGENTS.md`、默认工具依据或 MCP 模式后会生成新草稿版本，旧验证结果不能发布新内容；历史 Attempt 仍保留原依据。
4. 验证 `selected` 只获得所选连接器、`none` 不获得 MCP，新登记的连接器不会进入任何 Agent；提交 `all`、空选择或跨租户 ID 拒绝，已选连接器失效时拒绝验证和新执行，不回退、不跳过。
5. 在受控 Runtime 中尝试调用未选 MCP，以及停用或改变已固定连接器后继续调用；调用被阻止且留有可回查的失败与审计依据。
6. 编辑草稿并重新打开，确认未展示的身份授权、数据需求和预算未被清空；对话、验证运行与主动任务沿同一能力装配规则运行。

**验收：** 界面配置形成统一发布契约；默认工具由平台准入和当前授权约束，MCP 范围在 Manifest 与实际调用处一致，三个运行入口均沿既有 Run/Attempt 链路。P1 不替代真实 DSH/OIDC 与获准 MCP 的 P2 验收。

### AG-CAP-P2 真实 DSH 能力装配验收

**优先级：** P2 · **角色：** 平台管理员、OIDC 员工及独立 Agent 身份 · **运行层级：** 真实 DSH/模型与 OIDC；本轮获准的 MCP 验收范围仅为本地可丢弃服务<br>
**前置数据：** 目标版本的真实 DSH、两个独立 OIDC 账号、两个本地可回查且可清理的 MCP 测试目标及单独的验收数据库<br>
**入口：** `pnpm probe:pf07:mcp:platform` 核对真实 DSH/本地 MCP 执行；管理端与员工端完整旅程须另留浏览器和 Run/Attempt 证据

### AE-MEMORY-01 提案、人工确认和只读投影

**优先级：** P0/P1 · **角色：** Agent 执行身份、发起员工、平台管理员 · **运行层级：** 原型浏览器冒烟、一次性 PostgreSQL、受控 ACP Runtime 和前端组件<br>
**前置数据：** 已发布且显式引用 `propose_memory@1.0.0` 的 Agent；本人可访问的成功 Attempt 与隔离管理员<br>
**spec：** `e2e/mvp-smoke.spec.ts`、`server/src/infrastructure/postgres/pf05-controlled-memory.integration.test.ts`、`server/src/modules/runtime/runtime-adapter.test.ts`、`apps/workbench-web/src/views/ConversationView.test.ts`

1. Agent 在真实 Run 的 DSH 工具桥提出偏好或经验；平台只保存与来源 Run/Attempt、Agent Version/Principal、发起人和空间绑定的 7 天提案。同一内容重放不复制；未声明工具、失效 Attempt 和停用身份不能提案。发布试运行仅返回 `trial_only`，不生成真实提案。
2. 员工仅在本人成功 Attempt 查看未过期提案；可以改为自行填写，或核对 Agent 提案全文并自行选择使用范围与期限。他人、未成功 Attempt 和已提交提案不显示正文；篡改提案正文或重复提交返回冲突。
3. 管理员审核之前任何提案和已同意候选都不能进入后续 Agent 上下文；审核后同一 Agent 的新定义版本可按当前 ACL 使用，其他 Agent、其他用户及团队空间不能继承私人内容。撤回和到期立即阻止新使用，未同意到期提案由清理任务删除。
4. 新 Attempt 仅将本次固定且获准的少量记忆写入 `workspace/memory.md`，文件权限为只读；Manifest/Prompt 标记其为非权威参考。领取、运行和等待恢复时继续复核当前来源、范围、身份、摘要与撤回状态。

**验收：** 提案、同意、审核及执行引用是四个独立状态；`propose_memory` 的成功回执仅表示暂存，不表示已批准或业务目标完成。P0 浏览器冒烟证明员工必须明确选择范围和期限；P1 自动化证明平台边界；真实 DSH、OIDC 与跨账号收权仍按 PF-MEMORY-P2 单独留证。
# AE-05 · Agent 主动任务（P1 集成旅程）

- **优先级／角色／层级：** P1；平台管理员和结果接收员工；一次性 PostgreSQL、受控 Runtime、独立浏览器会话。
- **前置数据：** 已发布 Agent Version、已启用的 Agent Principal、授权团队空间及明确的接收员工；专用可丢弃数据。
- **操作：** 管理员在 Agent 详情从当前岗位权限中确认角色与数据范围上限并启用规则，手动触发、查看执行记录，再暂停；服务集成测试创建手动、定时和事件规则并重复触发相同事件，检查错过槽位及接收人读权限。
- **可观察结果：** 浏览器中批准、触发和暂停状态与执行记录一致；服务集成中仅一次受理，重叠和遗漏有原因，Task 发起与执行身份均为 Agent Principal，Run 无员工 Session；停用或收权阻断后续动作，仅指定接收人且有当前 Workspace 授权者能看到结果。
- **Spec：** `e2e/agent-routines.integration.spec.ts`（独立 P1 管理端配置）；`server/src/infrastructure/postgres/agent-routines.integration.test.ts`（服务、身份、接收结果）。员工浏览器和真实 DSH/OIDC 另列 P2 验收。
