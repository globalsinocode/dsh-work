# 钉钉接入

设计见[钉钉接入方案](../../docs/design/dingtalk-integration-plan.md)，确认的原型见方案第 7 节说明（四屏：员工与权限、钉钉集成、钉钉内首次登录即绑定、个人设置 › 钉钉）。本分册覆盖 DT-S1（账号绑定、钉钉内免登、管理员代绑、钉钉集成页、容器内协作模式）；DT-S2（工作通知投递、群组提醒）的旅程随该切片登记。

**层级说明：** 所有 P0/P1 旅程中的钉钉开放平台都是测试替身——服务端身份测试用进程内替身（`server/src/testing/dingtalk-double.ts`），浏览器 P1 用夹具启动的假钉钉 HTTP 服务，配合生产实现 `DingTalkOpenApiDirectory`（`DSH_WORK_DINGTALK_API_BASE_URL` 指向它）。钉钉容器用页面注入的 `window.dd` 替身模拟 `requestAuthCode`。它们不能证明真实钉钉企业内部应用、真实授权码与错误码、iOS/Android 钉钉容器的行为，这些只在 `DT-P2` 验收。

## 身份与会话（DT-S1 后端）

### DT-ID-01 钉钉内首次登录即绑定、免登与会话来源

**优先级：** P1 · **角色：** 已开通账号的员工、平台管理员 · **运行层级：** 专用可丢弃 PostgreSQL、钉钉开放平台测试替身、真实 HTTP 认证接口<br>
**前置数据：** 已改初始密码并有员工端权限的员工；钉钉替身中对应成员（姓名、部门）<br>
**spec：** `server/src/modules/identity/dingtalk-auth.integration.test.ts`

1. 在钉钉入口用授权码免登：没有绑定时返回待绑定凭证与钉钉姓名、部门，不设置 Cookie。
2. 用账号密码与凭证登录：同一事务内绑定（本人绑定）并签发 12 小时的钉钉会话；之后免登直接进入，并撤销此前的钉钉会话。
3. 凭证重复使用、过期、来源不符或伪造：拒绝且不签发会话、不绑定；授权码重放、非本企业授权码、未登记入口、跨站请求均被拒；`return_to` 只接受同源路径。
4. 钉钉账号已绑定他人、本账号已有其他绑定、管理员锁定了自行绑定：本次只签发普通密码会话并说明原因，不替换已有绑定；并发绑定同一钉钉账号只有一个成功。
5. 需先改初始密码：先改密，改密请求带回凭证后才绑定。
6. 手机钉钉会话与桌面密码会话并存；退出登录撤销全部来源；钉钉会话不能改密；绑定失效、管理员重置密码、停用账号后钉钉会话立即失效；员工自己改密时绑定保留、钉钉内下次自动免登。
7. 钉钉不可用时明确返回不可用，不降级。

**验收：** 只有同时证明平台身份（密码）与钉钉身份（授权码）才绑定；会话按 `binding_id` 校验与撤销。

## 管理端（DT-S1 管理员代绑与钉钉集成）

### DT-ADM-01 管理员代绑、改绑、解绑与锁定（服务端）

**优先级：** P1 · **角色：** 平台管理员、第二位平台管理员、员工、拥有管理权限的账号 · **运行层级：** 专用可丢弃 PostgreSQL、钉钉开放平台测试替身<br>
**前置数据：** 若干员工；钉钉替身中有对应手机号的成员与部门<br>
**spec：** `server/src/modules/identity/dingtalk-admin.integration.test.ts`

1. 输入员工手机号预览：显示钉钉姓名与部门（最多 2 个）、脱敏号码与确认凭证；确认只接受该凭证，凭证固定目标员工与发起管理员、单次有效。
2. 钉钉姓名与员工姓名不一致、或部门读取失败：须勾选“我已核实是本人”才能确认。
3. 不能为拥有管理权限（admin:*、admin:write、admin:read、audit:read）的账号代绑；非平台管理员不能代绑；单个管理员每日代绑次数有上限。
4. 钉钉账号已绑定其他员工：确认改绑后原绑定失效、原员工的钉钉会话撤销并收到站内通知。
5. 绑定后员工收到站内通知“管理员已为你绑定钉钉账号（姓名）”；审计只记手机号后 4 位与哈希，平台不保存手机号字段。
6. 解绑撤销钉钉会话并通知员工；勾选“锁定自行绑定”后员工无法在钉钉内重新绑定，解除锁定或重新代绑后恢复。
7. 未找到手机号、手机号无效、应用缺少权限分别给出明确提示。

### DT-ADM-02 钉钉集成：连接检查、绑定情况、未绑定名单与提醒、离职检查（服务端）

**优先级：** P1 · **角色：** 平台管理员 · **运行层级：** 专用可丢弃 PostgreSQL、钉钉开放平台测试替身<br>
**spec：** `server/src/modules/identity/dingtalk-admin.integration.test.ts`

1. 员工与权限列表返回每位独立账号员工的钉钉状态（已绑定 / 未绑定 / 已失效及原因），可按状态筛选，并给出已绑定（本人 / 代绑）与未绑定人数。
2. 连接检查报告凭据与各项接口权限；凭据或权限问题显示为“配置异常”。
3. 未绑定名单含已失效员工及原因；“提醒员工”给未绑定且未锁定的员工登记站内通知，同一员工每天一条。
4. 每日离职检查只把钉钉明确返回“用户不存在”的判为离职并使绑定失效；超时、限流等记为检查失败、不改变绑定；判为离职的超过有效绑定 10% 时整批暂停，管理员确认后才执行；权限错误记为配置异常；连续 3 次失败超过 5% 时显示常驻“离职检查异常”。

### DT-ADM-03 管理员在浏览器中代绑、解绑并查看钉钉集成页

**优先级：** P1 · **角色：** 平台管理员 · **运行层级：** 真实应用（`server/src/main.ts`）、专用可丢弃 PostgreSQL、夹具启动的假钉钉 HTTP 服务（生产实现经 `DSH_WORK_DINGTALK_API_BASE_URL` 访问）、Playwright Chromium<br>
**前置数据：** 平台管理员；员工“赵宁”（钉钉成员同名）、“王一凡”（钉钉姓名不同）；已绑定员工“林岚”<br>
**spec：** `e2e/dingtalk.integration.spec.ts`

1. 打开“员工与权限”：列表有“钉钉”列与筛选，顶部显示已绑定 / 未绑定人数；按“未绑定”筛选只剩未绑定员工。
2. 配置“赵宁” › 钉钉 › 代为绑定钉钉：输入手机号查找，看到“将绑定以下钉钉成员”和钉钉姓名、部门；确认后显示“已绑定”“管理员…代绑”。
3. 配置“王一凡”：查找后提示姓名不一致，未勾选“我已核实是本人”前不能确认。
4. 输入不存在的号码：提示“企业钉钉中没有找到这个手机号”。
5. 解除“赵宁”的绑定并勾选锁定：状态变为“已失效”“已锁定自行绑定”。
6. 打开“钉钉集成”：看到应用配置与“重新检查连接”后各项接口权限“已开通”、绑定人数；“未绑定”页签列出未绑定员工，“提醒员工”后显示已提醒；“通知投递”页签说明在 DT-S2 启用。

**验收：** 原型①②的状态与文案在真实应用中可用；钉钉调用经生产实现发出。

### DT-ADM-04 在钉钉集成页配置钉钉应用（DT30）

**优先级：** P1 · **角色：** 平台管理员 · **运行层级：** 服务端：专用可丢弃 PostgreSQL、凭据主密钥（测试值）、钉钉开放平台测试替身；浏览器：同 DT-ADM-03<br>
**前置数据：** 部署配置提供初始钉钉应用配置（浏览器夹具）或无配置（服务端用例）<br>
**spec：** `server/src/modules/identity/dingtalk-settings.integration.test.ts`、`e2e/dingtalk.integration.spec.ts`

1. 页面从未保存过时，“应用配置”显示部署配置提供的 CorpId、AgentId、AppKey 与“部署配置（尚未在页面保存过）”。
2. 编辑配置：AppSecret 留空沿用已保存的值；修改每日代绑上限等参数，“验证并保存”后立即生效（无需重启），来源变为“管理端 · 姓名”。
3. 填写错误的 AppSecret：钉钉拒绝，提示“钉钉拒绝了这组凭据”，原配置不变、连接检查仍通过。
4. 首次配置或更换 CorpId / AppKey 时必须填写 AppSecret；参数越界被拒。
5. AppSecret 加密保存：配置表、接口返回与审计都不含明文；服务没有凭据主密钥时不能在页面保存；主密钥更换后显示“无法读取”并停用钉钉功能。
6. 更换 CorpId（页面保存或部署配置的初始配置变化）：所有绑定失效（原因“钉钉应用换到了其他企业”）、钉钉会话撤销、未使用的凭证删除；同一企业只改参数不影响绑定。页面保存前要求确认。
7. 部署配置超出范围的参数在启动时收进范围；依赖部署配置 AppSecret 的配置在页面保存后加密入库，删除部署配置后仍可用，删除前未保存过则提示“部署配置中已没有它”；验证期间配置被他人清除时不保存。
8. 清除配置：删除加密的 AppSecret，免登与连接检查立即显示未配置；重启后部署配置不会自动恢复；重新填写即可恢复。
9. 非平台管理员不能查看或修改。

## 员工端（DT-S1 钉钉内登录与个人设置）

### DT-EMP-01 钉钉内首次登录即绑定与各拒绝情形

**优先级：** P1 · **角色：** 员工 · **运行层级：** 真实应用、专用可丢弃 PostgreSQL、假钉钉 HTTP 服务、页面注入的钉钉容器替身（`window.dd` 与钉钉 User-Agent）、Playwright Chromium（手机视口）<br>
**spec：** `e2e/dingtalk.integration.spec.ts`

1. 在钉钉容器中打开员工端：自动免登失败（未绑定）时显示账号密码登录页，并提示“当前钉钉账号：姓名（部门）”与“登录后将绑定此钉钉账号”。
2. 登录并绑定后进入协作模式（B）首页，显示“已绑定钉钉账号”；再次打开时无需登录直接进入。
3. 账号需先修改初始密码：进入改密页，提示“修改后才会绑定钉钉账号”，“修改并绑定”后进入首页并已绑定。
4. 钉钉账号已绑定他人、本账号已绑定其他钉钉、管理员已锁定：显示对应说明与“不绑定，继续使用”，继续后进入首页并提示本次未绑定。
5. 默认 A 工作模式的员工在钉钉内进入协作模式（B）的五个主导航入口，回到桌面浏览器仍是 A，偏好不变。

### DT-EMP-02 个人设置 › 钉钉：查看与解除绑定

**优先级：** P1 · **角色：** 员工 · **运行层级：** 同 DT-EMP-01<br>
**spec：** `e2e/dingtalk.integration.spec.ts`

1. 已绑定（本人绑定）：显示钉钉账号、绑定方式与时间；管理员代绑时显示“如果不是你本人的钉钉账号，请立即解除绑定并联系管理员”。
2. 解除绑定：确认对话框说明影响；解除后显示“未绑定”与如何绑定的三步说明；钉钉内的登录立即失效。
3. 被管理员锁定：显示“已失效”与“管理员已暂停你的钉钉自行绑定”。

### DT-EMP-P0 员工端钉钉页面冒烟

**优先级：** P0 · **角色：** 测试身份员工 · **运行层级：** P0 冒烟服务（内存数据）<br>
**spec：** `e2e/personal-workbench.spec.ts`（个人设置 › 钉钉）

1. 个人设置中有“钉钉”分区，未配置钉钉时显示未绑定与如何绑定。

## 真实验收

### DT-P2 真实钉钉企业内部应用

**优先级：** P2 · **运行层级：** 真实钉钉企业内部应用、公网入口与受信证书、iOS 与 Android 钉钉客户端、真实 DSH

1. 钉钉内登录即绑定与管理员代绑（真实手机号查询、姓名与部门）。
2. 离职员工 `user/get` 实际返回的错误码（确认后回写方案 8.1）。
3. 在 iOS 与 Android 钉钉内从工作台打开 → 免登 → 协作模式群组 → 查看并回复（含 @Agent 经真实 DSH 执行）；返回键、软键盘、文件上传下载与安全区表现。
4. 配置 AI Hub 时公网 origin 的启动行为与部署手册一致。

**验收：** 按发布流程留证；P0/P1 绿灯与测试替身不能代替本条。
