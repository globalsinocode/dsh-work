# HTML 页面

适用于用户要求“做成网页 / HTML / 页面 / 可视化报告 / 演示页”等需要交付一个可打开页面的场景。只要求文字回答或 Markdown 时不必使用。

## 先确认内容

1. 读取用户提供的方案、数据或文件（读取方法见文件分析内置 Skill），列出页面要呈现的部分，按“结论 → 要点 → 细节”组织信息层级。
2. 数值和图表数据先算准再写进页面；不要编造示例数据充当真实数据，确需示意时在页面上标明“示意”。

## 页面要求

- **单个文件。** 只生成一个 `.html` 文件，CSS 写在 `<style>`、脚本写在 `<script>` 中；不引用任何外部地址（CDN、网络字体、远程图片、统计脚本）。执行环境断网，成果预览也在隔离沙箱中，外链资源一律不可用。
- **图表与图片。** 简单图表用内联 SVG 或纯 CSS 绘制；需要嵌入图片时用 data URI，并控制体积。
- **结构清晰。** 设置 `<!doctype html>`、`<meta charset="utf-8">`、`<meta name="viewport" content="width=device-width, initial-scale=1">` 和有意义的 `<title>`；使用 `header`、`main`、`section`、`table` 等语义标签，表格带表头。
- **样式克制。** 使用系统字体栈（含中文字体，如 `-apple-system, "PingFang SC", "Microsoft YaHei", sans-serif`），正文字号不小于 14px，颜色对比清晰；适配手机宽度，不出现横向滚动；加 `@media print` 让打印版去掉多余装饰。
- **脚本最少。** 能用静态内容表达就不写脚本；需要交互（如切换表格、展开详情）时只用原生 JavaScript，页面在脚本失效时内容仍完整可读。

## 生成方式

- `write` 工具不能写 `.html`。在可以运行命令时，用 `bash` 把完整内容写入 `output/<有意义的文件名>.html`（例如用 `cat > output/报告.html <<'EOF' … EOF`，或用 `python3` 写文件）。
- 内容较长时可分段写入同一文件，但最终只保留一个 HTML 成果，不要在 `output/` 留下草稿或中间文件。
- 不能运行命令时，改为输出结构相同的 Markdown，并说明当前无法生成 HTML 文件。

## 完成前自检

- 用 `bash` 确认文件存在且大小合理（成果单个不超过 20 MB）。
- 用 `grep` 检查文件中没有 `http://`、`https://` 或 `//` 开头的外部资源引用（页面内正文提到的网址除外）。
- 确认标题、各部分和关键数字与来源一致，没有占位文字（如 TODO、lorem ipsum）。
- 回答中简要说明页面包含哪些部分；不要把整段 HTML 源码贴进回答。
